# Pymarkdown Configuration

This repository uses `.pymarkdown` (JSON format) to configure markdown linting rules.

## Current Configuration

### Front Matter Extension

- **Status**: Enabled
- **Reason**: Allows YAML front matter blocks at the beginning of markdown files
- **Default**: Disabled

### MD003 (Heading Style)

- **Status**: Enabled with ATX style (`#` headings)
- **Reason**: Enforces consistent use of ATX-style headings throughout documents
- **Default**: Consistent

### MD013 (Line Length)

- **Status**: Enabled with limit of 210 characters
- **Reason**: Accommodates tables with long badge URLs while still catching overly long prose
- **Default**: 80 characters

### MD036 (Emphasis as Heading)

- **Status**: Disabled
- **Reason**: Causes false positives with bold text in numbered lists (e.g., `1. **Step title**`)
- **Default**: Enabled

### MD041 (First Line Heading)

- **Status**: Enabled with front matter title support
- **Reason**: Allows documents to use YAML front matter with a `title` field instead of requiring a heading on the first line
- **Default**: Enabled without front matter support

### MD029 (Ordered List Prefix), MD031 (Blanks Around Fences), MD046 (Code Block Style)

- **Status**: Disabled
- **Reason**: **Their fixers are unsafe, and the hook runs `fix`**
  ([#1574](https://github.com/vig-os/devkit/issues/1574))
- **Default**: Enabled

The `pymarkdown` hook runs `pymarkdown -c .pymarkdown fix`, so a rule here is
not an opinion about style — it is permission to rewrite the document. These
three rewrite *meaning*, on the ordinary idiom of a fenced code block indented
inside an ordered list item:

| Rule | What its fixer does |
|---|---|
| **MD031** | With two consecutive list items each carrying an indented fence, the second is dumped to column 0 while its body and closing fence stay at the old indent, and the item's continuation paragraph is pulled out of the list. **Exits "success"**, so it survives an inattentive re-commit. |
| **MD029** | Renumbers ordered lists. Deliberate continuation numbering (steps `9.`, `10.` resuming after a heading, referenced in prose as "step 9") becomes per-list `1..n` — a semantic change to a runbook. Colliding with MD031 it also aborts the whole run with `BadPluginFixError`. |
| **MD046** | Converts fenced blocks to indented ones by **deleting the fence markers**, dropping language tags and breaking indentation inside lists. |

`pyml` pragmas (`<!-- pyml disable-next-line ol-prefix -->`) suppress a `scan`
finding but **not** a `fix`, so there is no per-site opt-out — disabling is the
only lever. All three reproduce on the pinned 0.9.23 *and* on upstream 0.9.39
(filed as jackdewinter/pymarkdown#1672, #1673 and #1674), so a version bump is
not the fix; `tests/test_pymarkdown_fix_safety.py` in the devkit re-runs the
reproducers against whatever version is pinned.

**If you run `scan` rather than `fix`**, these rules are safe and worth having —
re-enable them in your own copy of this file's config.

### A related hazard that stays enabled: MD004 (Unordered List Style)

A wrapped prose line whose first characters are a plus sign and a space parses
as a list item, and
MD004's "consistent" style then rewrites *real* list markers to match it —
silently turning a textual plus into a minus (or the reverse). MD004 is left
enabled because the value of consistent markers is real and the trigger is
narrow, but check plus-initial prose lines before accepting a marker-only diff.

## Per-Line Exceptions

Unfortunately, pymarkdown does not currently support inline HTML comments like `<!-- markdownlint-disable -->`.

If you need per-line exceptions, you have three options:

1. **Adjust the global rule** in `.pymarkdown` (current approach) — note
   that `pyml` pragmas gate `scan` only, never `fix` (see MD029/MD031/MD046
   above)
2. **Use command-line args** in `.pre-commit-config.yaml` to disable rules entirely
3. **Split content** across multiple files with different rules

## Configuration Format

The `.pymarkdown` file uses JSON:

```json
{
  "plugins": {
    "rule-id": {
      "enabled": true/false,
      "parameter": value
    }
  }
}
```

See [pymarkdown documentation](https://github.com/jackdewinter/pymarkdown) for available rules and parameters.
