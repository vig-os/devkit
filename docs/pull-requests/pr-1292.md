# [PR 1292](https://github.com/vig-os/devkit/pull/1292) feat(workspace): scaffold-time Refs policy knob (DEVKIT_REFS_POLICY)

## Summary

New `.vig-os` manifest key `DEVKIT_REFS_POLICY` steering the `Refs: #N` enforcement policy from ONE key into BOTH enforcement points — the `validate-commit-msg` hook args in the scaffolded `.pre-commit-config.yaml` and CI's `validate-commit-range` (which until now silently ran the tool default, the #1074 desync class):

- `chore-optional` (default / empty key) — today's behavior, byte-identical scaffold
- `optional` — Refs never required (type/format validation kept)
- `required` — every type needs `Refs:`, `chore` included

Solo/private consumers get Refs-optional without editing the preserved `.pre-commit-config.yaml` (no permanent upgrade-diff nag, no hook/CI desync).

## Design notes

- **`required` maps to a `none` sentinel, not `""`**: both CLIs guard with `if args.refs_optional_types:` — an empty string is falsy and silently reverts to the `{chore}` default (the existing empty-set unit test bypasses the CLI). `none` is not a real commit type, so every real type requires Refs; no vig-utils change needed.
- Scaffold surface: `render_refs_policy` in `init-workspace.sh` (anchored sed, no-op for the default, composes with the trunk render on the same file); manifest READ/validate/write-back per the #1116 round-trip idiom. In direnv/flake-hooks mode (no scaffolded pre-commit YAML) the render no-ops — hooks are flake domain; CI still enforces.
- CI surface: `resolve-toolchain` parses the key and emits a `refs-optional-types` output (tolerant: unexpected/absent → `chore`); `ci.yml` commit-checks routes it via `env:` (zizmor/#1279 pattern) into `--refs-optional-types`. The two policy→types mappings are cross-referenced in comments at both renderers.
- `docs/MIGRATION.md`: manifest-table row + the manifest-vs-flake doctrine bullet.
