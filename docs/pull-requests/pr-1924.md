# [PR 1924](https://github.com/vig-os/devkit/pull/1924) fix: harden GitHub App provisioning callbacks and inputs

## Description

A browser reload or concurrent callback could repeat the single-use manifest exchange and replace a successful result with an error. Claim the callback before processing so subsequent requests return a fixed HTTP 200 page without changing state.

## Changes Made

- Guard callback replay and overlapping requests with a lock and a claimed flag.
- Require an HTTP(S) scheme and host for `--base-url`; make it mutually exclusive with explicit `--host`.
- Pin sanitized exchange timeout and malformed JSON errors, checking terminal and callback output for secret values.
- Check the chosen secret prefix in the skill before provisioning; document callback and CLI behavior and remove the resolved known limits.

## Changelog Entry

### Fixed

- **Harden GitHub App provisioning callbacks and inputs** ([#1919](https://github.com/vig-os/devkit/issues/1919))
  - Accept callbacks only once, including concurrent requests, and preserve the original result on replay
  - Validate reverse-proxy URLs and reject combining `--host` with `--base-url`; cover exchange timeout and malformed JSON errors without exposing secrets
  - Check the chosen secret prefix before the provisioning skill creates another App
