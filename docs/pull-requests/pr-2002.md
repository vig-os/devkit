# [PR 2002](https://github.com/vig-os/devkit/pull/2002) fix(release): handle plan-limited rulesets during promotion

## Description

Fix release promotion on private repositories whose GitHub plan returns the plan-limit HTTP 403 (`Upgrade to GitHub Pro`) for branch rulesets. Both scaffold approval gates stop retrying that response and require one approving review by default.

## Type of Change

- [x] `fix` -- Bug fix
- [x] `test` -- Adding or updating tests

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- Share the rules query between validate and merge; Only HTTP 403 with `Upgrade to GitHub Pro` ends retries immediately; rate-limit, permission, SAML, and other errors retain retries and fail on exhaustion. Host retry diagnostics go to stderr, preserving API stdout after a transient error.
- Add `DEVKIT_RELEASE_REQUIRED_APPROVALS`, a validated non-negative integer preserved through scaffold upgrades and resolved into both gates. Empty defaults to 1; solo consumers can set 0. The knob applies only to the 403 fallback; real ruleset counts retain precedence and classic protection remains enforced at merge time.
- Count distinct reviewers using their latest APPROVED, CHANGES_REQUESTED, or DISMISSED review, ignoring COMMENTED and PENDING and requiring APPROVED on the current PR head and excluding the PR author. This shared counter handles both the plan-limit path and the 200-path fallback when `reviewDecision == null`.
- Keep the 200-path fallback comparison changed from `-eq 0` to `-lt "$REQUIRED_APPROVALS"`: a successful rules lookup can require more than one approval, so accepting just one when GitHub has no review decision would under-enforce the returned ruleset.
- Document the fallback and knob. Leave the root workflow unchanged because its gate does not call the rules endpoint.

## Changelog Entry

### Fixed

- **Promote releases on plan-limited private repositories** ([#1851](https://github.com/vig-os/devkit/issues/1851))
  - Stop retrying only rulesets plan-limit HTTP 403 responses and require one approval by default in both promote gates.
  - Count distinct current-head approvals from each reviewer's latest APPROVED, CHANGES_REQUESTED, or DISMISSED review, ignoring COMMENTED and PENDING and excluding the PR author; keep host retry diagnostics out of API responses.
  - Add `DEVKIT_RELEASE_REQUIRED_APPROVALS` for the 403 fallback; solo consumers can set 0, while real ruleset requirements retain precedence.
