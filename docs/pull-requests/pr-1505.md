# [PR 1505](https://github.com/vig-os/devkit/pull/1505) fix(smoke): reclaim deploy PRs by branch so a partial create stays recoverable

## Description

On the 1.9.0 rc1 train the smoke listener's `deploy` job failed on a transient GraphQL 500 whose wording was **`pull request update failed`** — *update*, not *create*. `gh pr create --label` creates the PR and then labels it in a **second** mutation: the create had succeeded ([devkit-smoke-test#367](https://github.com/vig-os/devkit-smoke-test/pull/367) existed), the labelling is what 500'd, and the step exited 1.

Two consequences: `pr_url` never reached `GITHUB_OUTPUT`, so every downstream job skipped; and an **unlabelled** deploy PR was left open. `Close stale deploy PRs` selected candidates with `--label deploy` only, so that orphan was invisible to it — the documented recovery (re-run the failed jobs) re-entered the create and failed with *"a pull request already exists"* until a human added the label by hand.

The structural point: the one step whose partial success is most likely was the one the cleanup could not reclaim.

## Changes Made

All in `assets/smoke-test/.github/workflows/repository-dispatch.yml` (the SSoT for the listener):

1. **Reclaim by head branch, not just by label.** `Close stale deploy PRs` now selects every open PR on `chore/deploy-*` as well as any carrying the `deploy` label (one `gh pr list --json number,headRefName,labels --limit 100` call). The branch name is deterministic and is pushed *before* the PR exists, so unlike the label it cannot be lost to a partial failure.
2. **Adopt, then record, then label.** `Create or adopt deploy PR` first looks for an open PR on `${BRANCH_NAME}` and adopts it instead of dying on *"already exists"*, and writes `pr_url` to `GITHUB_OUTPUT` immediately — before anything else can fail.
3. **Labelling is its own step.** `Label deploy PR` retries `gh pr edit --add-label deploy` three times with backoff and is non-fatal: now that the cleanup reclaims by branch, an unlabelled PR is still recoverable, so a label transient must not strand `pr_url`.
4. **`notify-failure` retries.** The same transient class killed its `gh issue create` 20 s later, so no upstream incident issue was filed at all and #1499 had to be written by hand. It now retries three times and fails loudly if the issue never lands.

## Testing

- [x] Tests pass locally
- [x] Manual testing performed (describe below)

New suite `tests/test_smoke_deploy_pr_reclaim.py` (12 tests), following the harness pattern established by #1477's `tests/test_smoke_dispatch_wait.py`:

- **Shape** — parses the listener YAML: the cleanup selects on `headRefName` *and* the label; the create step no longer passes `--label`; `pr_url` is recorded before a separate label step that consumes it; the label step contains no `exit 1`; notify retries.
- **Behaviour** — executes each step's **real bash** against a stubbed `gh` (and a no-op `sleep`), replaying the rc1 timeline. `--jq` filters run through the real `jq`, so the selector under test is the one that runs:
  - an unlabelled PR on `chore/deploy-1-9-0-rc1` is closed, a labelled legacy deploy PR is still closed, an unrelated `feature/*` PR is never touched
  - with labelling 500'ing on every attempt, `pr_url` still reaches `GITHUB_OUTPUT` and the job stays green
  - with an open PR already on the deploy branch, `gh pr create` is never called and the adopted url is recorded
  - two labelling 500s then success → three `gh pr edit` calls, exit 0
  - two notify 500s then success → three `gh issue create` calls; exhausted retries fail the step

## Additional Notes

**This PR does not make the fix live.** `repository_dispatch` always runs the listener from the smoke-test repo's **default branch**, so the asset here reaches `devkit-smoke-test` `main` only through that repo's own release cycle (`docs/CROSS_REPO_RELEASE_GATE.md` §Contract dependencies). A mirror hotfix on `devkit-smoke-test` `main` follows this merge, so the next train is covered and the next scaffold deploy converges rather than reverts — same dance as [devkit-smoke-test#345](https://github.com/vig-os/devkit-smoke-test/pull/345) / [#353](https://github.com/vig-os/devkit-smoke-test/pull/353).

`docs/CROSS_REPO_RELEASE_GATE.md` gains the reclaim invariant plus a Failure Signals entry for `pull request update failed`, including what to do on a listener version that predates this fix (add the label by hand *before* re-running).
