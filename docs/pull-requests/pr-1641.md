# [PR 1641](https://github.com/vig-os/devkit/pull/1641) fix(workspace): render knobs unconditionally and refuse symlinks

## Description

`.pre-commit-config.yaml` is preserved across upgrades (#878 — the consumer owns
its hook excludes), so it accumulates past renders. The three knob renders
early-returned on an empty manifest key, which means *"don't touch it"*, not
*"restore the default"*. A consumer who set a knob and later **cleared** it kept
the previous render locally, while CI — which re-derives from `.vig-os` on every
run with no memory — resolved the default. The local hook and
`validate-commit-range` then disagreed about the same gate.

The scaffold-drift gate (#1295) could not catch it: it re-runs the scaffold and
`git diff`s, so it hits the same early return, reproduces the stale file
byte-identically, and sees no drift.

## Changes Made

All in `assets/init-workspace.sh`.

**1. The three renders are unconditional and idempotent.** `render_commit_types`,
`render_branch_types` and `render_refs_policy` now write the resolved value on
every run. For an unset knob that rewrites exactly what the template already
ships, so a default scaffold stays byte-identical and the drift baseline is
untouched; for a cleared knob it restores the default instead of stranding the
previous render.

**2. `render_branch_types` gained a generic anchor.** It was anchored on the
literal stock alternation, which by construction stops matching the moment a
custom set has been rendered — so making it unconditional alone would not have
fixed it, because the stock set could never be written back. The anchor is now
the `(?!^(` prefix plus the `)/[0-9]` suffix, which together pin exactly this one
alternation: the `(chore)/[a-z0-9]` clause has the wrong suffix, and the
`renovate`/`worktree` clauses have no inner group. Verified to round-trip
byte-identically: stock → custom → stock reproduces the template line exactly.
With the stock literal gone, the old ordering constraint (this render had to run
before anything else that rewrites the line) goes with it.

**3. New `precommit_render_target` helper refuses a symlinked config.** This is
what makes the rest safe. A flake-hooks consumer's `.pre-commit-config.yaml` is a
gitignored `/nix/store` symlink (#883/#1167). `[[ -f ]]` is true for it, and GNU
`sed -i` writes a temp file and renames it over the path — replacing the symlink
with a regular file, which shadows the generated config with a frozen copy and
silently drops the consumer's `hooks`/`hooksExcludes` customizations. Making the
renders unconditional multiplies the chances of hitting that, so every in-place
render of this file now goes through one resolver that refuses both an absent and
a symlinked target. `render_workflow_model`'s `.pre-commit-config.yaml` block was
carrying the same latent hazard and now uses it too.

Skipping costs a flake-hooks consumer nothing: their knobs reach the hook through
`mkProjectShell`, which reads the same `.vig-os` keys at eval time (#1434).

## Additional Notes

`render_workflow_model`'s `gitflow → trunk` transform has the same one-way shape
— switching a consumer back cannot restore the dropped `(?!dev$)` clause or the
prose substitutions — and is deliberately **not** fixed here. It is a set of
anchored prose/marker substitutions across many files rather than a single value
slot, so it needs its own design rather than this pattern. It does get the
symlink guard, since that hazard is identical.
