# [PR 2024](https://github.com/vig-os/devkit/pull/2024) fix(release): restore changelog when abandoning a release

## Description

Abandoning a regular release restores dev's pending changelog entries to Unreleased. Restoration commits are pinned to the checkout SHA so a stale fold cannot silently replace concurrent dev changes. The one-off 1.19.0 repair is generated by the tested command from current dev, preserving concurrent entries and regenerating the mirror.

## Changes Made

- Add `prepare-changelog unfreeze VERSION [FILE]`: combine pending entries and repeated categories, preserve entry order and nested details, and deduplicate whole entries. An absent version is a no-op; dated releases are refused.
- Preserve Unreleased's LF/CRLF style and blank lines between entries. Keep untouched header/history spans verbatim, including their original line endings. Refuse preambles, unsupported headings/prose, and loose bullets without rewriting the file; errors identify the offending section.
- Capture `git rev-parse HEAD` immediately after checkout in both abandon workflows and fail if SHA capture fails, and pass it as `BASE_SHA` to the same Commit App API action used by prepare-release. A non-fast-forward update fails; rerun abandonment from a fresh checkout.
- Re-sync and commit the devkit mirror with the root changelog. Missing pending sections produce no API commit, including hotfix trains and reruns.
- Use devkit-version-pinned host utilities in the consumer job. Trunk scaffolding omits dev restoration. Keep the consumer changelog seed empty.
- Document the command, failure modes and concurrency behavior.

The pinned v0.3.3 [runner reads `BASE_SHA` into `baseSha`](https://github.com/vig-os/commit-action/blob/7ba7e1ae17547813e708d4cc6a771a09f978f724/src/commit-runner.ts#L192), and [commit.ts uses that fixed base for the tree and commit parent, then updates the ref with `force: false`](https://github.com/vig-os/commit-action/blob/7ba7e1ae17547813e708d4cc6a771a09f978f724/src/commit.ts#L414). Retries reuse that base and commit; they do not recompute against a newer dev head.
