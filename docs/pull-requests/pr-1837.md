# [PR 1837](https://github.com/vig-os/devkit/pull/1837) feat: seed the Rust pack on cold adoption (cargo recipes, tool configs, mkRustProject flake, #rust template)

## Description

Ships the Rust pack's missing entry point (#1496: L1, L4, L7). A repo with a `Cargo.toml` now gets a working Rust setup from the scaffold, instead of the Python recipes that skip without a `pyproject.toml` and let CI go green without compiling anything. It also completes #1810's second half: the Rust flake forwards the `.vig-os` hook settings.

**Stack 3/6** for #1833. Base: #1836 (`feature/1834-rust-sandbox-test-excludes`).

## Type of Change

- [x] `feat` -- New feature
- [x] `test` -- Adding or updating tests

## Changes Made

**L4: cargo `justfile.project`** (`assets/justfile.d/rust.justfile.project`)
- `lint` = `cargo fmt --all --check` + `cargo clippy --workspace --all-targets -- --deny warnings`; `test` = `cargo test --workspace` (doctests included, and the tests `sandboxExcludes` keeps out of the flake check); `sync` = `cargo fetch`; plus `format`, `test-cov` (cargo-llvm-cov), `build`, `update`, `clean-artifacts`. Each recipe reports its skip when `Cargo.toml` is absent (#1478).

**L1: base tool configs** (`assets/lang.d/rust/`)
- `rustfmt.toml` (stable options only), `clippy.toml` (unwrap/expect allowed in tests), `deny.toml` (permissive licence allow-list, `[licenses.private] ignore = true`, wildcard and unknown-source denial). They are seeded where the repo has none, and they're `PRESERVE_FILES`, so consumer-owned from then on. #1400 settled ownership: the pack owns them, and guardrails' copies defer.
- `.cargo/config.toml` is **deliberately not shipped**. Everything it would carry (mold, linker flags) already comes from the flake's rust module, so the file would only be comments.

**Rust `flake.nix`** (`assets/flake.d/rust.flake.nix`)
- Replaces the fresh `flake.nix` on a first direnv scaffold of a Cargo repo (never an existing one). `rust = vigos.lib.mkRustProject { … }` provides `devShells.default`, and `inherit (rust) checks packages;` keeps statix clean. All five `.vig-os` settings are forwarded behind `functionArgs` probes, because `vigos` floats (#1249). This closes #1810's remaining half.
- The managed `.vig-os` reader and the `extraPackages` block are byte-identical to the base stub. `tests/test_rust_scaffold.py` pins that lockstep, so the two stubs can't drift.

**Seeding** (`assets/init-workspace.sh`)
- `seed_node_justfile_project` became `seed_language_variant <dir> <suffix> <target> <preexisted>`. It serves the Node and Rust `justfile.project` and the Rust `flake.nix` from one code path. Node still wins over Rust, as before. A second language that also ships a variant is named in a notice, never silently dropped.
- New `seed_language_statics` walks `lang.d/<lang>/`.
- `infer_legacy_mode` also recognises a `mkRustProject` flake as the scaffold stub.
- `scripts/sync_manifest.py` stamps the preserved banner on the Rust seed and on every `lang.d` file, with targets derived from the layout.

**L7: `nix flake init -t github:vig-os/devkit#rust`** (`templates/rust/`)
- Edition-2024 crate with a library, a binary, a doctest, a unit test, an integration test, `[lints]` and a stripped release profile. The README gives the order (template first, then `install.sh`).

**Consumer matrix**
- `EXPECTED_FAIL[rust]` is removed (c-vigo's acceptance condition on #1496), and the `rust` cell passes.
- New `rust-flake` cell: rust fixture in direnv mode, running `nix flake check` (fmt/clippy/nextest/doctest/doc/deny/workspace), the first-commit hooks, then `just sync/lint/test` inside the flake's dev shell. The fixture gains its `Cargo.lock`.
- The expected-fail mechanism stays tested through a synthetic marker.

## Changelog Entry

### Added
- **Rust cold adoption: a Cargo repo gets a working Rust setup from the scaffold** ([#1496](https://github.com/vig-os/devkit/issues/1496))
  - The first scaffold of a repo with a `Cargo.toml` seeds a cargo `justfile.project`: `just lint` runs `cargo fmt --check` and clippy with warnings denied, and `just test` runs `cargo test --workspace`. It used to get the Python recipes, which skip without a `pyproject.toml`, so CI went green without compiling anything
  - A fresh direnv scaffold of a Rust repo gets a `flake.nix` on `vigos.lib.mkRustProject` instead of `mkProjectShell`: one call wires the dev shell, the `nix flake check` suite (fmt, clippy, nextest, doctests, rustdoc, cargo-deny, the package builds) and `packages`, and forwards the `.vig-os` hook settings
  - Base `rustfmt.toml`, `clippy.toml` and `deny.toml` are seeded where the repo has none; they are consumer-owned from then on and never overwritten
  - New `nix flake init -t github:vig-os/devkit#rust` starter crate that passes the pack's whole check suite as shipped
  - The consumer matrix's `rust` cell now passes, and a new `rust-flake` cell runs the whole direnv path (`nix flake check`, hooks, `just lint`/`just test` in the flake's shell) on every PR

## [Comment #1](https://github.com/vig-os/devkit/pull/1837#issuecomment-6001692459) by [@gerchowl](https://github.com/gerchowl)

_Posted on October 5, 2026 at 07:39 PM_

Follow-ups from an independent review of the stack:
- **Fixed (was a blocker):** the base tool configs were seeded on every `--force`. An existing `mkRustProject` repo without a `deny.toml` would have received one on its next devkit-upgrade PR, which silently switches on `checks.deny`. They are now seeded only for a language this run *adopts*, meaning it was not declared in `.vig-os` before. `DEVKIT_LANGUAGES` and the Rust pack both date from 1.9.0, so every existing pack consumer is covered. Tested: an upgrade of a repo with `DEVKIT_LANGUAGES=rust` seeds nothing.
- Never seeded beside an equivalent: `.rustfmt.toml`, `.clippy.toml` or `.cargo/deny.toml` counts as present. Tested.
- `deny.toml`: the allow-list now also covers `0BSD`, `BSL-1.0`, `CC0-1.0`, `MIT-0`, `MPL-2.0` (file-level copyleft), `Unicode-DFS-2016` and `Unlicense`. `unknown-git` is now `warn`. A real crate's dependency graph no longer turns cold adoption red on licence noise.
- The Rust flake now carries the same commented hooks opt-in block as the base stub. #1167's inserted comment refers to it, and the lockstep test pins it.
