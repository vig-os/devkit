# [PR 1591](https://github.com/vig-os/devkit/pull/1591) feat(sesh): remote project seeds and per-project gh-dash scope/profiles

## Summary

One PR for the coupled pair #1585 + #1586: `vigos.sesh` learns remote project seeds with a runner-aware picker, and `vigos.ghdash` gains per-project scope plus named section profiles. They land together deliberately — both introduce a binary that collides with a downstream config's own copy (`sesh-picker`, `gh-dash-repo`), so shipping them in the same release makes the consumer migration atomic, and the ghdash wrapper is what a sesh layout profile points its dashboard window at.

## vigos.sesh: remote seeds + runner stage (#1585)

- **`vigos.sesh.remotes`** — `{ project, host, path }` list (`host` is an `~/.ssh/config` alias; no connection details in the module). Rendered to `remotes.tsv` beside `sesh.toml` **only when populated**, so the empty default is a bit-for-bit no-op, asserted as such.
- **Runner stage in `sesh-picker`** — appears only when a project has more than one location; last-used runner remembered and pre-selected (`Enter Enter` reconnects). One script for both shapes: an empty-inventory guard at the top preserves today's one-stage flow verbatim, rather than a second generated picker that could drift. Remote-only entries get a portable `⇄` marker (no Nerd-Font dependency).
- **`sesh-remote-connect`** — attach-or-create over SSH (`tmux new -A`), tiered capability probe in a single round trip (`sesh-layout` → full layout; tmux → persistent blank session; neither → warned plain shell), forced `TERM=xterm-256color`, Nix profile bins prepended for non-interactive shells. Ships unconditionally (useful standalone).
- **`vigos.sesh.remoteTerminal`** (design call) — the nested-tmux escape hatch's terminal is an option, not a baked-in binary. **Null default opens a local tmux window** running the ssh client: functional everywhere at the cost of nested prefix keys; set e.g. `"ghostty -e"` for an own-window experience.

## vigos.ghdash: per-project scope + profiles (#1586)

- **`gh-dash-repo [profile]`** — resolves the repo from `origin` at the launch CWD, substitutes it into a rendered template, and `exec`s `gh-dash --config`. Outside a GitHub repo it falls back to the `repoFilters` scope (or `involves:@me`), so it is always valid. Unknown profile → error listing the valid names.
- **`vigos.ghdash.profiles`** (design call) — named section sets with **scope-free filters; the module appends the launch-time scope** (same composition as the generated sections), so a profile cannot silently ship unscoped. `default` mirrors the generated sections and cannot be redefined (same rule as sesh layout profiles). Templates are full merged settings with only the section keys swapped, so consumer tuning carries into every per-repo config; rendered as JSON (a YAML subset) so the text is eval-pure and testable.
- **Backward compatible** — `programs.gh-dash.settings` unchanged (asserted byte-level on the section filters); the placeholder never reaches the global config.
