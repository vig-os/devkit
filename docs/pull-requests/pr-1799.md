# [PR 1799](https://github.com/vig-os/devkit/pull/1799) feat: export packages.<system>.guardrails

## Description

Surfaces the vendored guardrails gates derivation directly as
`packages.<system>.guardrails`, for a consumer that already owns its own dev
shell and a committed pre-commit/prek config and only wants the hermetic
gate binaries — without migrating to `mkProjectShell`.

## Type of Change

- [x] `feat` -- New feature
- [x] `docs` -- Documentation only
- [x] `test` -- Adding or updating tests

### Modifiers

- [ ] Breaking change (`!`)

## Changes Made

- `tests/test_flake_checks.py`: new `test_guardrails_package_is_exposed`
  (builds `packages.<system>.guardrails` and asserts
  `share/guardrails/gates/test-gates.sh` is present in the output) — committed
  failing first (TDD RED).
- `flake.nix`: added `guardrails = guardrailsPkg;` to the cross-platform
  `packages` set (the existing `guardrailsPkg` derivation used by the
  `guardrails` capability module and the `guardrails-canary`/`-shellcheck`
  checks), alongside the existing `services` package (TDD GREEN).
- `docs/NIX.md`: new subsection in Capability modules documenting
  `packages.<system>.guardrails` as the supported API for a consumer that
  owns its dev shell/hook config, and
  `$out/share/guardrails/gates/test-gates.sh` as the supported way to assert
  gate execution in a consumer flake. Docs-only change, no new consumer-facing
  check added (YAGNI, per the issue's "optional" ask #2).
- `CHANGELOG.md` `## Unreleased` → `Added` (mechanically synced to
  `assets/workspace/.devcontainer/CHANGELOG.md` by the `sync-manifest` hook).

## Changelog Entry

### Added
- **`packages.<system>.guardrails`: the vendored gates without a `mkProjectShell` migration** ([#1572](https://github.com/vig-os/devkit/issues/1572))
  - The guardrails gates derivation (previously reachable only through
    `mkProjectShell`'s `modules = [ "guardrails" ]`) is now exposed directly
    as `packages.<system>.guardrails`, for a consumer that owns its own dev
    shell and pre-commit/prek config and only wants the hermetic gate
    binaries. Composes with #1492: the consumer's hook config stays
    consumer-owned
  - Documented in `docs/NIX.md`: `$out/share/guardrails/gates/test-gates.sh`
    is the supported way for a consumer to assert gate execution in its own
    flake
