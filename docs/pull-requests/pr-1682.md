# [PR 1682](https://github.com/vig-os/devkit/pull/1682) fix(ci): freeze main's carried changelog entries in the hotfix lane

## Description

`prepare-hotfix.yml` refused to start whenever `main`'s `## Unreleased` had content, resting on [#590](https://github.com/vig-os/devkit/issues/590)'s invariant that it never does. [#1676](https://github.com/vig-os/devkit/issues/1676)'s revised plan supersedes that invariant — `main` may now carry changes that have landed but are not yet shipped — and this refusal was its only mechanical blocker. Left alone, the lane that exists for urgent security incidents would refuse every time the release-neutral lane had been used.

A hotfix cuts from `main`'s head, so it **ships** whatever `main` carries; those entries belong in the hotfix's own version section. The refusal becomes a branch on content.

## Changes Made

- **`validate` classifies instead of refusing.** The step is now `Classify main's Unreleased section`: it probes with `prepare-changelog validate`, sets `MODE=prepare` when the section carries entries and `MODE=seed` when it does not, dry-probes that exact call locally, and publishes the verdict as a new `changelog_mode` job output.
- **`prepare` branches on that verdict.** `prepare-changelog prepare X.Y.Z` freezes `main`'s carried entries into `## [X.Y.Z] - TBD` (plus a fresh empty Unreleased); `prepare-changelog seed X.Y.Z` writes an empty section exactly as before. The classification is load-bearing: `prepare` run on an *empty* Unreleased scoops the previous release's section instead (verified locally), which is why the mode is decided before anything is written.
- **The write still lands on the release branch only** — never `main`, never `dev` — so rollback remains "delete the branch". `main`'s `## Unreleased` self-clears when the release branch merges back.
- PR body, run summary and the seed commit message now state which of the two happened, so a non-empty section is visible rather than silently tolerated.
- Header comments, `docs/RELEASE_CYCLE.md` (hotfix preconditions, CHANGELOG-state block, `prepare`/`seed` CLI reference) and `docs/DOWNSTREAM_RELEASE.md` record the superseded invariant.

**Not changed, deliberately:** `release.yml`'s publish-time gate (`prepare-changelog validate --version`). No empty sections at release time; an empty section is acceptable at `prepare-hotfix` time. This does mean carried entries satisfy that gate without the hotfix's own fix being described — accepted on the issue, no compensating check added. Both the PR body the lane writes and the docs say so explicitly.

**Commit split.** Devkit's own `.github/workflows/` copy and the `assets/workspace/` scaffold copy land as separate commits: the first is release-neutral and can reach `main` through the #1676 lane, the second is a published asset and needs a release. The scaffold copy **did** carry the equivalent refusal (its own dialect: mode-aware toolchain, no `uv run`) and received the same branch.
