# [PR 1960](https://github.com/vig-os/devkit/pull/1960) test: add strict managed workflow expression evaluator

## Description

Add a strict GitHub Actions expression evaluator so test tooling can execute the managed workflows' runner wiring. Unknown syntax raises with the whole expression and position, even in short-circuited branches. Case-insensitive lookup closes a fork-safety regression that previously went undetected.

## Type of Change

- [x] `test` -- Adding or updating tests

### Modifiers

- [ ] Breaking change (`!`)

## Changes Made

- Add `evaluate(expression, context)`, typed `render(value, context)` for runs-on, and string-valued `render_input(value, context)` for step/reusable-job with values. The JSON CLI is `python -m tests.github_expression --context ctx.json --expr '...'`; `--input` stringifies its result. Context-file errors exit 2 without a traceback.
- Place the helper in `tests/` beside `workflow_scaffold.py` and `nix_helpers.py`: shared pytest/bats infrastructure belongs here; `packages/vig-utils` ships consumer utilities. Document usage and strict limits in the module docstring.
- Support the managed subset: context/property lookups, literal string indexing with runner array conversion/floor/bounds semantics, double-valued literals, grouping, logical/equality operators, interpolation, and case-insensitive fromJSON/toJSON function names. Other functions, numeric/dynamic indexing, and filters raise.
- Resolve property names case-insensitively and reject ambiguous object keys. Reject non-standard JSON constants; treat context NaN as falsy; use per-character simple uppercase mappings for OrdinalIgnoreCase equality and property matching. Keep keyword literals lowercase per the runner lexer. Use one number parser for hex literals and coercion, rejecting invalid/overflowing hex literals and preserving signed Int32 values. Match double precision, G15 formatting and negative zero. Reject non-finite numeric CLI results (exit 2) to keep stdout valid JSON; name unsupported YAML scalar types accurately.
- Match toJSON output with two-space indentation, LF newlines, compact empty collections, G15 scalar numbers, and Newtonsoft string escaping. Tests cite GitHub documentation and the runner/Newtonsoft source used for exact formatting.
- Evaluate every shipped runs-on, resolve-step with, and reusable-job with value for fork PR, same-repo PR, and push contexts, with runner variables set/unset. Mutation tests copy workflows and prove that the exact mixed-case fork escape and a reusable-input contains call fail the gate.
- Audit of runs-on/with/env (including reusable jobs and devkit-upgrade step env) at origin/dev and 1.18.0 found bracket indexing only in origin/dev release-core.yml runs-on. Keep literal string indexes and implement the runner Index.cs array behavior; numeric/dynamic indexes and filters stay outside the managed subset.
- No workflow/action or S8 consumer-matrix changes; lane-mapping assertions remain S8's responsibility.
