# [PR 1536](https://github.com/vig-os/devkit/pull/1536) fix(vig-utils): skip inline code spans when matching blocked emails

## Summary

Implements #1521 (follow-up to the #1516 train blocker): the `emails` blocklist in `contains_agent_fingerprint` matched as a bare substring over the whole content, so a changelog entry or PR body that merely *quotes* a bot identity in an inline code span blocked its own release PR.

Of the two options the issue offered, this takes **code-span stripping**, not the `_ATTRIBUTION_CONTEXT_RE` guard — deliberately: the context regex (`…[\s-]+by\b`) does not match `Signed-off-by:` (the `-off-` infix) or `Author:` lines, so gating emails on it would let real attributions through and would have required deleting two deliberate #274-era pins. Instead:

- New single-line `_CODE_SPAN_RE` (`` `[^`\n]+` ``) — single-line so an unbalanced backtick can't swallow a following attribution line (pinned by test).
- The email loop matches against the span-stripped text; `names` keeps its #274 context guard, trailer rules still see raw lines, case-insensitivity preserved. Implemented in code rather than `allow_patterns` because a TOML allow-pattern would also strip before *name* matching, weakening #274.
- No vendored code copy exists (consumers use the published package); the scaffold ships only the blocklist *data*, unchanged.

## Test plan

- Acceptance 1 (red before fix): the verbatim pre-#1516 changelog wording (recovered from `git show 2c533424`, load-bearing line quoting `github-actions[bot]`) now passes `check-pr-agent-fingerprints` run against the **real** blocklist — previously reproduced the exact #1516 CI failure.
- Acceptance 2 (regression pins, green before and after): `Co-authored-by`, `Signed-off-by`, `Author:` attributions still fail; `GitHub-Actions[Bot]` case-insensitivity; names behavior unchanged; a trailer whose email is wrapped in backticks still fails via the trailer rule.
- `packages/vig-utils/tests`: 523 passed (+9 new); `test_workflow_pr_agent_fingerprints.py` + `test_flake_hooks.py`: 70 passed; `prek run --all-files` exit 0 (verified independently of the implementation run).
- Sanity: this branch's own `## Unreleased` section run through `check-pr-agent-fingerprints` as PR_BODY → exit 0.

Closes #1521
