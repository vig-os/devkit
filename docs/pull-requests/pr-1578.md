# [PR 1578](https://github.com/vig-os/devkit/pull/1578) feat(nix): add poppler-utils to the docs capability module

## Summary

Adds `poppler-utils` to the `docs` capability module, so `modules = [ "docs" ]`
covers reading PDFs as well as writing documents.

`typst`/`typstyle` were the writing half only. Without `pdftotext`/`pdftoppm` on
PATH there is no CLI path from a PDF to text, and an agent's file reader — which
shells out to `pdftoppm` to render a page — cannot open a PDF at all. Every
consumer the module names (exo-pet/vault, the future `qms` app, EXOMA
presentations/grants) handles PDFs.

## Changes

- `nix/modules/docs.nix` — `poppler-utils` in `packages`, docstring records the
  PDF-reading rationale and why OCR stays out
- `docs/NIX.md` — the `docs` bullet gains a "PDF reading is part of the
  capability" paragraph; OCR joins the deliberate-exclusions list
- `tests/test_flake_modules.py` — `test_docs_module_provides_poppler_utils`
  asserts `pdftotext`/`pdftoppm` resolve from the module shell's own PATH
- `CHANGELOG.md` — Added (semver:minor, additive capability)

## Cost

`nix path-info -S nixpkgs#poppler-utils` on the current pin: **145.9 MB**
(139 MB when the issue was filed). OCR is explicitly out of scope: `tesseract`
1.11 GB, `ocrmypdf` 1.68 GB — an order of magnitude more for a capability most
`docs` consumers never use. It stays repo-local in exo-pet/vault#70 until a
second consumer justifies a dedicated `ocr` module.
