# [PR 1606](https://github.com/vig-os/devkit/pull/1606) feat(home): org tmux keybindings and terminal defaults for vigos.multiplexer

## Description

`vigos.multiplexer` set five options and no keybindings, and left
`programs.tmux.terminal` at home-manager's default. Every consumer re-derived
the same `extraConfig` by hand, and a host running the module bare — a shared
remote development guest, a devcontainer — got none of it.

Two concrete symptoms, both from #1605:

- `prefix + X` (kill the current session) lived only in a downstream personal
  config. `prefix + x` still worked there because kill-pane is a tmux default;
  `X` is not, so a habit built on one machine silently did nothing on the next.
- `programs.tmux.terminal` evaluated to `"screen"`: 8 colors, no italics. Every
  colored tool the org ships — starship, neovim, delta, lazygit, `gh-dash` —
  rendered degraded the moment it ran inside tmux, on every host.

## Type of Change

- [x] `feat` -- New feature

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

Not breaking, but two behaviour caveats for a host already enabling the module
(both accepted in the issue's Impact section):

- `prefix + l` becomes `select-pane -R` rather than stock `last-window`. The
  only default this replaces; coherent with the module's own `keyMode = "vi"`,
  and the cookbook now shows how to take the key back.
- `detach-on-destroy off` changes what happens to a client after its session
  ends — it switches to another live session instead of dropping to a shell
  (still detaches if that was the last one).

## Changes Made

`nix/home/multiplexer.nix`:

- `terminal = lib.mkDefault "tmux-256color"` plus
  `set -ga terminal-overrides ",*256col*:Tc"` for truecolor.
- `bind-key X confirm-before … kill-session` — `X` is unbound in stock tmux, so
  this takes nothing away, and the prompt keeps a stray prefix from destroying
  a project's layout.
- cwd-preserving splits/new windows, `renumber-windows`, `focus-events`.
- `set-clipboard on` (OSC 52 — a yank on a remote host reaches the local
  clipboard with no X forwarding) and `v`/`y` in copy mode, which the module's
  own vi `keyMode` does not imply.
- `detach-on-destroy off`, `set-titles` / `set-titles-string "#S"`.
- `h`/`j`/`k`/`l` pane selection.

The block is a plain (not `mkAfter`) `extraConfig` definition, so it lands
*before* any `lib.mkAfter` block. tmux takes the **last** binding of a key, so
the override seam `vigos.sesh` already uses for `bind o` keeps working, and a
consumer can take a key back the same way.

`docs/home/COOKBOOK.md` documents that seam.

Deliberately not done: a per-group `enable` option (YAGNI — `extraConfig` is
already the seam and every option is `mkDefault`), and nothing moved into
`vigos.sesh`.

### Manual Testing Details

The generated `tmux.conf` was loaded into a real tmux 3.6a server on an
isolated socket, and the resulting bindings/options read back — the eval
asserts the *text*, this asserts tmux actually accepts it:

```console
$ tmux -f "$conf" -S ./t.sock new-session -d -s probe \; list-keys \; show-options -g
bind-key -T copy-mode-vi v   send-keys -X begin-selection
bind-key -T copy-mode-vi y   send-keys -X copy-pipe-and-cancel
bind-key -T prefix       X   confirm-before -p "kill session '#S'? (y/n)" kill-session
bind-key -T prefix       \"  split-window -v -c "#{pane_current_path}"
bind-key -T prefix       \%  split-window -h -c "#{pane_current_path}"
bind-key -T prefix       c   new-window -c "#{pane_current_path}"
bind-key -T prefix       h   select-pane -L
bind-key -T prefix       j   select-pane -D
bind-key -T prefix       k   select-pane -U
bind-key -T prefix       l   select-pane -R
base-index 1
detach-on-destroy off
history-limit 100000
mouse on
renumber-windows on
set-titles on
set-titles-string "#S"

$ ... \; show-options -s \; show-options -gw
default-terminal tmux-256color
escape-time 10
focus-events on
set-clipboard on
terminal-overrides[0] linux*:AX@
terminal-overrides[1] *256col*:Tc
mode-keys vi
```

`terminal-overrides` appends to tmux's own default rather than replacing it,
and the merged `extraConfig` ends with `bind o display-popup -E "sesh-picker"`
— sesh's `mkAfter` still last.
