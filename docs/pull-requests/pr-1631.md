# [PR 1631](https://github.com/vig-os/devkit/pull/1631) feat: refuse a promote that would move :latest backwards

## Description

Adds a semver guard to `promote-release.yml` so a promote can never move the floating refs backwards. Devkit moves GHCR `:latest` unconditionally; with the hotfix lane (#1621, #1623) a patch cut from `main` and a train cut from `dev` could, if both existed, promote in the wrong order and walk `:latest` back to an older version. The guard is the last line of defence behind the single-train refusals (#1627): the `validate` job compares the version against the highest **published final** GitHub Release — the version the floating refs follow — and fails before the irreversible publish when it is lower.

Design notes (plan comment on #1626): no `org.opencontainers.image.version` label exists (the image is built by Nix; `flake.nix` sets only title/source/licenses) and reading GHCR metadata needs a `packages` scope the scaffold token lacks, so the published-final list is the source of truth. No override input; the recovery is to abandon the stale train and re-cut the fix as the next patch of the published line.

Stacked on #1630 (#1627): this branch is based on `feature/1627-prepare-release-single-train` because both PRs rewrite the same hotfix runbook paragraph. Once #1630 merges, this branch gets rebased onto `dev` so the diff shrinks to the commits listed below.

## Changes Made

- `.github/workflows/promote-release.yml` — new validate step **Verify version does not move :latest backwards**, after the draft-release check: pages `repos/{repo}/releases`, keeps `draft == false && prerelease == false` bare-semver tags, takes the highest with `sort -V`, and fails when `VERSION` sorts below it. Passes when no final release exists yet. A failed API call fails the step (no fail-open).
- `assets/workspace/.github/workflows/promote-release.yml` — the same step for the opt-in git floating tags, gated on `needs.resolve-toolchain.outputs.floating-tags != ''`; release tags are filtered to the `TAG_PREFIX` line and compared after the prefix is stripped, so pre-devkit bare tags are ignored. Consumers without floating tags are unaffected.
- `tests/test_promote_release.py` — shape pins for both copies (data source, filters, `sort -V`, placement after the draft check; devkit unconditional, scaffold gated and prefix-aware).
- `tests/test_promote_latest_guard.py` (new) — runs the extracted step body with `gh` stubbed to answer the release listing: lower refused with the message and remedy, higher passes, numeric (not lexical) ordering, empty list / drafts-only passes, drafts and pre-releases ignored, prefix stripped, tags outside the prefix ignored.
- `docs/RELEASE_CYCLE.md` — release-phases step 6, the hotfix runbook rule (now points at the guard), and a troubleshooting entry for the refusal. `docs/DOWNSTREAM_RELEASE.md` (+ mirror) — floating-tags note. `CHANGELOG.md` (+ mirror).
