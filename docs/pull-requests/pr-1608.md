##### Changed

- **The release pipeline rebuilds the action bundle instead of relying on a hand-written commit** ([#&#8203;157](https://redirect.github.com/vig-os/commit-action/issues/157)). `prepare-release-extension.yml` — the devkit-seeded, consumer-owned no-op whose header names exactly this use case — now resolves the devkit toolchain, runs `just sync && just bundle` on the freshly cut `release/X.Y.Z`, and commits `dist/` when it differs. It runs after the branch is fast-forwarded onto the changelog freeze and before `open-pr`, so the refreshed bundle is in the release PR diff from its first CI run and `Dist Check` validates it; `rollback` already lists `extension` in its `needs`, so a failed rebuild deletes the branch and takes the commit with it. `release-extension.yml`'s finalize-time `verify-dist` is untouched and becomes a genuine backstop rather than the only gate, and `dist-check.yml` triggers are unchanged so `dev` stays ungated ([#&#8203;71](https://redirect.github.com/vig-os/commit-action/issues/71)). This removes the recurring manual rebuild that [#&#8203;130](https://redirect.github.com/vig-os/commit-action/issues/130) fixed once by hand and that had accrued again: six lock-file-maintenance PRs ([#&#8203;139](https://redirect.github.com/vig-os/commit-action/pull/139), [#&#8203;143](https://redirect.github.com/vig-os/commit-action/pull/143), [#&#8203;146](https://redirect.github.com/vig-os/commit-action/pull/146), [#&#8203;148](https://redirect.github.com/vig-os/commit-action/pull/148), [#&#8203;152](https://redirect.github.com/vig-os/commit-action/pull/152), [#&#8203;156](https://redirect.github.com/vig-os/commit-action/pull/156)) moved `@octokit/core`, `@octokit/request`, `@octokit/endpoint`, `@octokit/request-error`, `@octokit/graphql`, `content-type` and `undici` — all **runtime** transitives that `ncc` inlines — while the committed bundle stood still. Drift is read from `git status` rather than a walk of `dist/`, so the gitignored declaration byproducts under `dist/src/` stay untracked (the [vig-os/devkit#1159](https://redirect.github.com/vig-os/devkit/issues/1159) bug behind [#&#8203;134](https://redirect.github.com/vig-os/commit-action/issues/134)), and the commit is made through `vig-os/commit-action` at its last released tag rather than the possibly-stale local bundle.
