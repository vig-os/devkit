# [PR 1968](https://github.com/vig-os/devkit/pull/1968) fix(nix): make project agent CLI an explicit opt-in

## Description

Project shells currently shadow a machine's `claude` wrapper, bypassing its release channel and per-profile credentials. Leave the agent CLI to the machine by default and provide an explicit opt-in.

## Type of Change

- [x] `fix` -- Bug fix

### Modifiers

- [ ] Breaking change (`!`)

## Changes Made

- Split the agent package into one shared list; default, scaffolded, capability, and Rust shells use the agent-free toolchain. Machine modules and the image retain the CLI.
- Add `withAgentCli = false` to `mkProjectShell` and `mkRustProject`. The fixed `devShells.<system>.with-agent-cli` output serves consumers who select a shell output rather than call the builder.
- Document migration and the system-wrapper shadowing effect. Keep the fast-mover overlay and package pin unchanged.
- Add an evaluation-only flake policy check covering default, consumer and scaffolded shells, opt-in package identity, and legacy home-manager/NixOS installs. Update the existing tool-list guard.

## Changelog Entry

### Changed

- **Project shells leave the agent CLI to the machine** ([#1967](https://github.com/vig-os/devkit/issues/1967))
  - Repositories relying on the dev-shell's `claude` must install it machine-wide (or via the home module), or set `withAgentCli = true`; consumers of devkit's own `devShells` output can select `#with-agent-cli`.
  - Opting in shadows any system `claude` wrapper. Home modules and the container image retain the CLI.
