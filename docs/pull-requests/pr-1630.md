# [PR 1630](https://github.com/vig-os/devkit/pull/1630) feat: refuse a regular release train while another release branch exists

## Description

Makes `prepare-release.yml` refuse to cut a regular train while any other `release/*` branch exists on the remote — the symmetric counterpart of the single-train policy `prepare-hotfix.yml` enforces (#1621, #1623). Without it a regular train can be cut from `dev` over an in-flight hotfix: that train predates the fix, so promoting it afterwards silently reintroduces the regression, and promoting it first walks `:latest` backwards.

The check is branch-name based and lives in the `validate` job directly after the existing "release branch does not exist" step, so the trunk render carries it unchanged. Same message shape as the hotfix lane: list the offenders, then "promote or abandon it first". No override input (a second concurrent train was never a supported state). Plan: the implementation-plan comment on #1627.

## Changes Made

- `.github/workflows/prepare-release.yml` — new validate step **Verify no other release train is in flight**: enumerates `refs/remotes/origin/release/` (the checkout is `fetch-depth: 0`, like the existing remote branch check) and fails with the list when any exists.
- `assets/workspace/.github/workflows/prepare-release.yml` — same step in the scaffold dialect (`git ls-remote --heads origin 'release/*'`, consistent with its existing branch/tag checks).
- `tests/test_workflow_prepare_extension.py` — shape pin for both copies and the `cached_tree("trunk")` render: the step directly follows the branch-exists check, enumerates remote `release/*` refs, carries the message and remedy, and exits 1.
- `docs/RELEASE_CYCLE.md` — Phase 1 prerequisites gain the precondition; the `prepare-release.yml` validate step list and the hotfix-lane runbook rule are updated (the prepare direction is now enforced in both directions; the `:latest` promote guard is #1626).
- `CHANGELOG.md` (+ scaffold mirror) — Unreleased entry.
