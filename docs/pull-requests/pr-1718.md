# [PR 1718](https://github.com/vig-os/devkit/pull/1718) feat(hooks): shellcheck the run bodies of composite actions

## Description

`actionlint` lints the shell in workflow `run:` steps but refuses composite actions outright (`unexpected key "runs" for "workflow" section`) and has no composite mode (#245 closed as a duplicate of the dormant #46; 1.7.12 is the latest release). So the 44 `run:` bodies across the seven composites — devkit's `build-image`, `setup-env`, `test-image`, `test-integration`, `test-project`, and the scaffold's `resolve-toolchain` and `setup-devkit-toolchain` under `assets/workspace/`, which are the ones consumers actually run — had no shellcheck pass at all, locally or in CI. #1692 moved seven more bodies into `test-project`, each shellchecked by hand for that PR and unguarded since.

This adds `shellcheck-composite-actions`, a vig-utils console script wired as a scaffolded pre-commit hook. It reproduces actionlint's own recipe rather than approximating it: stdin = `set -eo pipefail` + body, each `${{ … }}` replaced by same-length underscores with newlines kept (so line **and** column offsets are exact), and actionlint's exclude list passed verbatim (`SC1091,SC2194,SC2050,SC2153,SC2154,SC2157,SC2043` — precisely the placeholder-induced false positives). Gate is `-S warning`; findings print in `action.yml` coordinates with the step name; inline `# shellcheck disable=` directives survive extraction. `sh` steps get `set -e` and `--shell sh`; `python`/`pwsh`/`powershell`/`cmd`/`node` and `uses:` steps and non-composite actions are skipped; any other unrecognised `shell:` value is skipped with a stderr note so a typo cannot quietly unlint a body (review finding).

The `files` regex `(^|/)\.github/actions/[^/]+/action\.ya?ml$` covers both trees with one pattern (the scaffold's copy is `.github/actions/` once scaffolded), so the same hook serves devkit, the scaffold copy and consumers unchanged. The Nix `check` and `consumer` fragments pin both the vig-utils binary and `shellcheck` by store path; the portable YAML entry stays store-path free like its siblings.

**First run over the seven composites: one real finding**, exactly as triage predicted — an unquoted `$(id -u)` in the podman socket URI of `test-integration` (SC2046). Fixed, not suppressed. The `$TEST_ARGS` SC2086 the issue cites is info-level and does not fire at `-S warning` (a test pins that `--severity info` surfaces it), so acceptance criterion 2 needs no suppression.

  ([#1704](https://github.com/vig-os/devkit/issues/1704))
  - `actionlint` refuses a composite action outright (`unexpected key "runs" for

  - Scaffolded: new scaffolds and flake-hooks consumers gate their own

    insert row. Findings are reported in `action.yml` coordinates. The first

Filed as #1717 to be done on the release branch, never speculatively on `dev`. New scaffolds get the hook immediately.
