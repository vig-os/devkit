# [PR 1964](https://github.com/vig-os/devkit/pull/1964) test: add workflow step replay helper

## Description

Add a small workflow replay helper so consumer-matrix tests can execute workflow scripts with evaluated env and conditions, isolated shells, and real output/environment propagation.

## Changes Made

- Add `tests.workflow_replay.Replay` and a JSON CLI with explicit step selection and seeded context for external boundaries.
- Reuse the expression evaluator for conditions and stringified env/run values; add the authorized `steps` and `env` context roots.
- Run steps in separate bash processes, parse single-line and multiline command files, and expose outputs to later steps. Document supported behavior and refusals in the module docstring.
- Fetch only tag `1.18.0` before devkit project tests: checkout is shallow, and the real pre-N workflow test intentionally fails if the tag is absent. This step is limited to the pytest suite; consumer workflows and S8 cells are untouched.

## Diff map

- `tests/github_expression.py` and its tests: accept `steps` and `env` roots with the existing case-insensitive lookup and ambiguity checks.
- `tests/workflow_replay.py`, `_file_values`: strict UTF-8 command-file decoding, LF-only parsing, multiline values and malformed-entry errors.
- `Replay.resolve_env` / validation: env precedence, literal workspace-relative working directories, and explicit refusals of unsupported step/job fields.
- `Replay.run` / execution / result handling: Linux implicit vs explicit bash defaults, isolated scripts, step outputs/outcome/conclusion, replacement of seeded replayed ids, and context-derived default variables.
- `tests/test_workflow_replay.py`: behavioral contracts, runner-source citations, real tag env resolution, mutations, byte-level regressions, CLI and failure cases.
- `.github/actions/test-project/action.yml`: fetch only the required historical tag before project pytest runs.
