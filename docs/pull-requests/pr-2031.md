# [PR 2031](https://github.com/vig-os/devkit/pull/2031) fix(ci): pin API file commits to checkout revisions

## Description

Pin all API file commits to the revision used to compute their files. Concurrent updates now cause a non-fast-forward failure instead of silently replacing newer changelog entries or generated files. Both devkit and consumer workflows use fail-closed SHA capture immediately after the relevant checkout.

## Changes Made

- Add an adjacent runtime guard before all 18 API file commits, checking the exact BASE_SHA input with the same condition as the commit.
- Export the consumer freeze action’s commit-sha directly; the visibility wait accepts only that confirmed SHA. Add complete rollback diagnostics and manual-release-review guidance.
- Export the root freeze action’s exact commit SHA before branch creation; skip rollback restoration when it is empty or dev has advanced.
- Verify each capture matches its target (or documented new-branch source), and that capture gates cannot be narrower than commit gates. Keep the extension fallback gate; make sync captures unconditional.
- Merge the duplicate Unreleased Fixed headings in the root changelog and generated mirror.
- Wire checkout outputs into `BASE_SHA` for all 16 previously unprotected calls; retain the two protected abandon-release calls.
- Use the checkout SHA for prepare's rollback baseline, rather than a later moving-head API read.
- Explicitly check out dev for consumer rollback. Capture the extension fallback's second checkout separately; capture the sync branch after its creation/checkout.
- Document the concurrency guarantee and recovery behavior in RELEASE_CYCLE.

Every `vig-os/commit-action` call under both workflow trees was audited. No moving-head exemptions are needed. `D` means `.github/workflows/`; `C` means `assets/workspace/.github/workflows/`.
