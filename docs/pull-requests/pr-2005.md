# [PR 2005](https://github.com/vig-os/devkit/pull/2005) feat(docs): add opt-in Typst guards and reproducible builds

## Description

Document projects can opt into formatting, compile, package-pin, and generated-PDF guards through the docs module. Scaffold upgrades reconcile committed hook configs and install reproducible build recipes while preserving consumer comments and exclusions.

## Changes Made

- Define four opt-in guards in nix/hooks.nix and drift-check the portable scaffold asset against that definition.
- Select entries with whitespace-tolerant `// devkit: entry` markers, warn about suspicious unmarked entries, smoke-compile templates, and support DEVKIT_TYPST_SKIP globs.
- Add stamped/canonical recipes with dependency lists and fixed epoch/timezone. Use built-in fonts by default and explicit repo-relative DEVKIT_TYPST_FONT_PATHS for branding; always ignore system fonts. Report resolved tool binaries and their own versions as JSON.
- Reconcile module-owned hooks inside the actual repos sequence using existing PyYAML source spans. Preserve indentation, CRLF, final-newline presence, comments, and original exclusions; ON/OFF restores original bytes. Validate staged and installed output with prek and roll back on failure. Skip existing hand-written document hooks with a notice.
- Keep docs-only committed-config shells out of generated-hook installation. Explicit hooks = { }; still enables generated hooks.
- Require ON lint findings to have no increased count for any rule/message under strict scaffold yamllint and consistent sequence indentation. Catch generated PDFs case-insensitively.

### Reconciliation design decision

The docs hooks fit the existing exact feature-marker block model (#1654). Reversible per-fixer `exclude` merges do not fit its version-gated whole-block tables. Extract the existing `hook_block_range`, `splice_lines`, and `delete_lines` shell functions into `assets/preserved-hooks.sh`, used by both legacy folds/inserts and docs. Route docs through the central preserved-hook pass and its insert/fold/drift reporting. Remove `typst_scaffold.py` and its separate marker matcher and position-keyed base64 protocol.

The small YAML-aware extension stages edits around those shared primitives, uses marker-only docs lookup while retaining structural lookup for legacy hooks, validates with prek, and rolls back on expected or unexpected failures. Restore exclusions by repository/hook ID and compare parsed values, allowing formatter re-quoting. Bounded state comments preserve original field bytes; derive indentation from the consumer structure and reuse an existing local hook sequence where available to avoid multiplying existing lint findings. Write and restore bytes in place to preserve the inode. Decline hand edits anywhere in the owned block, including comments, using the existing fold ownership rule. Failures print manual advice and let the installer continue. Existing pre-release blocks with the old state format require manual cleanup; they are left intact with a warning.

The installer owns `justfile.devkit-docs` to avoid collisions with consumer `justfile.docs` files, which are never touched or imported. Only docs ON with a managed recipe file emits the import; unmanaged files at the reserved name are retained without importing them. Preview reports hook and recipe/import changes. Inline comments on injected exclusion fields are refused before any text is dropped; deleted fixers, changed repository URLs, and relocated excludes receive precise recovery advice. See docs/NIX.md. Extended regex comments cannot swallow the generated-directory alternative.
