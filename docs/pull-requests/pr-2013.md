# [PR 2013](https://github.com/vig-os/devkit/pull/2013) feat: add opt-in terminology register guards

## Description

Document-oriented consumers can keep canonical terminology and part numbers in a YAML register. The opt-in docs module installs schema validation and tracked-source checks that reject forbidden variants with their replacements and report unknown numbers in registered part families. Registered terms and aliases remain valid, including casing corrections such as Github → GitHub and us → US.

## Changes Made

- Ship the JSON Schema with vig-utils, expose `glossary-guard schema|terms`, and document a release-tagged schema URL for editors.
- Reject duplicate YAML keys, duplicate IDs, ambiguous registered names, cross-entry forbidden aliases, unknown replacements, invalid regex/flags, empty-matching patterns, and numbers inconsistent with their own pattern.
- Preserve registered term/alias spans and handle casing corrections separately; compile forbidden variants into one alternation per case mode. Match across Unicode whitespace and hard wraps, with underscore prose boundaries.
- Scan only tracked Markdown/Typst sources selected by Git pathspecs; exclude hidden/generated paths, report non-UTF-8 files individually, and support file-type-specific end-of-line suppression markers. Code spans and fences are scanned.
- Scope known part numbers to entries sharing an identical pattern, deduplicate unknown-token reports, and exclude URL spans.
- Add reversible docs-module hooks through the shared hook definition and scaffold reconciler; preserve register/source settings across upgrades.
- Include jsonschema and its runtime dependencies in every image/toolchain through vig-utils, sharing the editor/hook structural-validation contract. Hook activation and scanning remain opt-in.
- Verify image venv isolation directly even when the toolchain already supplies the probe package.

## Additional Notes

An absent default register is a no-op. A configured missing register fails. Schema mode never scans sources; terms mode with a nonempty register requires a Git working tree and has no non-Git fallback. Source checks do not parse markup or discover synonyms. Hyphens are literal, not whitespace separators. Candidate discovery, its recipe/workflow, and Typst package helpers remain separate phases.
