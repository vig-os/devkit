## Changes Made

**#1757, sync watermark.** In both copies of `sync-issues.yml` (scaffold and devkit's own), `Save sync state` changes from `if: always()` to `steps.sync.outcome == 'success' && steps.commit.outcome != 'failure'`.
- A failed push keeps the old cutoff, so the next run retries the same delta.
- A skipped commit (nothing changed) still saves.
- The 14-day look-back on a cache miss already covers the endless-rebuild loop that `always()` was added to break.

**#1759, stacked PRs.**
- `pull_request.branches` is now `'**'` in both copies of `ci.yml` and `codeql.yml`.
- `codeql.yml` gets `concurrency: codeql-${{ github.workflow }}-${{ github.ref }}`, with `cancel-in-progress: ${{ github.event_name != 'push' }}` so post-merge analysis on `main` still reports every merge.
- The trunk render's `- dev` filter deletion and the trigger-header prose rewrites for these two files are gone. They were dead code once the filter no longer lists `dev`.

**#1745, Dist Check deadlock** (the issue's option (a)).
- The detect-and-build logic moves out of `release-core.yml` into a new managed composite action, `.github/actions/build-bundle`. It outputs `has_bundle` and `dist_paths` and keeps the #1159 non-ignored-files rule.
- `prepare-release.yml` calls it before the CHANGELOG freeze, and the rebuilt `dist/` rides the freeze commit. The release PR therefore opens with a fresh bundle.
- `release-core.yml` calls the same action at finalize. The rebuild is idempotent, and the tag stays authoritative.
- Rollback still reverts only `CHANGELOG.md`; a fresher bundle on the integration branch is harmless.
- The action is added to the `release` feature group, so a release-less repo does not receive it.

**#1366, App-ID fallback.**
- `devkit-upgrade.yml` reads only `DEVKIT_UPGRADE_APP_CLIENT_ID`. The fallback expression, the legacy branch of the preflight check and the deprecation warning are gone.
- `docs/runbooks/devkit-upgrade-app.md` is updated to match.
- The issue's preconditions were checked live on 2026-09-30:
  - The Client-ID secret exists in vig-os (selected repos), exo-pet (all private repos) and exoma-ch (all repos).
  - Every vig-os repo that can read the legacy secret can also read the Client-ID secret.
  - exo-pet already has no legacy secret.
- Commit type is `feat`, not `feat!`: by the issue's own reasoning, the set of consumers this breaks is empty.

**#1753, multiplexer.** `detach-on-destroy off` → `no-detached`, with the comment updated.
