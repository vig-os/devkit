# [PR 1623](https://github.com/vig-os/devkit/pull/1623) feat: add the hotfix release lane cut from main

## Description

Adds the gitflow hotfix lane (Phase 1, devkit-only): a new `prepare-hotfix.yml` workflow cuts `release/X.Y.Z` directly from `main`, so an urgent fix (typically a security-register incident, cf. #1592 / #1614) ships as a patch release without carrying whatever `dev` has accumulated. The fix lands via a `bugfix/N-*` PR into the release branch; the existing candidate/final/promote/abandon train and `sync-main-to-dev` run **unchanged**.

Decisions on the issue's open questions, as posted in the [implementation plan](https://github.com/vig-os/devkit/issues/1621#issuecomment-5661033925): version policy is machine-enforced (patch+1 of the latest stable tag on `main`); a hotfix is hard-refused while any other `release/*` train is in flight; `:latest` ordering stays a runbook rule; the post-promote sync conflict on `CHANGELOG.md` is accepted and documented; the scaffold port (copy-excluded under trunk) is a follow-up issue.

## Changes Made

- `.github/workflows/prepare-hotfix.yml` (new) — validate (semver, patch-of-latest-main-tag, no other `release/*` branch, no colliding branch/tag, empty Unreleased on `main`), prepare (re-check `main` unmoved, cut branch at `main`'s SHA via the Git Data API, `prepare-changelog seed`, commit to the release branch via `commit-action`, assert the branch head is the seed commit), extension (reuses `prepare-release-extension.yml` with the seed commit as `branch_sha`), open-pr (draft PR to `main`, bare checkout), rollback (`always()`, deletes the partial branch only). No job reads or writes `dev`; every checkout sets `persist-credentials: false`.
- `.github/workflows/release.yml` — the validate job's "Verify CHANGELOG has TBD entry" step now runs `prepare-changelog validate --version` (content required, not just the heading). Note: for a hotfix `release.yml` runs from `main`'s copy, so this guard reaches hotfix trains only after it ships through a normal train.
- `packages/vig-utils/src/vig_utils/prepare_changelog.py` — new `seed VERSION [FILE]` subcommand (empty `[VERSION] - TBD` under an empty Unreleased; refuses a non-empty Unreleased or an existing section) and `validate --version X.Y.Z` (pending section must carry bullets).
- `packages/vig-utils/tests/test_prepare_changelog.py` — `TestSeedChangelog`, `TestValidateVersionSection`, `--version` cases in `TestCmdValidate`, subprocess e2e cases.
- `tests/test_workflow_prepare_hotfix.py` (new) — shape pins for the lane (no dev access, branch cut from main, dry-run gating, validate policy markers, seed commit target and `branch_sha` hand-off, draft PR to main, rollback scope, the `release.yml` guard, and the scaffold leak guard); `tests/test_workflow_prepare_extension.py` — the hotfix lane joins `CALLER_WORKFLOWS` so the branch → extension → PR DAG and rollback/cancellation contracts apply to it.
- `justfile.gh` — `just prepare-hotfix X.Y.Z [ref] [flags]` (default ref `dev`); `scripts/manifest.toml` — `RemoveBlock` transform strips it from the scaffolded `justfile.gh` until the Phase 2 port; `justfile` — process comment; `README.md` / `CONTRIBUTING.md` — regenerated recipe tables.
- `docs/RELEASE_CYCLE.md` — branch hierarchy/table, new "Hotfix lane" section (preconditions, workflow steps, fix-PR contract, sync-conflict recipe, runbook rules, rehearsal, scaffold status), `seed` / `validate --version` docs, recipe list, two troubleshooting entries.
- `CHANGELOG.md` (+ mirror) — Unreleased entry.

## Changelog Entry

### Added

- **Hotfix release lane: cut `release/X.Y.Z` from `main` without going through
  `dev`** ([#1621](https://github.com/vig-os/devkit/issues/1621))
  - New `prepare-hotfix.yml` workflow (`just prepare-hotfix X.Y.Z`): validates
    that the version is the next patch of the latest stable tag on `main` and
    that no other `release/*` train is in flight, forks the release branch at
    `main`'s head, seeds an empty `## [X.Y.Z] - TBD` section on the branch
    (never `main`, never `dev`), re-syncs the workspace mirror through the
    existing `prepare-release-extension.yml` hook and opens the draft PR to
    `main`. Rollback deletes the partial branch and nothing else. The fix
    lands via a `bugfix/N-*` PR into the release branch; candidate, final,
    promote and abandon run unchanged
  - `prepare-changelog seed X.Y.Z` inserts the empty section under an empty
    Unreleased and refuses anything else; `prepare-changelog validate
    --version X.Y.Z` checks the pending section carries content, and
    `release.yml` now gates on it so a seeded-but-unfilled section cannot
    ship. That gate reaches hotfix trains only once it has shipped through a
    normal train, since `release.yml` runs from `main`'s copy for a hotfix
  - Accepted cost: the post-promote `sync-main-to-dev` PR conflicts on
    `CHANGELOG.md` whenever `dev` is ahead; the resolution recipe and the
    runbook rules live in `docs/RELEASE_CYCLE.md` (Hotfix lane). Devkit-only
    for now: the `assets/workspace/` port is a follow-up, and the recipe is
    stripped from the scaffolded `justfile.gh` until it lands

## [Comment #1](https://github.com/vig-os/devkit/pull/1623#issuecomment-5661819147) by [@c-vigo](https://github.com/c-vigo)

_Posted on September 14, 2026 at 09:23 AM_

**Layer 1 correction.** The plan (and #1621) assumed a workflow pushed on a non-default branch is dispatchable. It is not: `prepare-hotfix.yml` is `workflow_dispatch`-only, and GitHub registers a workflow only when an event creates a run for it. The `spike-992-conditional-container.yml` precedent was registered by its own `pull_request` run, which this workflow deliberately does not have. With this PR open, `GET /actions/workflows` still lists no `prepare-hotfix.yml` and `gh workflow run prepare-hotfix.yml --ref feature/1621-hotfix-release-lane` returns `HTTP 404: workflow not found on the default branch`.

Consequences:
- No dry-run or real dispatch is possible until the file is on `main`, i.e. after the next regular train ships this change. Merging to `dev` is not enough (`dev` is not the default branch). This also holds for the `release.yml` guard, as already noted.
- `just prepare-hotfix` (default ref `dev`) works from then on exactly like `prepare-release`: the registration comes from `main`, `--ref` picks which copy runs.
- Test layers before the first dispatch are therefore: the shape tests in this PR, plus (optionally) executing the `validate` job's bash locally against fixture refs, the same way `tests/workflow_scaffold.py::run_ci_gate` executes the CI-green gate. The Layer 2 candidate-only rehearsal runs after that train and after `release/1.14.1` promotes, as `MAJOR.MINOR.(PATCH+1)` of whatever `main` ships then.
