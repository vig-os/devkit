# [PR 1510](https://github.com/vig-os/devkit/pull/1510) feat(release): single human approval at promote; unattended smoke leg

## Summary

Collapses the release train's three human interactions into **one**: the approval of the devkit release PR, collected after finalize and immediately before promote — where it lands on the release content exactly as it ships, finalize commits included.

**#1504 — approval moves to promote**
- `release.yml` validate (and the consumer `release-core.yml`) no longer asserts review state for finals; the draft and CI gates stay, candidates unchanged (#902). The promote-side gates (#1487) are untouched and become the cycle's single approval. Revisits #1474 under its own stated condition.
- New `just abandon-release X.Y.Z` + `abandon-release.yml`: the first-class rejection path at promote time. As the Release App (same tag-ruleset-bypass machinery as the RC prune) it deletes the **draft** Release by id, the tag, the release PR, and `release/X.Y.Z` — idempotent, fail-closed, and hard-refusing a published release (tombstone protection). Devkit-only for now via a manifest `RemoveBlock`; consumer variant is a follow-up.

**#1506 — smoke approval gone**
- The listener's `Gate final release on human approval of release PR` poll is removed: the smoke PR is bot-authored scaffold output, its Main protection now requires 0 reviews (org-config#167, already applied), and under count-0 the poll could only time out — un-unblockably, since GitHub never computes the polled field.
- The consumer `promote-release.yml` gates (validate + merge) are **protection-aware**: zero required approving reviews on the base branch ⇒ explicit logged skip of the approval assertion (never the #438 fallback). This amends #1506's "compiled out" AC — rationale recorded on the issue: the smoke repo's promote workflow IS the shared scaffold and the drift gate re-renders it from the manifest, so a smoke-only render divergence would trip every smoke PR; the runtime skip is drift-safe and also fixes the whole solo-adoption (count-0) class. Devkit's own promote gates stay unconditional.
- Sequencing invariant (ruleset ⟷ listener must move together, on smoke `main`) recorded in `docs/CROSS_REPO_RELEASE_GATE.md`.

Docs: RELEASE_CYCLE (mermaid, phases, runbook, troubleshooting, new abandon runbook), CROSS_REPO_RELEASE_GATE, DOWNSTREAM_RELEASE (+ scaffold mirror), MIGRATION, CLAUDE.md, justfile process header, CONTRIBUTING/README regenerated.
