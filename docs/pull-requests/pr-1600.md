# [PR 1600](https://github.com/vig-os/devkit/pull/1600) fix(workflows): trust the consumer flake's nixConfig in devkit-upgrade

## Description

The scaffolded `devkit-upgrade.yml` installed Nix with only
`experimental-features`, so a consumer repo whose `flake.nix` declares a
`nixConfig` block had it ignored on **both** Nix legs of the job — `install.sh`'s
`nix flake update vigos` and the `nix develop -c git commit` — each emitting

```
warning: ignoring untrusted flake configuration setting 'extra-substituters'.
Pass '--accept-flake-config' to trust it
```

and resolving the dev-shell against `cache.nixos.org` alone.

`setup-devkit-toolchain` — same scaffold payload, same runner class, same
consumer flake — has always passed the full set. This closes the gap and pins
all three copies to one constant.

## Changes Made

- `assets/workspace/.github/workflows/devkit-upgrade.yml` — the `Install Nix`
  step now carries `accept-flake-config = true`, `extra-substituters` and
  `extra-trusted-public-keys` alongside `experimental-features`, with a comment
  explaining the #773 boundary
- `tests/workflow_scaffold.py` — new shared `NIX_SETTINGS` constant and
  `parse_nix_settings()` helper, so the three places that ship these settings
  assert against one expectation instead of three
- `tests/test_workflow_devkit_upgrade.py` — new
  `test_install_nix_carries_the_toolchain_nix_settings`
- `tests/test_setup_toolchain_env.py` — its two existing assertions now use the
  shared constant (net −22 lines of hand-rolled parsing)

### Not a #773 regression

\#773 removed `accept-flake-config = true` from the **image's baked**
`/etc/nix/nix.conf`, where any in-container `nix run github:attacker/flake` would
silently trust a *foreign* flake's substituters.
`tests/test_image.py::test_nix_conf_does_not_accept_flake_config` still guards
that and is untouched.

This is the other case: a per-runner installer setting, in a job that evaluates
**the consumer's own repo flake** and nothing else — the identical posture
`setup-devkit-toolchain` already ships to every consumer.

### Scope note

This removes two warnings per run and restores the substituters the consumer's
flake asked for. It is **not** a meaningful speed-up: the upgrade step advances
the consumer's `nixpkgs` pin immediately before the `nix develop`, so that
closure is new and no cache holds it. Sized `effort:small` / `priority:low`
accordingly.
