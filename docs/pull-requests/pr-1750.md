# [PR 1750](https://github.com/vig-os/devkit/pull/1750) feat: pluggable pre-release format, draft-first Release owner and publish seam for the release train

## Description

Makes Rust (and Rust+Python) repos first-class on the release train without making the train Rust-aware. It adds three language-neutral seams from #1746:

1. **Pluggable pre-release format.** Candidates can be tagged `X.Y.Z-alpha.1`, `-beta`, `-nightly.YYYYMMDD.N` and so on. The format resolves with precedence dispatch input > `.vig-os` `DEVKIT_PRERELEASE_FORMAT` > `rc{N}`. The default reproduces today's `X.Y.Z-rcN` byte for byte. A format switch that would sort below an existing pre-release of the same `X.Y.Z` is refused.
2. **Draft-Release-first owner contract.** `release-publish.yml` creates the draft (`--target <finalize_sha>`) *before* the tag ref, so tag-triggered asset workflows always find a draft to upload into. That period is the documented "pre-publish assets window". A failed tag push discards the orphan draft, and `promote-release.yml` stays the only publisher.
3. **Standalone `publish-release-extension.yml` seam.** A preserved, default no-op workflow on `release: published`, plus a `workflow_dispatch` tag retry, for irreversible publishes (crates.io, PyPI, registries). It is standalone so Trusted Publishing's OIDC subject binds to its own path. It is deny-by-default, with the `id-token: write` and `environment:` opt-ins seeded as comments.

Two corrections to the issue text (details in [this comment](https://github.com/vig-os/devkit/issues/1746#issuecomment-5869565145)):

- **The issue's cargo-dist recipe does not work.** With `create-release = false`, cargo-dist uploads into the draft and then *undrafts it itself* under `GITHUB_TOKEN`. That bypasses promote, makes the Release immutable before late assets land, and never fires `release: published`. The documented recipe instead uses cargo-dist as an asset builder (`hosting = ["github"]`, no generated CI) plus a consumer tag-push workflow that uploads into the draft.
- **The default is `rc{N}`, not `rc.{N}`.** Only `rc{N}` meets the byte-identical acceptance criterion.

## Changes Made

- `packages/vig-utils/src/vig_utils/release_version.py` (+ `pyproject.toml` script, README): new `release-version` CLI.
  - Validates the format (`{N}`, `{YYYYMMDD}`, SemVer charset, valid pre-release expansion).
  - Discovers the counter per format; `{N}` in a dated format restarts per day.
  - Monotonicity gate: a format's own tags rank by counter (SemVer ranks `rc10` below `rc9`), while other formats compare by SemVer precedence. An existing final `X.Y.Z` only warns, which keeps the forward-fix path after a failed final open.
- `assets/workspace/.github/workflows/release.yml`: new `pre-release-format` dispatch input, threaded with the documented precedence.
- `assets/workspace/.github/workflows/release-core.yml`: new `pre_release_format` input; *Compute publish version* now delegates to `release-version` and lists `<prefix>X.Y.Z` plus `<prefix>X.Y.Z-*`.
- `assets/workspace/.github/actions/resolve-toolchain/action.yml`, `assets/workspace/.vig-os`, `assets/init-workspace.sh`: new `DEVKIT_PRERELEASE_FORMAT` key, resolved into a `prerelease-format` output and persisted across re-scaffolds.
- `assets/workspace/.github/workflows/release-publish.yml`: release notes, then the draft (`--target`, no `--verify-tag`), then the tag ref. New *Discard orphan draft on tag failure* step. It never deletes a published Release, and never deletes a pre-existing draft whose tag exists.
- `assets/workspace/.github/workflows/publish-release-extension.yml`: new seed. `init-workspace.sh` adds it to `PRESERVE_FILES` and to the `release` feature group.
- `docs/DOWNSTREAM_RELEASE.md` (+ scaffold mirror): new sections *Pre-release format*, *Release owner and the pre-publish assets window*, *cargo-dist adopter recipe* and *Publish Extension Hook*. `docs/MIGRATION.md` and `docs/WORKFLOW_SECURITY.md` now list the third seam.
- Tests:
  - `packages/vig-utils/tests/test_release_version.py`
  - `tests/test_release_prerelease_format.py`: executes the real compute step against a stubbed `git` and the real CLI.
  - `tests/test_release_publish_draft_first.py`: executes the publish steps against a stateful `gh`/`git` fake, covering ordering, orphan cleanup and idempotent re-runs.
  - `tests/test_workflow_publish_release_extension.py`: executes the resolve step for both triggers; checks that promote publishes under the App token, and the scaffold ship/preserve/opt-out behaviour.
  - `tests/test_vig_os_manifest.py`

## Changelog Entry

### Added

- **Release train: pluggable pre-release format, draft-Release-first owner
  contract, and a standalone publish seam**
  ([#1746](https://github.com/vig-os/devkit/issues/1746))
  - Candidates can be tagged in any SemVer pre-release format, e.g. `alpha.{N}`
    for `v0.1.0-alpha.1` (`{N}` counter, `{YYYYMMDD}` date). Precedence:
    `release.yml` input `pre-release-format` > `.vig-os`
    `DEVKIT_PRERELEASE_FORMAT` > `rc{N}`, which keeps today's `X.Y.Z-rcN` tags
    byte-identical. A format switch that would sort below an existing tag of
    the same `X.Y.Z` is refused. Computed by the new `release-version`
    vig-utils CLI
  - `release-publish.yml` now creates the draft GitHub Release before the tag
    ref, so tag-triggered asset workflows always find it (the "pre-publish
    assets window"); a failed tag push discards the orphan draft.
    `promote-release.yml` stays the only place a draft is published
  - New preserved, default no-op seam `publish-release-extension.yml` on
    `release: published` (plus a `workflow_dispatch` tag retry) for
    irreversible publishes such as crates.io or PyPI. It is standalone so
    Trusted Publishing binds to its own path
  - `docs/DOWNSTREAM_RELEASE.md` documents the contract and a cargo-dist
    recipe: cargo-dist builds the assets and a tag-push workflow uploads them
    into the train's draft, because `create-release = false` makes cargo-dist
    publish the draft itself

## Additional Notes

- **Behaviour change:** an explicit `rc-number` with a leading zero (e.g. `01`) is now rejected. It used to produce a `-rc01` tag that auto-discovery read back as 1.
- **Existing consumers:** the upgrade seeds the no-op `publish-release-extension.yml`, the `.vig-os` template gains an empty `DEVKIT_PRERELEASE_FORMAT=`, and the draft is now created before the tag. Tags and outputs are unchanged for the default format.
- **Out of scope, filed as follow-ups:** #1747 (git-cliff changelog recipe), #1748 (Rust pack L6 seed templates, including `publish = false` detection) and #1749 (promote's candidate-tag cleanup still prunes only `-rc*`).
- The devkit repo's own `.github/workflows/release.yml` (the upstream train) is untouched. This PR changes only the consumer scaffold.
