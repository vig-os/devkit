# [PR 2081](https://github.com/vig-os/devkit/pull/2081) fix(security): reconcile the 2026-11-18 vulnix exceptions

## Description

Reconciles the seven `.vulnixignore` entries that expire on 2026-11-18 (two blocks: fzf 0.72.0 and the #2052 sqlite 3.53.3 + rsync 3.5.0 batch). From 2026-11-19 they would fail `check-expirations` in every PR, both nightly lanes and the release train. Every entry was re-verified on 2026-11-17, following docs/CONTAINER_SECURITY.md ("a renewal is a re-verification, not a date bump"). No other block is touched (2026-11-25, 2026-12-02 and 2027-06-23 are unchanged). This also resolves the dev-lane notice #2072.

Evidence, checked 2026-11-17:

- **All seven are still live findings.** The dev lane of nightly run 44099322680 (2026-11-17, pin `08d3a975`) still reports them. No other CVSS >= 7.0 finding exists for these packages, and NVD lists no newer HIGH CVE for sqlite 3.53.3, rsync 3.5.0 or fzf 0.72.0.
- **The NVD CPEs match the right product and version.** `sqlite:sqlite` < 3.54.0 (119373/119374/119379) and <= 3.54.1 (119586); `samba:rsync` <= 3.5.1; `junegunn:fzf` < 0.73.1. NVD now gives every range an upper bound, so the open-ended-range concern from the #2052 review no longer applies to rsync.
- **Nothing is fixed at the pin, so nothing is deleted.** The pin `08d3a975` and the open advance #1821 (`f1e5c356`, 2026-11-13) both ship sqlite 3.53.3, rsync 3.5.0 and fzf 0.72.0.

| Entry | Lever, 2026-11-17 | Decision |
|---|---|---|
| rsync CVE-2026-119741 | Fixed on nixos-26.05 head `b349185b`, after the pin. The fix is nixpkgs `190957f1` (rsync 3.5.0 -> 3.5.2, backport NixOS/nixpkgs#584501), which reached release-26.05 with staging-next iteration 10, NixOS/nixpkgs#584522. #1821's rev predates it. | Exit is the next pin advance to a rev at or after `190957f1`. Short expiry **2026-12-02**: two Monday windows, because #1821 is red. Do not renew. |
| sqlite CVE-2026-119373 / -119374 / -119379 | Fixed in upstream 3.54.0. The fix commits are in tag `version-3.54.0` but not in `version-3.53.4`. In nixpkgs, 3.54.0 is staging/unstable only (NixOS/nixpkgs#572495). Every 26.05 branch still ships 3.53.3 with no CVE patches, and no backport PR is open. | Renewed with fresh evidence to **2026-12-09**. |
| sqlite CVE-2026-119586 | **Correction:** the old note said "fixed in 3.54.2". 3.54.2 does not exist; the latest upstream release is 3.54.1. sqlite.org/cves.html says "Not a bug in the core SQLite library" and points to the CLI's `--safe` option. | Re-classed as not-exploitable (it needs a deliberate, unsafe two-step user action). It stays in the sqlite block under the exact `@3.53.3` key, so the version bump re-gates it. |
| fzf CVE-2026-53432 / -53433 | Every 26.05 branch, the pin and #1821 ship 0.72.0. The only backport, NixOS/nixpkgs#572684, was closed unmerged on 2026-10-11. Unstable ships 0.75.0. | Renewed (availability-only on a 64-bit image) to **2026-12-16**. |

Each block now sits on its own Wednesday: glibc 11-25, Brotli + rsync 12-02 (one entry each), sqlite 12-09, fzf 12-16.
