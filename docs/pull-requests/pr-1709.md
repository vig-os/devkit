# [PR 1709](https://github.com/vig-os/devkit/pull/1709) test(bats): isolate worktree.bats and tighten the BATS suite

## Description

Four tests-only issues in one PR. The load-bearing one is #1694: `tests/bats/worktree.bats`
drove `just worktree-clean` against the repository's **live** `<repo>-worktrees` sibling
directory, and that recipe force-removes every entry in it and `git branch -D`s its branch.
On 2026-09-25 a local full-suite run deleted three agent worktrees and their branches
mid-work. The file now drives every recipe against a throwaway `git init` fixture under
`BATS_TEST_TMPDIR`, which also lets it drop its `CI=true` skips and rejoin `bats -j`'s
within-file parallelism. The other three tighten the same suite: a per-file
`bats_require_minimum_version` declaration with a pytest guard (#1697), concurrent fixture
rendering in `init-workspace.bats`'s `setup_file` (#1695), and the settled
`_upgrade` ≡ `_scaffold` equivalence that collapses the last pure-setup renders (#1696).

No product code changes: `justfile.worktree`, its scaffolded mirror and
`assets/init-workspace.sh` are untouched. The only non-test file is
`CHANGELOG.md` (plus its synced mirror), where an **unreleased** #1687 sentence
had to be corrected — see Changelog Entry.

Review fixes are appended as their own commits rather than folded into the
reviewed history.

## Changes Made

**#1694 — worktree.bats no longer touches the live worktrees directory**

- `_wt_assert_throwaway` (committed red-first) asserts the base is non-empty and under
  `$BATS_TEST_TMPDIR` before any recipe runs or any directory is created. 6 of the 10 tests
  were red against the old wiring.
- `_wt_fixture` `git init`s a one-commit throwaway repo at `$BATS_TEST_TMPDIR/fixture`;
  `_wt_just` runs the recipes with `--justfile "$WT_MAIN" --working-directory "$FIX"`.
  `_wt_base` is `../<basename $(git rev-parse --show-toplevel)>-worktrees` resolved against
  just's working directory, so that one flag moves the whole base to `$FIX-worktrees` —
  no product knob, and the `#1463` tests in the same file already used the idiom.
- The five `[ "${CI:-}" = "true" ] && skip` lines go: tmux reaches the CI PATH via
  `setup-env` and `tmux new-session -d` needs no TTY. The `command -v tmux/just/claude`
  skips stay.
- `setup_file`'s `BATS_NO_PARALLELIZE_WITHIN_FILE` (added by #1690) goes too — it was a
  symptom of the shared base, not of the tmux server. Issue numbers carry a
  `$$-$BATS_TEST_NUMBER` tag so derived session names stay unique.
- `/tmp/bats-claude-$$` and a `mktemp -d` move under `BATS_TEST_TMPDIR`, which retires the
  manual `rm -rf` / `rmdir` cleanups.
- `tests/bats/worktree-claude-cli.bats` needs no change: pure recipe-grep, no directories,
  no recipe invocations, no tmux.

**#1697 — `bats_require_minimum_version` in every file**

- New `tests/test_bats_shape.py`: one parametrized case per `tests/bats/*.bats` asserting
  the declaration is the file's first statement, plus a discovery guard so a zero-file glob
  cannot pass silently. Committed red (20 failures) before the fix.
- The declaration is added to the 20 files that lacked it; `githooks.bats` already had it.

**#1695 — concurrent `setup_file` renders**

- The fixture list is declarative (one `<name> <mode> [extra args]` line each), marker
  seeding moves into `_seed_shared`, and all renders are backgrounded and `wait`ed on, with
  **every** failed fixture's log dumped rather than the first.
- Two new fixtures (`cargo-both`, `nix-module-both`) now that a fixture costs ~0 wall time;
  the four `Cargo.toml` / `nix/module.nix` seed-group tests clone them. The two nix tests
  create `$ws` instead of `$ws/nix` — `_clone_shared` refuses a non-empty target.

**#1696 — collapse the pure-setup `_upgrade both` renders**

- The `_upgrade` ≡ `_scaffold` question is settled by evidence (below) and the verdict is
  written into `_clone_shared`'s CONTRACT comment so it is not re-litigated.
- The 5 pure-setup sites clone the `both` fixture: the first run of the `#878` stock test
  (whose subject is the second run) and the four `#886` `--preview` setups. The other 30 of
  the 35 `_upgrade` tests seed a consumer file first or assert on the run itself and keep
  their real invocation.

**Review round**

- The guard pinned `WT_BASE`, which **no recipe reads** — the recipes derive
  `../<basename $(git rev-parse --show-toplevel)>-worktrees` from just's working directory,
  and that is `FIX`. `FIX` is now pinned first (the `WT_BASE` asserts stay, so the two cannot
  drift), and `_wt_fixture` runs the guard **before its `git init`**: that helper
  `git add -A`s and commits inside `FIX`, so it mutates a real checkout before any recipe
  would. `_run_wt_start` — the file's one other real-recipe path, and the one that actually
  `git worktree add`s — runs the same guard against its own sandbox.
- A `teardown()` reaps leaked tmux sessions: only a `wt-` name ending in this test's unique
  `WT_TAG`, or the claude probe's PID-tagged name. An unset `WT_TAG` matches nothing, so
  `wt-*` can never sweep a developer's real sessions.
- Test 1 gave a backgrounded `just` exactly 2 s before a single `has-session`; it now polls
  up to 5 s, so a cold runner is a slow pass rather than a false negative.
- Both asserts in `tests/test_bats_shape.py` name the offending file, the exact line required
  and where it goes.
- `CHANGELOG.md`: the unreleased #1687 sub-bullet is corrected (below).

What this PR does touch is a **correction to an existing, still-unreleased sentence**, not a
new entry. The #1687 bullet under `## Unreleased` claimed the opposite of what is now true:

```md
  - GNU parallel now rides with the bats wrapper in `nix/bats.nix` — … and both entry

    `bats -j "$(nproc)"`. `worktree.bats` first opted out of within-file jobs, because its
    tests drove real tmux sessions against the repository's own sibling worktrees directory;
    it now drives an isolated per-test fixture repo instead, so it runs under `-j` and in CI
    like every other file
    ([#1694](https://github.com/vig-os/devkit/issues/1694))
```

Nothing below `## Unreleased` is touched. `assets/workspace/.devcontainer/CHANGELOG.md` is
the hook-synced mirror, regenerated by `sync-manifest`.

Three of the four issues carry factual corrections, posted separately as issue comments:
