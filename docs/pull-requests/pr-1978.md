# [PR 1978](https://github.com/vig-os/devkit/pull/1978) fix(nix): restore managed Python downloads with uv 0.13

## Description

Fix managed Python downloads with the packaged uv 0.13.4 on the 1.18.1 release branch. The flake constructed a URL using the old `uv-python` crate path; uv 0.13 moved the file to `uv-python-managed`. Both CI setup actions forward the flake value unchanged.

- [x] `test` -- Adding or updating tests

### Modifiers

- [ ] Breaking change (`!`)

## Changes Made

- Select the metadata crate layout by packaged uv version, retaining the version-derived tag for future bumps.
- Evaluate the shipped uv version and dev-shell URL for both Linux architectures without building either toolchain; guard both action forwarding paths.
- Record the fix under 1.18.1 Fixed in both changelogs, as required for this release fix.

Investigation: the assignment is in `flake.nix`, not a nixpkgs setup hook. The override lets FHS CI runners fetch managed CPython for manylinux hooks while local Nix shells pin their interpreter and disable downloads. At tag 0.13.4, `ManagedPythonDownloadList::from_settings` still supports HTTP URLs, local paths and file URLs. The 0.13.0 release notes document interpreter reuse and the new Python 3.15 default; the metadata crate relocation is visible in that tag's source tree. The bad URL is only exercised when managed interpreter acquisition is needed, so an existing compatible interpreter/download can hide it in amd64/dev CI. The candidate's amd64 job was cancelled; it did not prove the URL worked.

Sources: [uv 0.13.0 notes](https://github.com/astral-sh/uv/releases/tag/0.13.0), [0.13.4 metadata](https://github.com/astral-sh/uv/blob/0.13.4/crates/uv-python-managed/download-metadata.json), [override loading](https://github.com/astral-sh/uv/blob/0.13.4/crates/uv-python-managed/src/downloads.rs).
