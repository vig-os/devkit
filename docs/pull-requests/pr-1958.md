# [PR 1958](https://github.com/vig-os/devkit/pull/1958) test(consumer-matrix): gate release N runner migration

## Description

Gate release N runner migration in the consumer matrix: key-only consumers keep selecting their legacy pool and receive the full actionable warning; variables-only consumers resolve every class and project lane correctly without a legacy warning. A local gitflow consumer has `dev` ahead of `main` and adopts N using the real upgrade and PR-body steps from immutable tag `1.18.0`: the key survives, the old body omits migration guidance, and the adoption CI resolver emits that guidance independently.

## Changes Made

- Add `runner-key-only` and `runner-gitflow`; change `ci-runner` to variable inputs with parameterized, generic fixture labels.
- Execute the rendered resolver and assert its class sources, lane outputs, and complete migration warning. Seed the full 1.18.0 scaffold and execute its upgrade and PR-body steps through the unchanged current `install.sh`, each with its own evaluated environment and shell. The ADR’s S8 file list did not include the transport adapter or tag-fetch steps: `install-transport.sh` is needed to execute the actual installer while keeping curl, docker, and gh local and strict; the CI fetch steps make the immutable 1.18.0 source available to Consumer Matrix and Project BATS. The target version comes from the repository’s `.vig-os` release pin. Local download/container/PR adapters replace only external boundaries and reject unknown commands. The container adapter forwards only the installer’s `-e` values into a clean environment.
- Add rendering tests and failure canaries for truncated warnings, incorrect outputs, and an unexpected migration section.
- Document the cells in `docs/RELEASE_CYCLE.md`. CI discovers cells from the script; both Consumer Matrix and Project BATS now fetch the required 1.18.0 tag. Move this tag forward only when the oldest supported pre-N release changes.
- A second adoption with N’s migration environment proves the installer forwards context, strips the inert key, and reconciles stock seeded hooks. Do not depend on unmerged S6/S7b work.
