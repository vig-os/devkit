# [PR 1790](https://github.com/vig-os/devkit/pull/1790) feat: give every Refs-optional commit type an issue-less branch form

## Description

Generalises the hardcoded `chore/<summary>` branch clause: every commit type in the resolved Refs-optional set now also gets an issue-less `<type>/<summary>` branch form. With `DEVKIT_REFS_OPTIONAL_TYPES=chore,docs`, `docs/<summary>` is accepted next to `docs/<issue>-<summary>`, in both the local guard and CI.

There is no new key. The branch set is **derived** from the Refs set, so a branch may skip the issue only where its commits may. Derivation (same in all three renderers):

- `chore` is a **floor**. The sync-main-to-dev and devkit-upgrade bot branches are `chore/<slug>`, so no policy (not even `required`) may drop them.
- Every other resolved Refs-optional type is appended, in order, and the `none` sentinel is dropped.

Default and `DEVKIT_REFS_POLICY=required` resolve to plain `chore`, so the rendered pattern is byte-identical to today's.

## Changes Made

- `assets/init-workspace.sh`: new `render_issueless_branch_types`, unconditional and idempotent (#1640). It uses a generic anchor (`(?!^(`…`)/[a-z0-9]`) that is distinct from `render_branch_types`' `)/[0-9]`. `render_branch_guard_model`'s gitflow re-insert now anchors on the bare `(?!^(` prefix, not on the `(chore)` literal. Before this, a trunk → gitflow switch with a custom set would silently not restore `(?!dev$)`.
- `nix/hooks.nix`: `branchNamePatternFor` takes the issue-less set, and the new `issuelessBranchTypesFor` derives it from `refsOptionalTypesFor`. The `mkProjectShell` wiring is unchanged: `refsOptionalTypes`/`refsPolicy`/`commitTypes` are already forwarded, so there is no template `flake.nix` port.
- `resolve-toolchain`: new `issueless-branch-types` output. `ci.yml` re-exports it, and the branch-name gate uses it in place of the literal `chore` alternative.
- Docs: the `.vig-os` template comments, the MIGRATION key table, COMMIT_MESSAGE_STANDARD, the branch-naming skill and both hook-config comments.
