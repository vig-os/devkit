# [PR 1436](https://github.com/vig-os/devkit/pull/1436) feat(workspace): add scaffold-time commit-types knob (DEVKIT_COMMIT_TYPES)

## Summary

New `.vig-os` key `DEVKIT_COMMIT_TYPES`: a comma-separated full-replacement list of approved commit types, driving **both** enforcement points from one key — the `validate-commit-msg` hook's `--types` arg (anchored scaffold-time render, mirrors `render_refs_policy`) and CI's `validate-commit-range` (new `commit-types` resolve-toolchain output, threaded into the commit-checks lane via env). Empty (default) resolves to the stock 11 types — a default scaffold stays byte-identical, and CI behavior is unchanged (explicit default == tool default; both CLIs already accepted `--types`, so no vig-utils change).

Follows the #1282 blueprint end-to-end. Option B of exo-pet/vault#54 (per-consumer flexibility over org-wide defaults), commit-type half; branch-type twin is #1432.

## Design points

- **Load-bearing charset guard** at the write path (each entry `^[a-z][a-z0-9]*$`, loud abort — the value is spliced into sed replacement text and YAML); CI side fail-safes to the stock list with a `::warning` (a broken value must never weaken the gate).
- **Bot-type notice** (never abort): dropping `chore`/`build` warns that Renovate / devkit-upgrade bot PRs will fail commit-checks.
- **Composition fix**: `DEVKIT_REFS_POLICY=optional` now mirrors the RESOLVED types list in both renderers (previously hardcoded the stock list) — the gate never requires Refs for a type it just accepted.
- Round-trips across `--force` upgrades like the sibling knobs; documented in the MIGRATION.md manifest table + COMMIT_MESSAGE_STANDARD.md (both copies) + template `.vig-os`.
