# [PR 1724](https://github.com/vig-os/devkit/pull/1724) feat(init): bind the commit-App token-minting jobs to an opt-in environment

## Description

The stamped workflows read the commit App credentials (`COMMIT_APP_CLIENT_ID` / `COMMIT_APP_PRIVATE_KEY`) from wherever GitHub resolves the names — in practice org or repo secrets, readable by a workflow job on **any** branch. The commit App typically holds a branch-protection bypass, so any write-access account could push a branch whose workflow mints the token and writes past the default branch's protection. A consumer can close that surface by moving the pair into **environment secrets** behind a deployment branch policy — but only if the token-minting jobs carry `environment: <name>`, and only devkit can put it there durably, since the workflows are regenerated on upgrade.

This adds `DEVKIT_COMMIT_APP_ENVIRONMENT=` to `.vig-os`, default empty. Unset, every workflow renders byte-identically to today. Set, `render_commit_app_environment()` appends `environment: <name>` under exactly the token-minting jobs, following the same post-copy anchored-`sed` pattern as `DEVKIT_SYNC_TARGET`, with the value written back so upgrades keep it.

**Three corrections to the issue as filed, all verified in code:**

- **The job list is 8 stamped jobs, not 3** (plus a 9th in mirror mode): `sync-issues.yml:sync`, `sync-main-to-dev.yml:sync` (gitflow only), `prepare-release.yml:prepare`+`rollback`, `prepare-hotfix.yml:prepare`+`rollback` (gitflow only), `release.yml:rollback`, `release-core.yml:finalize`, and `promote-release.yml:reset-sync-mirror` — the last one is injected by `render_sync_settings` in mirror mode, so no grep over the templates can see it. Left unbound it would be the only job still minting from org/repo secrets and would break at **promote**, after a release is published, the moment a consumer moves the pair. Bound; isolated in its own test+feat commit pair.
- **The branch policy must include `dev` under gitflow**, not only `main` + `release/*`: `prepare-release` / `prepare-hotfix` dispatch from `dev` by default.
- **The reusable callee.** `on.workflow_call` does not accept `environment`, and the `github` context in a reusable workflow is the caller's, so the key goes on `release-core.yml`'s `finalize` job, not on `release.yml`'s `core:` `uses:` job. With the pair living only as environment secrets, the caller's `secrets: inherit` cannot satisfy `required: true`, so the render flips `release-core.yml`'s two `COMMIT_APP_*` declarations to `required: false` (the `RELEASE_APP_*` pair stays required, pinned by a test). **This is the one behaviour that needs the live proof below before merge.**

Also: a bound job on a missing environment auto-creates an unprotected one (create it first), required reviewers would inject a second approval into the single-approval train (none), branch policies match ref *names* (pair with a ruleset restricting who may create `release/*`), and `prepare-release-extension.yml` is preserved — if a consumer's extension mints the token, they add the key themselves.

## Additional Notes

**Do not merge before the live proof.** Two behaviours cannot be verified locally: (a) a job-level `environment` on a `workflow_call` **callee** supplying `COMMIT_APP_*` when the caller's `secrets: inherit` delivers nothing and the declarations are `required: false`; (b) GitHub not rejecting the dispatch for the now-optional secrets. Checklist for `devkit-smoke-test`:

1. Create environment `commit-app` **first**. Deployment branch policy (selected branches): `main`, `release/*`, plus `dev` if smoke-test runs gitflow. No required reviewers, no wait timer.
2. Add `COMMIT_APP_CLIENT_ID` and `COMMIT_APP_PRIVATE_KEY` as **environment** secrets there, then remove (or rename) the org/repo copies — while both exist, `secrets: inherit` satisfies the callee and the run proves nothing.
3. Set `DEVKIT_COMMIT_APP_ENVIRONMENT=commit-app` in its `.vig-os` and run the scaffold/upgrade from this branch; confirm `grep -n -A1 '^  finalize:' .github/workflows/release-core.yml` shows the key and both `COMMIT_APP_*` entries read `required: false`.
4. Dispatch `prepare-release.yml` from `dev` (proves `prepare` reads the pair from a `dev`-admitted environment), then `release.yml` with `release_kind: candidate` from `release/X.Y.Z` — the decisive leg: the callee's `finalize` must mint the token from its own environment.
5. Look for: the `finalize` job header naming the environment (and a Deployments entry for `commit-app` targeting `release/X.Y.Z`); the `Generate commit app token` step succeeding; the date-stamp commit landing on `release/X.Y.Z` as a verified App commit. Failure signatures: `Input required and not supplied: private-key` / empty `client-id` (environment secret not reaching the callee — the design would then need the pair passed explicitly), a 401 `invalid client id`, or `Secret … is required, but not provided while calling` at dispatch (the flip did not take).
6. Negative control: dispatch `sync-issues.yml` from a throwaway branch outside the policy; the bound `sync` job must be unable to read the credentials.

Semver: **minor** (opt-in feature). Existing consumers see no change until they set the key.

### Live probe on devkit-smoke-test: both open questions answered

A throwaway push-triggered caller (`secrets: inherit`) → local `workflow_call` callee whose single job carried `environment: 'commit-app'` and declared `COMMIT_APP_CLIENT_ID` / `COMMIT_APP_PRIVATE_KEY` as `required: false`. The environment held **dummy** values, so the step could name the source without printing anything real; the org secrets with the same names stayed selected for the repo the whole time.

**In-policy branch** (run [36180182307](https://github.com/vig-os/devkit-smoke-test/actions/runs/36180182307), `core / finalize` → success):

```
COMMIT_APP_CLIENT_ID: ENVIRONMENT secret (dummy value matched, length 26)
COMMIT_APP_PRIVATE_KEY: ENVIRONMENT secret (dummy value matched, length 28)
```

So (a) a job-level `environment` on a `workflow_call` callee delivers that environment's secrets under the caller's `secrets: inherit`, and the environment value **takes precedence** over the org secret of the same name; (b) `required: false` declarations are accepted and the dispatch is not rejected.

**Outside-policy branch** (run [36180185111](https://github.com/vig-os/devkit-smoke-test/actions/runs/36180185111), `core / finalize` → failure):

```
Branch "feature/1710-probe-outside" is not allowed to deploy to commit-app due to environment protection rules.
```

The surface #1710 exists to close is closed by the binding.

**Left in place:** environment `commit-app` on devkit-smoke-test with deployment branch policies `main`, `dev`, `release/*` (no reviewers, no wait timer) and **no secrets** — ready for the real move. Probe branches and dummy secrets deleted. Note for anyone repeating this: the branch-name hook only allows `<type>/<issue>-<summary>`, so the probe branch was `feature/1710-probe-callee-env`, and a new workflow cannot be dispatched from a non-default branch — `push` triggers are the way.

The full rehearsal (move the real pair, deselect the org secrets for this repo, set the knob, dispatch a prepare + candidate) remains available but is no longer a merge blocker.
