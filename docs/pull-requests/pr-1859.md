# [PR 1859](https://github.com/vig-os/devkit/pull/1859) fix(ci): make direnv toolchain setup portable on macOS

## Problem and change

The scaffolded `setup-devkit-toolchain` action fails on macOS hosts before it can expose the direnv toolchain: it calls GNU `tac` / `env -0` and uses associative arrays unsupported by Apple's Bash 3.2.

Use POSIX awk to reverse PATH entries, Bash builtins to capture NUL-delimited exported variables, and indexed environment records to compare host and dev-shell values. Multiline and empty values remain intact, unchanged host values stay out of `GITHUB_ENV`, and PATH retains dev-shell priority.

Add Linux and macOS smoke jobs to devkit's own CI. They run the scaffolded action in direnv mode against a minimal consumer using the repository's locked nixpkgs, then verify the installed toolchain, retry helper, and shellHook values in a subsequent step. Both jobs feed the required CI summary.

Reserve `__*`, `NIX_*`, and `MACOSX_*` namespaces, plus `PATH_LOCALE` and the Darwin SDK selectors. A project-variable allow-list would break the action's contract to forward arbitrary consumer shellHook exports, so this change reserves the build/session namespaces instead.

The smoke jobs capture the forwarding step's actual `GITHUB_ENV` using a CI-only BASH_ENV exit hook. On both Linux and macOS, its exact name set must equal `DEVKIT_SMOKE_CHANGED`, `DEVKIT_SMOKE_EMPTY`, `DEVKIT_SMOKE_VALUE`, and `XDG_DATA_DIRS`. Any extra or missing name fails CI. Pattern tests cover actual Darwin leaks and synthetic future internal names; project exports outside those namespaces still forward.

## Validation

- Regression tests committed before implementation reproduce Darwin SDK leaks, lost readonly/integer exports, and exported empty-array crashes.
- 163 targeted environment/profile/CI-summary tests pass locally, including the real dump parser with flag combinations, multiline declaration-like values, and exported empty/populated arrays.
- Empty-array iteration uses Bash 3.2-safe expansions throughout the action.
- Smoke jobs verify the dev-shell profile, nix/just/prek, retry, multiline/empty shellHook values, and unchanged host Darwin SDK settings. They also run the complete environment test module using `/bin/bash`; macOS asserts Bash 3.2 explicitly.
- Locked nixpkgs provides Bash 5.3p9, with neither `bashInteractive_3` nor `bash_3`. The macOS host Bash is the 3.2 gate.
- Commit hooks pass inside `nix develop`.
- Audited other direnv actions/scripts for GNU-only commands and associative arrays: no other matches. Remaining associative arrays in Linux-only release workflows are outside this path.

Fixes #1857
