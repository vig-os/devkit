# [PR 1835](https://github.com/vig-os/devkit/pull/1835) fix(nix): forward the .vig-os hook knobs through mkRustProject

## Description

`lib.mkRustProject` builds its dev shell through `mkProjectShell` but did not accept the four `.vig-os` hook settings. A Rust flake therefore had nowhere to pass `branchTypes` / `commitTypes` / `refsPolicy` / `refsOptionalTypes`. Its `DEVKIT_*` settings were silently ignored by the generated branch guard and commit-message hook, and the manifest bindings the flake reads went unused, which fails deadnix on the first commit touching `flake.nix`.

**Stack 1/6** for #1833 (Rust cold adoption). Base: `dev`.

## Type of Change

- [x] `fix` -- Bug fix
- [x] `test` -- Adding or updating tests

## Changes Made

- `nix/mk-rust-project.nix`: new `branchTypes`, `commitTypes`, `refsPolicy`, `refsOptionalTypes` arguments (default `null`), forwarded verbatim to `mkProjectShell`, which already documents and validates them.
- The usage examples in `nix/mk-rust-project.nix` and `flake.nix` use `inherit (rust) checks packages;` (statix [04]).
- Having the Rust scaffold pass these settings is the remaining half of #1810. It lands with the `#rust` template in #1496 (stack 3/6), because no Rust flake scaffold exists before that PR.

## Changelog Entry

### Fixed
- **`mkRustProject` forwards the `.vig-os` hook settings** ([#1810](https://github.com/vig-os/devkit/issues/1810))
  - `lib.mkRustProject` accepts `branchTypes`, `commitTypes`, `refsPolicy` and `refsOptionalTypes` and passes them to `mkProjectShell`, so a Rust repo's `DEVKIT_BRANCH_TYPES` / `DEVKIT_COMMIT_TYPES` / `DEVKIT_REFS_POLICY` / `DEVKIT_REFS_OPTIONAL_TYPES` reach the flake-generated branch guard and commit-message hook instead of being silently ignored
  - A Rust flake no longer has to drop or `# deadnix: skip` the manifest bindings it reads, which made the first commit touching `flake.nix` fail deadnix
