# [PR 1805](https://github.com/vig-os/devkit/pull/1805) fix(hooks): exclude scaffold-copied CHANGELOG.md from large-file check

## Description

A fresh devcontainer/both-mode consumer's first commit fails `check-added-large-files`: the scaffold copies devkit's own, growing `CHANGELOG.md` to `.devcontainer/CHANGELOG.md`, and that file has crossed the hook's 500 KB default (514,976 bytes at 1.17.0; 528,063 on `dev`).

## Type of Change

- [x] `fix` -- Bug fix

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- `nix/hooks.nix` (the SSoT for the rendered `.pre-commit-config.yaml`): `check-added-large-files` now carries `exclude: ^\.devcontainer/CHANGELOG\.md$` in its one shared `yaml` block.
- This is **not** a scaffold-only override. devkit's own repo has no `.devcontainer/` directory at all, so the identical exclude on the runner's committed `.pre-commit-config.yaml` matches nothing there and is an inert no-op — one render, both committed YAMLs, no new SSoT concept, no weakening of the drift gate's hook-identity check.
- Hand-synced both committed YAMLs (`.pre-commit-config.yaml` and `assets/workspace/.pre-commit-config.yaml`) to match the new render, as there is no generator script — the drift gate (`tests/test_flake_hooks.py`) is what keeps `nix/hooks.nix` and the two committed YAMLs in lockstep.
- **Preserved consumer configs need no fold.** An existing consumer's hand-managed `.pre-commit-config.yaml` is preserved on upgrade (not overwritten), and `.devcontainer/CHANGELOG.md` is already present in its tree by the time this hook would ever see it there (the hook only rejects *added* files, per the issue's own "Additional Context"). Only a brand-new scaffold hits the failure, and a brand-new scaffold always renders the fixed config.
- Kept the diff minimal: did not touch the `no-commit-to-branch` hook (a parallel branch, #1760, is rewriting it in the same files).
