# [PR 1711](https://github.com/vig-os/devkit/pull/1711) fix(nix): run bats --jobs on rush instead of GNU parallel

## Description

The 2026-09-25 nightly vulnix scan went red on `dev` (#1708) with three unexcepted HIGH/CRITICAL findings in **perl 5.42.0** (CVE-2026-4176 9.8, CVE-2026-13221 9.1, CVE-2026-57432 8.4) while `main` scanned green on the same nixpkgs pin. The runtime-closure diff `main` → `dev` is exactly `+ bats-with-libraries`, `+ parallel`, `+ perl`: #1690 (#1687) put GNU `parallel` on the bats wrapper's PATH so `bats --jobs` works, GNU parallel is a perl script, and the wrapper ships in the image env. That silently reversed the perl eviction from #1108, whose CVE exception batch had been retired on the strength of perl being gone.

`nixos-26.05` still carries perl 5.42.0 (5.42.3 is only on `master`/`nixos-unstable`, no backport), so a pin advance cannot clear this. The fix swaps the runner for shenwei356/rush, which `bats-exec-suite` supports natively via `BATS_PARALLEL_BINARY_NAME`; the wrapper sets it, so `bats -j` still needs nothing from the caller. rush is Go: no interpreter, and the image's runtime closure measures 47 MiB smaller. No `.vulnixignore` entry is needed since perl leaves the closure.

A negative image test now pins the eviction on both axes (`command -v perl` fails **and** no `*-perl-*` derivation in `/nix/store`). The PATH half alone was blind — perl was never on PATH while it sat in the closure, which is where vulnix looks — and that blindness is why nothing caught #1690.

### Fixed

    [#1108](https://github.com/vig-os/devkit/issues/1108) had evicted it

    CVE-2026-13221 9.1, CVE-2026-57432 8.4). The nightly vulnix gate on `dev`
    caught it; no release carried it.
  - The runner is now [shenwei356/rush](https://github.com/shenwei356/rush),
    which bats supports natively via `BATS_PARALLEL_BINARY_NAME` (the wrapper

  - A negative image test pins the eviction, which nothing had: no perl on PATH
    **and** no perl derivation anywhere in the image's store. The second half is
    the one that matters — perl was never on PATH even while it sat in the
    closure, which is where the vulnix scan looks.
