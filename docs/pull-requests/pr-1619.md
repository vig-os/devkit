# [PR 1619](https://github.com/vig-os/devkit/pull/1619) fix(security): except the curl 8.21.0 + openssl 3.6.3 advisory batches in the vulnix register

## Description

The nightly scan of 2026-09-12 ([run 34684718095](https://github.com/vig-os/devkit/actions/runs/34684718095)) went red on **both** refs, opening #1614 (main) and #1615 (dev). They are the same incident: `main` and `dev` sit on the same pinned nixpkgs rev (`c25784012c`), and the two lanes' findings artifacts are byte-identical.

The NVD feed picked up the fix-release advisory batches for **curl 8.21.0** (9 CVEs, NVD 7.4–9.8) and **openssl 3.6.3** (8 CVEs, 7 of them >= 7.0) in the 09-11 → 09-12 window. The 16 blocking findings are excepted by this PR; openssl CVE-2026-63074 (5.9) falls under the gate's threshold and needs no entry.

Full diagnosis on #1614/#1615 follows; the register block carries the per-CVE notes.

## A feed event, not a closure change

The 2026-09-11 nightly ([run 34583730623](https://github.com/vig-os/devkit/actions/runs/34583730623)) was **green on the same pin**. The findings diff is 16 added across exactly two packages, 0 removed, and no exception expired (next grid date is 2026-09-30).

## Remediation lever: exists, but has nowhere to land today

All 16 are fixed in **curl 8.22.0** / **openssl 3.6.4**. Propagation state as of 2026-09-14:

| Branch | curl | openssl |
|---|---|---|
| `staging-26.05` | **8.22.0** ([NixOS/nixpkgs#561666](https://github.com/NixOS/nixpkgs/pull/561666)) | **3.6.4** ([NixOS/nixpkgs#557618](https://github.com/NixOS/nixpkgs/pull/557618)) |
| `staging-next-26.05` | **8.22.0** | **3.6.4** |
| `release-26.05` | 8.21.0 | 3.6.3 |
| **`nixos-26.05`** (pinned) | **8.21.0** | **3.6.3** |

Both fixes ride the **open** iteration-7 PR [NixOS/nixpkgs#563094](https://github.com/NixOS/nixpkgs/pull/563094) (`staging-next-26.05` → `release-26.05`), so advancing the pin today changes nothing — the exact rsync situation of #1592/#1593.

## Triage summary (verified online, upstream pages)

- All 16 are real product+version matches — no CPE collisions. curl rates eight of its nine Low (one Medium); openssl rates all seven Low/Moderate. The NVD-vs-upstream severity gap is the widest yet in this register.
- All nine curl defects are client-side (hostile/compromised server required); two are **not compiled in** at all (CVE-2026-82208 needs the wolfSSL backend, CVE-2026-13608 needs `ldapSupport`, both off in nixpkgs).
- The openssl set is CMP/CMS/DTLS/QUIC surface: nothing in the image runs a TLS/DTLS/QUIC server, a CMP client/server, or processes untrusted CMS messages.

## Expiry placement

`2026-09-23` — the early-slot Wednesday the rsync block freed on the staggered grid (#1553), because this block's lever moves soonest: the review lands the Wednesday after the 2026-09-21 weekly pin advance, so the block should die on remediation rather than be renewed.
