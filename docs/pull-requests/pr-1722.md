# [PR 1722](https://github.com/vig-os/devkit/pull/1722) fix(init): classify the preview through the pruned candidate emitter

## Description

#1715 made `COPY_PRUNE_NAMES=(.git .venv)` the single source of truth for the copy step's prunes, consumed by both rsync copies and by `emit_template_candidates` (the `u+w` sweep, the substitution pass, the `+x` sweep). The `--preview` classifier was left out because it needs the source-relative path for destinations that do not exist yet. It kept its own `! -path "*/.git/*" ! -path "*/.venv/*"`, which differs in kind: `-path` skips only a directory's *contents*, while the emitter, like rsync, prunes any entry *named* `.git` or `.venv`. So a file with one of those names, at any depth, was reported as ADDED but never copied.

`dest → rel` is lossless — both sides glue with the same `"$WORKSPACE_DIR/"` — so the preview now consumes the emitter and strips the prefix. That deletes the duplicated walk and gains the `-L` / `-mindepth 1` / basename-prune semantics for free. The emitter moves up next to `COPY_PRUNE_NAMES` (a pure, verbatim move) because the preview block precedes its old definition point. `-type f` stays explicit (the emitter defaults to `-true`). The two `docs/issues|pull-requests` predicates stay, with their comment corrected: they came from #951 to mirror rsync excludes that #1466 later deleted, the template ships neither path, so they are report-only.

The report is byte-identical on the pristine template: `--preview --force` before and after diffed clean (117 ADDED rows, same order) — the prune only removes entries and traversal order is unchanged.
