# [PR 1661](https://github.com/vig-os/devkit/pull/1661) feat(workspace): ship the actionlint hook and its label config to consumers

## Description

Ships the `actionlint` GitHub Actions workflow linter to consumers: the prek hook that runs it, plus the `.github/actionlint.yaml` label config it needs.

`actionlint` has been in the vigOS toolchain since #995 — `nix/devtools.nix`, so it is on `PATH` in the dev-shell, the image and the `vigos.packages` home module — but the hook that runs it was devkit-only. Consumers therefore shipped workflows that **nothing ever linted**: a survey of `vig-os`, `exo-pet`, `MorePET` and `exoma-ch` found no `actionlint` hook, CI step or justfile recipe in any repo. `shellcheck` is the precedent this follows: same toolchain SSoT (`nix/devtools.nix`), same `language: system` form, already shipped to consumers.

The hook needs a companion. `actionlint` rejects any **literal** `runs-on:` label missing from its built-in list, and only an `actionlint.yaml` declaring `self-hosted-runner.labels` can teach it one. The baseline is `ubuntu-26.04` / `ubuntu-26.04-arm`: real hosted runners (PR #1658's build job ran on `Image: ubuntu-26.04` / `20260907.131.1` and passed) that `actionlint` 1.7.12 — the latest upstream release, published 2026-03-30 — predates, so no pin bump recognises them.

Expression forms need no entry: `runs-on: ${{ fromJSON(...) }}`, which is how `DEVKIT_CI_RUNNER` (#1173) reaches `runs-on`, is skipped by `actionlint` entirely (verified directly).

This unblocks #1658, whose 43 `[runner-label]` findings and 7 failing rendered-template bats tests cannot clear without it.

## Changes Made

- **`nix/hooks.nix`** — `scaffold = true` on the `actionlint` hookDef. The two committed `.pre-commit-config.yaml` files are renders of this one definition and are drift-gated by `tests/test_flake_hooks.py`, so this is the only correct place to add the hook; the comment explaining the old devkit-only scoping is rewritten (the "wrong reusable-workflow root" objection applies to linting templates in-place inside devkit, not to a real consumer repo).
- **`assets/workspace/.github/actionlint.yaml`** (new) — the shipped label config, with each baseline label carrying its reason and a delete-when condition inline.
- **`.github/actionlint.yaml`** (new) — devkit's own copy; its workflows are not scaffolded, so it needs one.
- **`assets/workspace/.pre-commit-config.yaml`** — the rendered hook block, bracketed by `# >>> devkit:actionlint` / `# <<<` sentinels. The drift gate compares *parsed YAML*, so comments are invisible to it: the markers give the opt-out an exact excision range while staying in step with `nix/hooks.nix`.
- **`assets/init-workspace.sh`** — `.github/actionlint.yaml` joins `PRESERVE_FILES` (consumer owns their label declarations, same class as `.yamllint`/`.pymarkdown`/`.typos.toml`); new `actionlint` group in `VALID_FEATURES` + `feature_paths()`; new `render_actionlint_optout()` excising the hook block when the group is disabled, wired in after the sibling `.pre-commit-config.yaml` renders.
- **`assets/workspace/.vig-os`, `docs/MIGRATION.md`** — the new group documented in the knob comment and the feature-group list (now nine), plus the preserved-class caveat.
- **`CHANGELOG.md`** (+ synced `.devcontainer` mirror) — `## Unreleased` entry.
- **`tests/bats/init-workspace.bats`** — 7 new tests (see Testing).

Note the banner on the shipped config is not hand-written: `sync_manifest.py` derives managed-vs-preserved from `PRESERVE_FILES`, so adding the path flips it to the "yours to edit; upgrades never overwrite this file" variant automatically.

    halves at once; an existing config is preserved-class and left in place.
  - Existing repos keep their preserved `.pre-commit-config.yaml` untouched: the
    new hook surfaces through the #878 template diff on upgrade, to fold in by
    hand.

## Additional Notes

**Scope history.** The issue began as "hold the `ubuntu-26.04` bump" and was rescoped twice; both turns are recorded on #1660. One claim in an earlier revision — that `DEVKIT_CI_RUNNER` leaves consumers with an unfixable `runner-label` failure — was **false** and is retracted there: those labels reach `runs-on` only through `${{ fromJSON(...) }}`, which actionlint never inspects.

**Dropped from scope** after the config became consumer-owned (recorded on the issue): `DEVKIT_ACTIONLINT_LABELS` and a `DEVKIT_CI_RUNNER` → label derivation. A preserved file is not re-rendered on upgrade, so such a knob would apply only at first scaffold and silently do nothing afterwards; the consumer edits the file directly instead. The alternative that would have justified them — a *managed* file with the #1640 `render_refs_policy` anchored-idempotent-sed pattern — was rejected as contradicting consumer overriding.

**Adoption is new-repos-only.** `.pre-commit-config.yaml` is preserved, so existing consumers do not receive the hook on upgrade; it surfaces through the #878 `print_preserved_template_diff` to fold in by hand. This follows the split #1652's own table documents: that table is for blocks the template retired *because they break*, "never for ordinary drift", and it names the #878 diff as the right tool for "a new hook was added".

**Follow-up:** #1658 (Renovate `ubuntu` v24 → v26) should be rebased once this merges; both gates — `actionlint` over `.github/workflows/` and the 7 rendered-template bats tests — should then clear.
