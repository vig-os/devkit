# [PR 1715](https://github.com/vig-os/devkit/pull/1715) fix(init): walk the template through one pruned candidate emitter

## Description

Two latent bugs in the template-tree walks of `assets/init-workspace.sh`, one fix.

**#1700.** `sweep_scaffold_writable` walked `find -L "$src_dir" -mindepth 1` with no excludes. The image bakes a `.venv` inside `/root/assets/workspace` that the copy step's `rsync --exclude='.git' --exclude='.venv'` never ships, so the sweep walked hundreds of baked venv paths and, wherever a consumer's own `.venv` had a file at the same relative path, `chmod u+w`'d a consumer file. Harmless in practice, but the same blind spot #1693 closed for placeholder substitution: a template-derived walk that does not apply the copy step's excludes reaches files devkit did not ship.

**#1703.** Three walks derived a workspace path with `rel="${src_path#"$src_dir"/}"`. With a trailing slash on `TEMPLATE_DIR`, GNU `find` prints `/…/workspace/a.txt`, the prefix `/…/workspace//` never strips, the destination never exists, and the walk silently does nothing — exit 0, no warning. Reproduced: with `TEMPLATE_DIR=".../tmpl/"` a read-only preserved `README.md` stayed `444` (control: `644`), a shipped `pkg/lib.sh` stayed `644` (control: `755`), and `--preview --force` printed "118 file(s) will be ADDED" as absolute-path garbage where the control printed "98 file(s) will be OVERWRITTEN".

**The design correction from triage.** "Derive the excludes from `EXCLUDE_ARGS`" does not work: `.git`/`.venv` are literal rsync flags and never in `EXCLUDE_ARGS`; `EXCLUDE_ARGS` is built after the `--preview` walk and is unset in the smoke branch; and feeding the preserved-file/mode excludes into the chmod sweep would stop preserved consumer files getting `u+w`. The single source of truth is `COPY_PRUNE_NAMES=(.git .venv)`, consumed by both rsync calls (via a derived `COPY_PRUNE_EXCLUDES`) and by one shared emitter:

```bash
emit_template_candidates <src_dir> [find-predicates...]   # NUL-delimited WORKSPACE destination paths
```

It normalises `${1%/}`, prunes `COPY_PRUNE_NAMES` by basename at any depth under `-L`, and is consumed by `sweep_scaffold_writable` (no type predicate — directories keep getting `u+w`), `emit_substitution_candidates` (`-type f`, #1693's routine) and the `+x` sweep (`-type f -name '*.sh'`). The `--preview` classifier walk stays separate (it needs `rel` for absent destinations and carries extra `docs/issues|pull-requests` excludes); it and every other reader are fixed by one line after the only assignment: `TEMPLATE_DIR="${TEMPLATE_DIR%/}"`.

## Changes Made

`assets/init-workspace.sh`

- `TEMPLATE_DIR="${TEMPLATE_DIR%/}"` right after the default assignment
- `COPY_PRUNE_NAMES=(.git .venv)` + derived `COPY_PRUNE_EXCLUDES`; both rsync copies (smoke and normal) use it instead of literal `--exclude` flags; the smoke `--exclude='/CHANGELOG.md'` is unchanged
- The smoke overlay rsync derives the same excludes, so the overlay's walks and its copy agree (review finding)
- `emit_template_candidates()` added before its first consumer; `sweep_scaffold_writable`, `emit_substitution_candidates` and the `+x` sweep now read destinations from it (NUL-delimited end to end); their own `-e && ! -L` / `-f && ! -L` / `-f` filters and the batched `xargs chmod` are untouched
- Comments that quoted the literal excludes now point at `COPY_PRUNE_NAMES`

`tests/bats/upgrade-atomicity.bats`

- RED for #1700: template `.venv/lib/pyvenv.cfg` and nested `pkg/.venv/x` with `0444` workspace twins must stay `0444` (failed on `dev` with `expected 444 / actual 644`)

`tests/bats/init-workspace.bats`

- RED for #1703, next to the #1693 trailing-slash test: with a trailing slash, a read-only preserved file is swept writable, a shipped `*.sh` is `+x`, and `--preview` reports OVERWRITTEN/ADDED correctly (failed on `dev` at the first assertion)
