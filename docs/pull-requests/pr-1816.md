# [PR 1816](https://github.com/vig-os/devkit/pull/1816) fix(test): skip .git in placeholder scans to dodge background repack

## Description

Fixes the intermittent `FileNotFoundError` on a `.git/objects/` path in the placeholder-scan integration tests. Seen on PR #1812, run 37247340361.

Root cause (full RCA in [#1815 comment](https://github.com/vig-os/devkit/issues/1815#issuecomment-5989587520)):
- The `install.sh` scaffold commit spawns a detached `git maintenance run --auto`.
- Under the git ≥2.54 default `geometric` strategy, that job sometimes repacks and deletes every loose object ~200–400 ms after the commit, depending on content.
- That window overlaps the first tests of the class, whose lazy `rglob("*")` walks into `.git/objects/`.

## Changes Made

- `tests/conftest.py`: new `scaffold_files(root, excluded_dirs=())` returns a sorted list of the workspace's regular files and skips `.git/`. Git internals never hold a placeholder, and the materialized list means no caller iterates a live walk.
- `tests/test_install_script.py`: `test_install_replaces_placeholder` now uses the helper. `test_install_replaces_org_name_placeholder` is deleted; it duplicated the parametrized `{{ORG_NAME}}` case, and it was the test that failed.
- `tests/test_integration.py`: `test_placeholders_replaced` now uses the helper (keeping its `.pre-commit-cache` / `.ruff_cache` exclusions). Its workspace also gets commits, so it was exposed to the same race.
- `tests/test_scaffold_files.py`: unit tests for the helper. They run in Project Tests, so the guard does not depend on the image-backed jobs.
- `install.sh` is unchanged. The background repack is correct for real consumer repos.
