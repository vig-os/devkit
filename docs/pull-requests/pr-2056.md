# [PR 2056](https://github.com/vig-os/devkit/pull/2056) fix(ci): record checkout SHA from the checkout action output

## Description

#2031 added a `Record checkout SHA` step (`CHECKOUT_SHA=$(git rev-parse HEAD)`) right after `actions/checkout` and before `Set up devkit toolchain`. In a `container:` job, git refuses the workspace as "dubious ownership" (exit 128) until `setup-devkit-toolchain` marks it a `safe.directory`. That broke the 1.19.0-rc4 smoke test (Prepare Release run 42151390302). This PR takes the SHA from `actions/checkout`'s documented `commit` output, so no git call is needed. Release blocker for 1.19.0 (#2033).

## Changes Made

- **15 captures that directly follow `actions/checkout`** (devkit `.github/workflows`: prepare-release ×2, prepare-release-extension, prepare-hotfix, release, abandon-release, sync-issues, update-nixpkgs, update-nixpkgs-unstable; consumer `assets/workspace/.github/workflows`: prepare-release ×2, prepare-hotfix, release-core, abandon-release, sync-issues):
  - The checkout step gets `id: checkout`.
  - The capture reads `CHECKOUT_SHA: ${{ steps.checkout.outputs.commit }}` through `env:`. Nothing is interpolated into `run:`.
  - It fails closed (`::error::`, exit 1) when the output is empty.
  - The step id `checkout-state`, the output `sha`, every `BASE_SHA` consumer and the `Require pinned commit base` guards are unchanged.
  - `actions/checkout@3d3c42e5` (v7.0.1) declares `outputs.commit` in its `action.yml`. `src/git-source-provider.ts` sets it from `git log -1 --format=%H` after checkout.
- **3 captures left on `git rev-parse` on purpose**: the extension's dev fallback (`dev-checkout-state`) and sync-main-to-dev in both trees.
  - Each follows a later manual `git checkout` step, so HEAD is no longer the commit `actions/checkout` reported, and that output would be the wrong base.
  - They run after the toolchain/safe-directory setup. The new ordering scan proves this for the container job.
- **New guard `tests/test_workflow_checkout_sha.py`** scans every workflow in both trees:
  - In every job with a `container:` key, no `run:` step may invoke git before the step that sets `safe.directory`. That step is `./.github/actions/setup-devkit-toolchain`, whose "Configure in-container toolchain env" step runs `git config --global --add safe.directory "$GITHUB_WORKSPACE"`; the test asserts that line exists.
  - Every `Record checkout SHA` after `actions/checkout` must read that step's `commit` output, use no git and fail closed when it is empty.
  - Anything else must follow a manual git checkout.
  - It checks that the scan is not vacuous: at least 20 container jobs and exactly 18 captures.
- **#2031/#2028 replay tests** (`test_commit_action_base_sha.py`, `test_abandon_release.py`) now seed the checkout `commit` output. The fail-closed tests check that an empty output stops the job with exit 1 (git-based captures still surface git's exit code).
- `docs/RELEASE_CYCLE.md` documents the capture rule and the reason for the exception.
