# [PR 2053](https://github.com/vig-os/devkit/pull/2053) fix(security): accept sqlite 3.53.3 and rsync 3.5.0 CVEs pending nixpkgs

## Description

Unblocks the 1.19.0 release train. The `release.yml` Vulnix CVE Gate failed for 1.19.0-rc4 (run 42140837792) on five HIGH findings published 2026-10-30 and 2026-11-03: four in sqlite 3.53.3 and one in rsync 3.5.0. Upstream has fixed all five (sqlite 3.54.0/3.54.2, rsync 3.5.2), but nixpkgs has not: the pinned rev, `nixos-26.05` and `nixpkgs-unstable` all still ship the vulnerable versions with no CVE patches (checked 2026-11-06). The pin advance cannot clear them yet, so this PR adds time-boxed `awaiting-upstream` exceptions.

## Changes Made

- `.vulnixignore`: a new block under `Expiration: 2026-11-18`, a Wednesday on the expiry grid. The window includes two Monday pin advances and their nightly deltas. It has five exact-scope entries:
  - `CVE-2026-119373@sqlite@3.53.3`, `CVE-2026-119374@sqlite@3.53.3`, `CVE-2026-119379@sqlite@3.53.3` (FTS5 and session extension, fixed in 3.54.0)
  - `CVE-2026-119586@sqlite@3.53.3` (CLI `.recover`, fixed in 3.54.2)
  - `CVE-2026-119741@rsync@3.5.0` (delta-transfer sender DoS, fixed in 3.5.2)
- Each entry has a risk note: the GHSA id, the fixed upstream version and the reachability.
  - sqlite: CVSS 7.8 AV:L/UI:R. Exploiting it needs the user to open a crafted database or changeset locally.
  - rsync: availability only. The advisory's attack is unauthenticated clients pulling from a public rsync daemon, and the image never runs one.
- How the no-daemon claim was verified, from `flake.nix`: the OCI config's `Cmd` is bash and it declares no `ExposedPorts`. `flake.nix`, `nix/` and `assets/` contain no `rsyncd.conf` and no `rsync --daemon`. rsync is in `imageTools`/`devtools.nix` only as the CLI the scaffold copies with. The note also records the one remaining path: a user pushing to a hostile receiver can stall their own rsync process.
- The new block shares 2026-11-18 with the two-entry fzf block (7 entries in total). That is not the single-Wednesday cliff the stagger rule guards against.
- `.trivyignore` needs no change: the Trivy scans in the same run passed, and Trivy does not report Nix-store packages. No test pins the register's entries.
