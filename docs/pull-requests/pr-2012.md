# [PR 2012](https://github.com/vig-os/devkit/pull/2012) fix(docs): harden Typst guard reconciliation

## Description

Address all seven follow-ups from the Typst docs guard review. Document recipes now load through a `devkit-docs` module so consumer `typst`, `typst-canonical`, and `typst-probe` recipes coexist with `just devkit-docs::typst` commands.

## Type of Change

- [x] `fix` -- Bug fix

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- Migrate the former flat docs import to `mod devkit-docs 'justfile.devkit-docs'`, supported by the pinned just 1.51.0 toolchain.
- Skip the module with one recovery notice on any consumer recipe, alias, or module named `devkit-docs` in justfile, justfile.project, or justfile.local. Consumer `docs` declarations coexist.
- Exercise remote-only four-space, three-space, and mixed-step YAML layouts, plus exact-byte rendering for indentless and wide-dash layouts.
- Trigger docs-OFF reconciliation only on devkit markers or recorded state; preserve consumer generated exclusions and YAML anchors without warnings.
- Qualify the docs-module glossary command as `just devkit-docs::glossary-candidates`.
- Limit the yamllint guarantee to previously clean configurations.
- Report stale docs hook removal without the recipe file and retain consumer-owned recipe files in preview.
- Give missing-exclusion recovery advice and detect generated exclusions after deletion of the local repository containing docs state.
- Restore original config bytes after an interrupted in-place write, including KeyboardInterrupt.

## Additional Notes

Consumers must use the documented `devkit-docs::` recipe names. Without the deleted block's recovery records, generated exclusions cannot safely be reversed: reconciliation retains the config and asks for restoration. With docs enabled, identical consumer-owned exclusions cannot be distinguished and require manual removal before retrying. With docs OFF and no managed markers/state, these configs stay untouched without warnings. In-place rollback preserves the inode; a second interrupt or I/O failure during rollback can prevent restoration, as documented. Existing configs with yamllint findings may acquire additional findings, as documented.
