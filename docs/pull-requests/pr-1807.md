## Description

**Part 2 of 2 for #1762.** This PR is stacked on #1803 (part 1) and targets `feature/1762-consumer-matrix`. **It will be retargeted to `dev` once #1803 merges.**

It adds language cells and a flake-evaluation cell to the `Consumer Matrix` job from part 1.

**Expected reds:** only the #1800/#1801 cells, as on #1803, until those fixes land on `dev`.

**`rust` is a strict expected-fail on #1496.** A scaffolded Rust consumer gets the stock Python `justfile.project`, so `just test` exits 0 without compiling anything. The cell still runs every gate, and is accepted only when:
- `test` is its sole failed gate, and
- that gate failed with the silent-no-op signal ("`just test` exited 0 but the rust fixture suite never ran").

If the cell passes, it fails ("rust now passes — remove the #1496 expected-fail marker"). If it fails in any other way, it fails. The marker is one entry, `EXPECTED_FAIL[rust]="test #1496"`, next to the cell list, and the summary shows `expected-fail (#1496)`. #1496 now has a comment saying this cell is its acceptance test and that its fix must remove the marker.

CI run: https://github.com/vig-os/devkit/actions/runs/36880846330. The only failing cells are `devcontainer`, `trunk`, `ci-runner`, `tag-prefix`, `language-guard` and `features-disabled` (#1801 `exceeds 500 KB`, plus #1800 `too many blank lines` on `features-disabled`). `rust` is `expected-fail (#1496)`. `direnv`, `bare`, `python`, `node` and `direnv-flake` pass. Every other job is green. An earlier run, https://github.com/vig-os/devkit/actions/runs/36878543444, gave the same verdicts.

## Changes Made

- **Fixtures** in `tests/fixtures/consumer/{python,node,rust}/`: a zero-dependency hello world plus one test each. Python uses pytest from a `dev` dependency group. Node uses `node --test` and ships a dependency-free `package-lock.json` so `npm ci` works. Rust uses a `#[test]` in `src/lib.rs`. Each test writes `$CONSUMER_MATRIX_SENTINEL` when it is set.
- **Language cells** `python`, `node`, `rust`:
  - The fixture is copied in as the marker files, then rendered in `bare` mode with `--force`. That is the adoption path for an existing project: no `.vig-os` yet, so nothing is upgraded, and without `--force` init-workspace.sh refuses a non-empty directory. `bare` ships the scaffolded hook config with no mode-specific files, so the result reflects the language and not the mode.
  - New gates `sync` (`just sync`) and `test` (`just test`), as the consumer's CI runs them. These apply to every cell.
  - A fixture cell's `test` gate fails if the sentinel was not written. `seed` also checks that the scaffold detected the language into `DEVKIT_LANGUAGES`.
- **`direnv-flake` cell:**
  - `nix flake check` on the rendered flake with `--override-input vigos "path:$ROOT"` (same approach as test-project's "Check downstream flake stub") and `--no-write-lock-file`.
  - It then builds the dev shell into a profile, and every later gate runs inside it. The shell hook installs the flake-generated `.pre-commit-config.yaml`, so `first-commit` and `precommit` exercise the direnv hooks for the first time. The plain `direnv` cell still skips them.
- **Toolchains:**
  - uv and npm come from the devkit dev shell.
  - Python is fetched by uv, the same way setup-env provides it.
  - nix comes from setup-env.
  - cargo is not in the devkit dev shell, and the rendered Rust recipe never calls it (#1496). Stubbing cargo would hide the defect.
- `pyproject.toml`: added `fixtures` to `norecursedirs` so devkit's own pytest does not collect the fixture suite.

### CI timing

Each cell's summary now lists the time of every gate, because the cells run concurrently and their logs are printed afterwards.

| | part 1 (#1803, 8 cells) | this PR (12 cells) |
| --- | --- | --- |
| setup-env | 44 s | 35 s |
| cells step | 130 s | 176 s |
| Consumer Matrix job | 182 s | 219 s |
| slowest other lane | 267 s (BATS) | 284 s (Flake Gates) |
| run wall clock | 5m39s | 5m14s |

The job still finishes about 65 s before the slowest lane, so **the critical path does not change**, and the flake cell stays in the same job (no separate job is needed). Per-cell times under 12-way concurrency on the 4-vCPU runner: `direnv-flake` 163 s, the both-mode cells 163–176 s, `python`/`node`/`rust` 67–70 s, `bare` 65 s, `direnv` 5 s. The flake cell is not the outlier: the `nix flake check` and dev-shell build reuse the closure setup-env already pulled. Locally, with a warm store and no contention, it takes 22 s.
