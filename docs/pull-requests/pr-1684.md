# [PR 1684](https://github.com/vig-os/devkit/pull/1684) fix(ci): source the retry helper in the release-neutral opener

## Description

The release-neutral lane's **first live dispatch failed**. Run [36054453452](https://github.com/vig-os/devkit/actions/runs/36054453452), at `gh pr create`:

```
/home/runner/work/_temp/....sh: line 40: retry: command not found
##[error]Process completed with exit code 127.
```

`retry` is a bash **function** exported through `BASH_ENV` by the `setup-env` composite action. The opener's job deliberately skips `setup-env` — `gh` is preinstalled and opening a PR needs no toolchain — so the function was never in scope.

`prepare-hotfix.yml`'s PR job had already solved this, and its comment even says so (*"the retry helper is sourced from the checkout"*). I copied its `retry … -- gh pr create` call without the `source` line that makes it work.

## Type of Change

- [x] `fix` -- Bug fix

## Changes Made

Sources `.github/scripts/retry.sh` from the checkout before the `retry` call, with the same `# shellcheck source=/dev/null` directive `prepare-hotfix.yml` uses, and a comment explaining why this job cannot rely on `BASH_ENV`.

The test walks every step of the opener job and requires any that calls `retry` to source the helper, so the coupling is pinned rather than remembered.

**Why no existing test caught it:** all 28 shape assertions pass what a step says about *itself*, and the step said `retry` quite correctly — it was the *environment* that lacked it. Only running the workflow surfaces this class of defect. That is now twice in this bootstrap: the first was gate 3 refusing the changelog mirror that gates 1 and 2 were widened to admit.
