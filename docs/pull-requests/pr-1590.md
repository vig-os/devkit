# [PR 1590](https://github.com/vig-os/devkit/pull/1590) feat(ci): evaluate homeManagerModules against home-manager master + nixos-unstable

## Summary

Adds the eval-only CI leg from #1589: the exported `vigos.*` home modules are now release-gated against **home-manager `master` + `nixos-unstable`**, the branch pair a production consumer runs, alongside the existing stable coverage.

## What changed

- **New flake input `home-manager-unstable`** (home-manager `master`, `follows nixpkgs-unstable`). One leaf lock node; fetched only when the guard is evaluated. One correction to the issue text: a new input *is* needed — devkit's `home-manager` input is pinned to `release-26.05`, so master has no existing source.
- **`nixosConfigurations.ci-hm-unstable`** — a throwaway eval-only NixOS system on `nixpkgs-unstable` wiring the full module set (the existing `hmProfiles.full`, so it stays in lockstep with the stable matrix) through the NixOS-module tier (`home-manager.users.<name>`), matching how the server consumer wires it. Carries the `vig-utils` overlay + `allowUnfree`, the same combination `mkHomePkgs` gives the stable matrix; the fast-mover overlay is deliberately absent (the base *is* the fast branch). Never built.
- **Blocking gate:** `test_hm_unstable_nixos_tier_evaluates` in `tests/test_flake_checks.py` forces the configuration's toplevel drvPath and asserts the full `vigos.*` surface is enabled. That file runs in the required Tier-0 job, so the leg is blocking with no workflow changes.
- **Freshness:** the weekly `update-nixpkgs-unstable` cron now bumps `home-manager-unstable` alongside `nixpkgs-unstable` — a master-side break surfaces as red CI on that bump PR, inside devkit's release gate, before any consumer lock bump. Without this the guard would test a frozen master snapshot.

- `prek run --all-files` green.
