# [PR 1632](https://github.com/vig-os/devkit/pull/1632) feat: port the hotfix release lane to the workspace scaffold

## Description

Phase 2 of #1621: ports the hotfix release lane (#1623) to the workspace scaffold so gitflow consumers get `prepare-hotfix.yml` and `just prepare-hotfix X.Y.Z` before they need it — `workflow_dispatch` only works once the file is on the consumer's default branch, so the lane cannot be adopted and used in the same emergency.

The scaffold copy is written in the scaffold dialect: every job runs on the mode-aware devkit toolchain (`resolve-toolchain` + `setup-devkit-toolchain`, no `uv run`), the latest-tag lookup and the collision check honour `DEVKIT_TAG_PREFIX`, every checkout sets `persist-credentials: false`, and `prepare-release-extension.yml` stays the only project-specific seam. The lane is gitflow-only: copy-excluded under `DEVKIT_WORKFLOW=trunk` and pruned on a gitflow → trunk upgrade, the same mechanism as `sync-main-to-dev.yml` — the two now share one `TRUNK_EXCLUDED_WORKFLOWS` list in `init-workspace.sh` instead of a sixth special case.

The scaffold `release-core.yml` validate job switched from grepping for the bare `## [X.Y.Z] - TBD` heading to `prepare-changelog validate --version`, so a seeded-but-unfilled hotfix section cannot ship downstream (the `--version` flag ships in the same devkit release, so the toolchain contract holds).

Stacked on #1631 (#1626), which is stacked on #1630 (#1627): all three rewrite the same hotfix runbook paragraphs and workflow validate jobs. Once #1631 merges, this branch gets rebased onto `dev` so the diff shrinks to the commits listed below.

## Changes Made

- `assets/workspace/.github/workflows/prepare-hotfix.yml` (new) — the scaffold lane: `resolve-toolchain` → `validate` (patch increment of the latest `main` tag, single-train refusal, empty-Unreleased refusal via `prepare-changelog`) → `prepare` (cut from `main`, seed the `## [X.Y.Z] - TBD` section) → `extension` hook → `open-pr` (draft, targets `main`) → `rollback` (deletes only the release branch). `dry_run` gates every job but `validate`.
- `zizmor.yml` (root + scaffold) — baseline the managed basename for `github-app`, `secrets-inherit` and `unpinned-images`; `artipacked` not needed.
- `assets/workspace/.github/renovate-default.json` — the new managed basename joins the trailing `enabled: false` rule (drift gate `test_renovate_preset_managed_exclusion`).
- `assets/init-workspace.sh` — `TRUNK_EXCLUDED_WORKFLOWS` list + `trunk_excluded()` replacing the five `sync-main-to-dev.yml` special cases (preview classifier, upgrade deletions, rsync exclude, post-copy prune, preserved-class carve-out); the hotfix lane joins the `release` feature group; the `prepare-hotfix` recipe is stripped from `justfile.gh` under trunk only.
- `scripts/manifest.toml` — drop the `RemoveBlock` that stripped `just prepare-hotfix` from the scaffolded `justfile.gh`; `assets/workspace/.devcontainer/justfile.gh` regenerated.
- `assets/workspace/.github/workflows/release-core.yml` — **Verify CHANGELOG has TBD entry** now runs `prepare-changelog validate --version "$VERSION"`.
- Tests — `tests/test_workflow_prepare_hotfix.py` parametrised over both copies plus scaffold-only pins (toolchain, tag-prefix awareness, `release-core.yml` content gate, recipe present); `tests/test_workflow_model.py` pins gitflow-has / trunk-lacks and the upgrade prune; `tests/test_workflow_zizmor_baseline.py` covers the baseline entries; `tests/test_workflow_prepare_extension.py` adds the scaffold lane to the callers.
- Docs — `docs/DOWNSTREAM_RELEASE.md` (+ mirror) hotfix-lane runbook and trunk carve-out, `docs/MIGRATION.md` workflow lists and `release` group, `docs/RELEASE_CYCLE.md` consumer-scaffold paragraph; `CHANGELOG.md` (+ mirror), including dropping the "devkit-only for now" note from the #1623 entry.
