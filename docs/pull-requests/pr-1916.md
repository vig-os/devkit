# [PR 1916](https://github.com/vig-os/devkit/pull/1916) fix(ci): extend runner host Nix configuration

## Description

Preserve a self-hosted runner's valid ambient `NIX_CONFIG` when configuring preinstalled host Nix in direnv mode. Runner caches, keys, experimental features and CPU limits survive into subsequent steps. Reject malformed configuration with a warning that never includes diagnostic values or access tokens. Register masks for accepted ambient access tokens and potentially credential-bearing URL values before exporting them, so later step environment headers cannot expose them.

## Changes Made

- Register one `add-mask` for every token on every ambient `access-tokens` line before the first `GITHUB_ENV` write; escape workflow-command data. Mask URL values with userinfo or query parameters as well. The Nix settings reference identifies `netrc-file` and `secret-key-files` as paths, so their file contents are never exported.

- Probe command support without ambient `NIX_CONFIG`: use `nix config show` when available, otherwise `nix show-config` (including Nix 2.18). If neither command works, fail explicitly rather than label the ambient value malformed.
- Validate with the selected command, preserving accepted ambient config ahead of devkit's lines. Rejected config produces a generic warning with diagnostic values redacted. Select a heredoc delimiter absent from the value.
- Enumerated settings: `extra-experimental-features`, `extra-substituters`, and `extra-trusted-public-keys` add to runner lists. `accept-flake-config = true` deliberately remains owned by devkit: the toolchain must accept the consumer repository flake's cache configuration. Devkit writes no CPU limits or replacement cache lists.
- Share expected values in the tests with explicit install/host feature keys, and compare whole URL sets. Document behavior in the self-hosted migration section. There is no devkit-owned `.github/actions/setup-devkit-toolchain` copy to update.

## Changelog Entry

### Fixed

- **Preserve runner Nix configuration in the toolchain action** ([#1907](https://github.com/vig-os/devkit/issues/1907))
  - With preinstalled host Nix in direnv mode, preserve valid ambient `NIX_CONFIG`, including runner caches and CPU limits, and add devkit's features and cache settings; `extra-experimental-features` extends the host `nix.conf` feature list instead of replacing it
  - Mask ambient access tokens and URL values containing userinfo or queries before export so later step environment headers do not expose credentials
  - Validate with the command supported by host Nix (including `show-config` before Nix 2.20); fail explicitly if neither command is available. Drop malformed ambient configuration with a warning that redacts diagnostic values; keep the exported configuration valid and the environment delimiter collision-safe
