# [PR 1713](https://github.com/vig-os/devkit/pull/1713) fix(ci): rewrite the guard verdict on gate failure or unlabel

## Description

Gate 6 of `release-neutral-guard.yml` — the sticky verdict comment (#1698) — ran under a bare `if: env.ACTIVE == 'true'`, whose implicit `success()` skipped it after any gate failure and on the `unlabeled` event. The last *positive* verdict then stood as the PR's single, permanent verdict: a reviewer read "This change is release-neutral" after a gate-2 refusal, or after the label had been pulled. The guard is not a required check on `main`, so nothing else contradicted it.

The issue's proposed `if: always() && (env.ACTIVE == 'true' || env.LABELLED == 'true')` cannot fire on the unlabel it targets: on an `unlabeled` payload the label is already gone from `pull_request.labels`, so `ACTIVE` and `LABELLED` are both false. This adds a third discriminator, `DEACTIVATED`, read from `github.event.label`, and runs gate 6 on `!cancelled()` (never `always()`: a run cancelled by a superseding head reached no conclusion and must not overwrite the comment).

Gate 6 now writes one of three bodies:

- **verdict** — unchanged wording, still the only branch that reads the worktree;
- **refusal** — names the first failing step in run order and says whether it was a gate refusal or an infrastructure failure (checkout / toolchain set-up, which leave the gates `skipped` — and `skipped` is not `failure`);
- **inactive** — "label removed at `<head sha>`, any verdict that stood here is withdrawn", PATCH-or-nothing, so a PR labelled and unlabelled without being judged gets no comment.

Both non-green bodies are tree-free by design: a deactivated run never checked anything out, and a failed gate 2 or vulnix extra leaves the worktree parked on the base ref because the `git checkout -q -` restore comes after the failing command. The marker lookup, PATCH-before-create order and prune-all-but-newest convergence from #1698 are unchanged.

  ([#1705](https://github.com/vig-os/devkit/issues/1705))

    event. Since the verdict became a single sticky comment, the last *positive*
    verdict then stood as the pull request's only — and permanent — verdict: a

    the unchanged verdict, a refusal naming the first failing step and saying
