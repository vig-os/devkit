# [PR 1729](https://github.com/vig-os/devkit/pull/1729) fix(init): match devkit sentinel ids exactly

## Description

`hook_block_range` located a hook's `# >>> devkit:<id>` / `# <<< devkit:<id>` sentinels with an awk `index()` prefix match, so a sentinel whose id extends another id answered the shorter id's lookup: a consumer-bracketed `# >>> devkit:shellcheck-composite-actions` block was returned for a lookup of `shellcheck`. Found in the #1725 review; nothing in the template trips it today, but it is exactly what the #1725 fallback anchor (which walks predecessors such as `shellcheck`) and the feature excisions would silently mis-target the day someone sentinel-wraps a hook whose id is a prefix extension of another.

The sentinel branch now regex-matches only the marker's whole-line shape, extracts the token after `devkit:` up to the first whitespace, and compares it to the requested id **as a string** — the id is never interpolated into a regex, so a metacharacter in a hook id cannot change what matches. The template's opening sentinels carry trailing prose (`# >>> devkit:actionlint — excised when …`), which is why the token stops at whitespace rather than requiring end-of-line.

Same hazard, same fix, in the two feature excisions: `render_actionlint_optout` and `render_release_optout` used unanchored `grep`/`sed` ranges on `# >>> devkit:actionlint` / `# >>> devkit:release`, so `…:actionlint-extra` or `…:release-notes` pairs would have been deleted too. Both are now anchored at line start and require whitespace or end-of-line after the id (`-E` alternation, again because of the trailing prose). The structural branch's sweep stops are left id-agnostic on purpose: any sentinel must stop the comment sweep.

## Changes Made

`assets/init-workspace.sh`

- `hook_block_range`: `sentinel(line, dir)` awk function (whole-line marker shape, token extracted, string equality against `"# " dir " devkit:" id`); docstring updated — the prefix hazard is gone, the feature-gating reason for keeping ungrouped hooks un-sentinelled stays
- `render_actionlint_optout`, `render_release_optout`: `grep -qE '^[[:space:]]*# >>> devkit:<id>([[:space:]]|$)'` guard and the matching `sed -i -E` range

`tests/test_scaffold_preserved_hooks.py`

- `_shell_function(name)` harness lifting one function's verbatim text out of the script into a `bash -c` run (the script is not sourceable)
- Five tests, four RED before the fix: a prefix-extended sentinel does not answer the shorter lookup (direct `hook_block_range`); the extending id still resolves to its own sentinel range; the anchor walk ignores a prefix-extended sentinel (upgrade-driven, pin 1.15.1 ⇒ actionlint lands after `shellcheck`, not after the composite block); the actionlint excision takes only its own pair (decoy `actionlint-extra` pair survives under the opt-out); the release excision takes only its own pair (real `render_release_optout` against a fixture `justfile.gh` with a decoy `release-notes` pair)
