# [PR 1653](https://github.com/vig-os/devkit/pull/1653) feat: scan preserved configs for retired hook blocks

## Description

A hand-edited `.pre-commit-config.yaml` is preserved on upgrade (#878), so template hook changes never reach it. That is right for hook-stack *evolution* and wrong for a hook **fix**: the repos carrying the broken block are exactly the ones the fix was written for.

Concretely, a config scaffolded before #1170 keeps the upstream `jackdewinter/pymarkdown` hook forever. It is `language: python`, so prek builds a venv on its own base interpreter while the flake toolchain's `pymarkdownlnt` targets `default_language_version` — the C-extension import then fails (`ModuleNotFoundError: No module named 'pyjson5.pyjson5'`), breaking `just precommit`, every local markdown commit, **and** the `devkit-upgrade.yml` commit step. A stale consumer's auto-upgrade can never land, and nothing says why.

This adds the missing signal: a table-driven scan of preserved files for blocks the template retired **because they break**.

Closes #1652.

## Type of Change

- [x] `feat` -- New feature

## Changes Made

- `assets/init-workspace.sh`
  - `known_bad_preserved_patterns()` — the SSoT table, one `<id>|<preserved rel-path>|<ERE>|<remedy>` row per known-bad block. A row earns its place only when the template retired something that breaks; ordinary divergence stays with the #878 diff.
  - `scan_known_bad_preserved()` — warns with `file:line` + remedy on **stderr** (like the #881 retired-`pre-commit` scan) and prints one machine-readable `preserved-hook-drift: <id> in <path>` line on **stdout** per matching row. Non-fatal; comment lines are filtered; only `PRESERVE_FILES` rows are scanned.
  - Called from both the `--preview` report (the preflight surface, side-effect-free) and the post-scaffold guard section.
- `assets/workspace/.github/workflows/devkit-upgrade.yml` — captures the marker lines out of the install log into a `hook-drift` step output and surfaces them in the run summary and the **adoption PR body**, riding the same channel as the `flake-bump:` report (#1497). A warning that only reaches a workflow log reaches nobody.
- `docs/MIGRATION.md` — "Fold the #1170 pymarkdown hook into a preserved config": why preservation blocks the fix, the failure signature, and the exact `language: system` replacement block.

## Follow-up (not in this PR)

A warning does not unstick a consumer that is already broken: their upgrade fails at the prek-gated commit step before any PR opens. The only thing that would is a **surgical auto-fold** of the block when it byte-matches the known old shape (precedent: `migrate_root_gitignore`, #1145). That edits a consumer-owned file, so it deserves its own issue rather than riding along here — filed as #1654.
