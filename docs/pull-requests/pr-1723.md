# [PR 1723](https://github.com/vig-os/devkit/pull/1723) docs(release): re-check inserted_hook_blocks rows before cutting a train

## Description

#1718 added the scaffolded `shellcheck-composite-actions` hook. A consumer whose `.pre-commit-config.yaml` is preserved receives a new hook only through `inserted_hook_blocks()` in `assets/init-workspace.sh`, whose rows are keyed on the *first release that ships the hook*. That version is a literal nothing else checks, trains have been renamed mid-flight twice, and a stale number either under-inserts or re-adds a hook a consumer deleted. The row for the new hook therefore goes on the release branch once the version is fixed (#1717 stays open for that).

What can land now is the guard against forgetting: the Phase 1 prerequisites in `docs/RELEASE_CYCLE.md` gain one bullet — re-check the table's rows against the version being cut — so the lesson is a repo artefact rather than session memory. Triage notes on the issue confirm the mechanism already accepts a hook with no feature group and extracts the block structurally, so no code change is needed on `dev`.
