# [PR 1422](https://github.com/vig-os/devkit/pull/1422) refactor(scaffold)!: drop devc-upgrade; notify via the adoption-PR flow

## Summary

Implements #1421: removes the scaffolded `devc-upgrade` recipe outright. Since the `devkit-upgrade` workflow's adoption PRs became the upgrade path, the recipe's every use was covered better elsewhere — release adoption by the reviewed PR, managed-file repair by git, manual/emergency re-scaffolds by the `install.sh --force` one-liner it merely wrapped — while the `version-check.sh` notification actively steered users at it, around the reviewed flow.

**Breaking** (semver:major): consumers scripting `just devc-upgrade` must use the one-liner.

## Changes

- `assets/workspace/.devcontainer/justfile.devc`: `devc-upgrade` recipe deleted (no stub).
- `assets/workspace/.devcontainer/scripts/version-check.sh`: `notify_update` rewritten — when `.github/workflows/devkit-upgrade.yml` exists in the repo it points at the adoption-PR flow (review, merge, pull, rebuild); otherwise it gives the `install.sh --force` one-liner. Header renamed to "Devkit Update Available". This also gives correct advice during the gitflow cron-dormancy window (workflow on dev but not yet on the default branch → one-liner).
- `docs/MIGRATION.md`: upgrade wording updated.
- Tests (written first, red against the old scaffold): tombstone + notification-contract pins in `tests/bats/just.bats`, `TestVersionCheckScaffold` updated in `tests/test_integration.py`, namespacing test in `tests/bats/init-workspace.bats` now rejects `devc-upgrade` alongside the legacy names. The #1418 behavioral tests for the recipe are removed with it.
- `CHANGELOG.md` `Unreleased` → `Removed` entry (+ manifest-synced copy).

## Verification

- New pins red-first against the old scaffold, green after removal: `TestVersionCheckScaffold` 6 passed; `just.bats` 49/49; `init-workspace.bats` 238/238.
