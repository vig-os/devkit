# [PR 1950](https://github.com/vig-os/devkit/pull/1950) feat: add site-private leak-check hook

## Description

Add the ADR §10 default-on site leak-check hook. A clone without private patterns exits silently; configured clones scan staged changes or selected working-tree files through gitleaks and publish only file, line and rule ID.

## Changes Made

- Resolve `DEVKIT_LEAK_PATTERNS` before `.site/leak-patterns.toml`. Require self-contained gitleaks rules with a nonempty `id` and either `regex` or `path`; reject any extension table, including empty tables and case variants, with exit 2 naming the file.
- Materialize raw blobs from the index for added, copied, modified and renamed paths. Use Git's NUL-delimited metadata only for path selection, with no external diff or textconv; read blobs with `git cat-file`, avoiding checkout filters. Staged, filename and all-files modes then share one gitleaks directory scanner.
- Cover full index content at changed paths, including pure renames; skip deleted and untouched paths. Filename mode skips NUL-containing inputs to enforce the text-hook contract, while direct staged and all-files scans include those bytes.
- Scan selected site bindings and repository ignore files as data. Isolate gitleaks 8.30.1's automatic source-ignore loading by scanning a root `.gitleaksignore` separately; the private config remains explicit.
- Define the default-on text hook once in `nix/hooks.nix` and mirror both portable configs. Pin gitleaks in Nix-generated hooks, and publish only file, line and rule ID. Document scan boundaries, printed paths, linked worktrees and intentional exceptions.

## Additional Notes

S4 PR #1938 is still open. This implementation uses exactly the ADR's `.site/leak-patterns.toml` path and gitleaks format without importing S4's loader. S4 supplies site initialization and ignored-directory scaffolding; it remains a coordination dependency for the complete site workflow.

The hook scans all text types so documentation is covered. Malformed project syntax does not require parsing. Rule IDs and matching file paths must be safe for public logs. Source archives without patterns are also silent no-ops. The final self-contained/path-or-regex rule is coordinated with S4 in issue #1932.
