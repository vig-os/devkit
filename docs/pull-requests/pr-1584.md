# [PR 1584](https://github.com/vig-os/devkit/pull/1584) feat(sesh): let a session pick its own layout profile

## Description

`vigos.sesh` applied one window set to every project. `layout.windows` parameterizes *which* windows a session gets, but the choice is global — every seed in `sessions` opened identically, so a repo with no pull-request workflow still started a dashboard window on a permanently empty view, and a docs repo still got a git TUI it had no use for. The only escape was disabling the module and hand-writing `sesh.toml`, discarding the whole layout mechanism to change one window.

This adds named layout profiles and a per-session selector. Opt-in and backward compatible.

## Changes Made

**`nix/home/sesh.nix`**

- `vigos.sesh.layout.profiles` — attrset of named window sets, reusing the existing `windowModule`. Empty by default.
- `sessions[].layout` — `nullOr str` naming a profile. Null (default) inherits.
- `default` is `layout.windows` and wins over a same-named key in `profiles`, so the default set has **one** home rather than two that can disagree.
- The layout body is factored into `renderProfile` so one code path serves every profile including the default; `sesh-layout` dispatches on an optional argument and stays a **single binary**, because consumers probe for it by name to detect a provisioned host.
- An undefined profile throws while rendering, naming the session, the bad profile and the valid set.

**Why the guard throws rather than using `assertions`:** assertions only fire when the activation package is evaluated. A consumer (or a test) that evaluates just `home.file.".config/sesh/sesh.toml".text` would sail past them and emit a `sesh.toml` whose sessions all die at `sesh connect` — far from the definition that caused it.

**Delivery uses sesh's own config, not a new mechanism.** `SessionConfig` embeds `DefaultSessionConfig` in sesh's `model/config.go`, so a `[[session]]` block already accepts `startup_command`, and `startup.Exec` resolves per-session → wildcard → default. A session with a profile emits `startup_command = "sesh-layout <profile>"`; one without stays bare and inherits `[default_session]`.

**Rejected alternatives** (detail in #1583): sesh's native `[[window]]` + per-session `windows` — it sends startup keys to the session rather than a captured `#{window_id}` (this module captures ids precisely because names collide or auto-rename), errors if a name has no `[[window]]` block, and cannot run a command *in* window 1 with a shell fallback, which is how the first entry works. `[[wildcard]]` patterns never fire for curated seeds, because `configWildcardStrategy` needs the connect name to resolve to a directory. Inline `sessions[].windows` duplicates a window list across every session sharing a layout.

`_ci_full_config` cannot express per-session behaviour (the ci profiles declare no sessions), so the new tests render `sesh.toml` from a synthetic home config. That needs expression eval rather than an installable, so `tests/nix_helpers.py` grows `nix_eval_expr` — returning the completed process rather than asserting, which is what makes the guard's *failure* path testable at all. It also gives the previously unused `flake_expr` its first caller.

- `uv run pytest tests/ --ignore=tests/test_image.py --ignore=tests/test_integration.py --deselect …::test_flake_check_succeeds` → **935 passed, 1 skipped** (192s). `test_flake_check_succeeds` is deselected in CI too, where nix-fast-build builds the same checks.

### Manual Testing Details

Built the generated `sesh-layout` from a synthetic config declaring a `docs` profile, and exercised the real artifact in scratch tmux sessions rather than reading the source:

| Check | Result |
|---|---|
| `default` profile | `edit git shell claude` — unchanged from module defaults |
| `docs` profile | `edit shell` |
| Idempotency guard (re-run inside a live session) | window set untouched, exit 0 |
| Unknown profile | `sesh-layout: unknown profile nope` on stderr, exit 1 |
| Per-session emission | selecting session gets `startup_command = "sesh-layout docs"`; silent session stays bare |

The mechanism was also field-proven in a consumer config before being upstreamed here — the same path `vigos.sesh` itself took ("parameterized port of the maintainer's proven setup") — including a check that the generated `sesh.toml` parses under sesh 2.26.2 with every seed still listed.
