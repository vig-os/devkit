# [PR 1742](https://github.com/vig-os/devkit/pull/1742) docs: creation runbook for the vigos-devkit-upgrade GitHub App

## Description

Adds the missing creation runbook for the `vigos-devkit-upgrade` GitHub App —
the machine identity behind the scaffolded self-polling `devkit-upgrade.yml`
workflow — and points that workflow's grant header at the new runbook instead
of restating the grant inline.

## Type of Change

- [x] `docs` -- Documentation only

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- New `docs/runbooks/devkit-upgrade-app.md` (`docs/runbooks/` did not exist
  yet), mirroring the structure of `vig-os/org-config`'s
  `docs/runbooks/github-app.md`: Purpose, Prerequisites, Create the App,
  Permissions, Webhooks, Visibility, Installation, Bootstrap secrets, Key
  rotation, What this App must NOT be given.
- `assets/workspace/.github/workflows/devkit-upgrade.yml`'s grant header:
  removed the restated permission list and replaced the closing
  `App provisioning + rotation: https://github.com/vig-os/devkit/issues/1302`
  line with a link to the new runbook (absolute URL, since the runbook itself
  is not shipped into consumer repos — `test_scaffold_has_no_unshipped_path_references`
  requires that).
- `CHANGELOG.md` `## Unreleased` → `### Added` entry (and its
  `assets/workspace/.devcontainer/CHANGELOG.md` mirror, regenerated by the
  `sync-manifest` pre-commit hook).

**This is a normal-train change, not release-neutral.** It edits
`assets/workspace/...`, which moves the image derivation path, so it cannot
ride the release-neutral lane.

## Acceptance criteria (issue #1739)

- [x] A runbook for the `vigos-devkit-upgrade` App exists in this repo and
      states the grant, the visibility setting, the install targets and the
      key-rotation procedure — `docs/runbooks/devkit-upgrade-app.md`,
      Permissions / Visibility / Installation / Key rotation sections.
- [x] The visibility paragraph links to the recorded decision in
      `vig-os/org-config` rather than re-deciding it, and says which repo is
      the source of truth for the credential lists — the runbook's Visibility
      section links `vig-os/org-config#271` and the `APP VISIBILITY DECISION`
      jsonnet comment; Bootstrap secrets states `vig-os/org-config`'s
      `otterdog/vig-os/vig-os.jsonnet` is authoritative for the secret lists.
- [x] Key rotation includes the `GET /app/installations` inventory sweep — step
      6 of Key rotation, called out as a **required** step (the only
      compensating control for a public App's install page).
- [x] The scaffolded `devkit-upgrade.yml` header links to the runbook — see
      the header diff above.

## Factual gaps flagged instead of guessed

The runbook calls these out inline as "verify against the live App" rather
than inventing values, since no source read for this issue states them:

- The App's exact display name if it differs from its slug, and its Homepage
  URL.
- The installation's repository scope ("All repositories" vs. "Only select
  repositories") on `vig-os` and on `exo-pet`.
