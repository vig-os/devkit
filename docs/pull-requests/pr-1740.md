# [PR 1740](https://github.com/vig-os/devkit/pull/1740) docs: fix DEVKIT_COMMIT_APP_ENVIRONMENT guard quoting claim

## Description

Fixes a factually wrong guard comment above the `DEVKIT_COMMIT_APP_ENVIRONMENT`
validation guard in `assets/init-workspace.sh` (around line 515). The comment
claimed the value is rendered as an **unquoted** YAML scalar, "exactly as for
`DEVKIT_SYNC_TARGET` above". `render_commit_app_environment()` (around line
2351, unchanged by this PR) actually emits `environment: '<name>'` —
**single-quoted, unconditionally** — precisely because the allowed charset
admits YAML 1.1 bool/number shapes (`true`/`no` parse as booleans, `0755` as
the integer 493, `1e3` as a float), and an unquoted scalar would hand GitHub a
non-string `environment` it rejects at dispatch, a failure `actionlint` does
not catch.

## Changes Made

Reworded the guard comment only, in `assets/init-workspace.sh`:

- States the value is rendered as a single-quoted YAML scalar
  (`environment: '<name>'`), not unquoted.
- Keeps the charset allowlist as the LOAD-BEARING guard, now explicitly because
  it refuses `'`, so the quoted splice never needs escaping.
- Keeps the cross-reference to `DEVKIT_SYNC_TARGET` but makes the quoting
  difference explicit (mixed quoted/unquoted splices there) instead of
  implying the two keys behave alike.
- Preserves the rest of the comment's content unchanged: the GitHub 255-char /
  case-insensitive constraint, the "pure `.vig-os` key, no CLI flag, so only a
  format guard" note, and the `#1710` reference.

No code changed — `git diff -- assets/init-workspace.sh` touches only `#`
comment lines. `render_commit_app_environment()` and the validation guard's
`if` body are untouched, so this is a byte-identical render for every existing
consumer.
