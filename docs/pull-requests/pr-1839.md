# [PR 1839](https://github.com/vig-os/devkit/pull/1839) fix: let the upgrade preflight pass untracked output the upgrade will ignore

## Description

The `install.sh --force` preflight refused **any** untracked file. A repo that had just gained a language, such as a Rust repo with `cargo build` output in `target/`, therefore could not take the very upgrade that adds the `.gitignore` fragment ignoring it. The workaround was to move the build directory aside. Same for `node_modules/`, `.venv/` and Nix `result` links.

**Stack 5/6** for #1833. Base: #1838 (`feature/1831-rust-pack-adopter-docs`).

## Type of Change

- [x] `fix` -- Bug fix
- [x] `test` -- Adding or updating tests

## Changes Made

The judgement moves to where the knowledge is. The host doesn't know the gitignore fragments or the detected languages; the image does.

- **`install.sh`** (host): tracked changes still refuse, unchanged. Untracked paths (`git ls-files --others --exclude-standard --directory`) are no longer refused host-side. They are forwarded to the container as `DEVKIT_PREFLIGHT_UNTRACKED`. New `--allow-untracked` flag skips that check: it names the paths it leaves out, and tracked changes still refuse.
- **`assets/init-workspace.sh`** (container): `preflight_untracked_guard` runs right after language detection, before any file is written. It assembles the root `.gitignore` this run will write (template base + the detected languages' `gitignore.d` fragments + `.gitignore.project`, the same parts `render_gitignore` uses) and matches each path with git's own matcher (`check-ignore --no-index`) in a scratch repo, because the workspace's `.git` may be an unmounted worktree pointer. Covered paths are named and left in place. Any other path refuses by name and hints `--allow-untracked` / `--skip-preflight`.
- Build output of a language that **isn't detected** is not excused (`node_modules/` without a `package.json`), because its fragment won't be in the upgraded `.gitignore`.
- `docs/MIGRATION.md` "Upgrade preflight guard and preview" documents the rule and the flag.

## [Comment #1](https://github.com/vig-os/devkit/pull/1839#issuecomment-6001693106) by [@gerchowl](https://github.com/gerchowl)

_Posted on October 5, 2026 at 07:39 PM_

Follow-ups from an independent review:
- `git ls-files` now runs with `--no-empty-directory`. An empty untracked dir never counted under the old `git status` check, and doesn't now.
- It also runs with `core.quotePath=false`. A non-ASCII name reaches the container verbatim; the C-quoted form matched no ignore pattern.
- **Version skew:** if a new `install.sh` runs `--version <old>`, an image whose `init-workspace.sh` doesn't know `DEVKIT_PREFLIGHT_UNTRACKED` would silently skip the check. `install.sh` now probes the image after the pull and refuses untracked paths as before when the image predates #1826. Tested with a stub runtime.
- **DRY:** `render_gitignore` and the guard now share `emit_gitignore_additions` and `flake_hooks_ignore_wanted`. The guard therefore also covers the #1092 `.pre-commit-config.yaml` store symlink. Tested.

Stack tip verified locally: `init-workspace.bats` + `install.bats` + `consumer-matrix.bats` 470 ok; Rust/flake pytest 90 passed; consumer-matrix `rust` and `rust-flake` cells passed.
