# [PR 1836](https://github.com/vig-os/devkit/pull/1836) feat(nix): add sandboxExcludes to mkRustProject's nextest check

## Description

`mkRustProject`'s `nextest` check runs inside the Nix build sandbox, where tests that need a PTY, process groups, signals or the network cannot pass. Before this PR a consumer had two options: `nextest = false`, which also dropped every test the sandbox *can* run, or an undocumented `craneArgs` patch. This adds a named seam for it.

**Stack 2/6** for #1833. Base: #1835 (`bugfix/1810-rust-project-hook-knobs`).

## Type of Change

- [x] `feat` -- New feature
- [x] `test` -- Adding or updating tests

## Changes Made

- `nix/mk-rust-project.nix`: new `sandboxExcludes ? [ ]`, a list of nextest filterset expressions. They are rendered into a single `-E 'not (a) and not (b)'`, because nextest *unions* repeated `-E` flags, so per-exclusion flags would still run everything. The filter is composed with any `cargoNextestExtraArgs` the consumer passes through `craneArgs`, never assigned over it.
- Malformed input (not a list, or an empty entry) fails eval with `sandboxExcludes must be …`.
- Only `checks.nextest` is affected. The excluded tests stay in `just test` and CI through the Rust `justfile.project` that #1496 (stack 3/6) seeds. The adopter docs for the seam land with #1831 (stack 4/6).

## Changelog Entry

### Added
- **`mkRustProject` `sandboxExcludes` for tests the Nix sandbox cannot run** ([#1834](https://github.com/vig-os/devkit/issues/1834))
  - A list of nextest filterset expressions (e.g. `[ "test(pty_)" "binary(supervisor)" ]`) that `checks.nextest` skips, for suites that need a PTY, process groups, signals or the network
  - The excluded tests stay in `just test` and CI; only the sandboxed flake check skips them, so a repo no longer has to choose between `nextest = false` and a red `nix flake check`
