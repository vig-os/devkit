# [PR 1603](https://github.com/vig-os/devkit/pull/1603) feat(ci): make the CI dev-shell gcroot path configurable

## Description

`setup-devkit-toolchain`'s direnv branch realises the consumer dev-shell into a
Nix profile under `$RUNNER_TEMP`. The `--profile` is what makes it a **gcroot**
rather than a bare `nix develop`, and on a hosted runner that placement is
right — the machine is discarded with the job anyway.

An **ephemeral self-hosted** runner inverts the trade-off: `RUNNER_TEMP` is
wiped between jobs while the `/nix/store` — the whole reason to run one —
persists. Nothing roots the dev-shell between jobs, so a routine `nix.gc` on the
host collects the closure every CI run needs. Measured on a `direnv` consumer
with a heavy dev-shell: a 26 s `Set up devkit toolchain` step becoming
180–237 s, in each of the three toolchain lanes that run per CI run.

This adds an opt-in `.vig-os` key naming a persistent path for that profile.
Absent or empty — the shipped default — reproduces today's behaviour byte for
byte for every consumer, hosted and self-hosted alike.

## Changes Made

Wired the way `DEVKIT_CI_RUNNER` (#1173) is, per the issue discussion — same
class of fact (an infrastructure detail of the runner this repo builds on),
declared in the consumer's committed manifest, so there is no repo variable to
declare and it round-trips a `--force` upgrade:

- **`assets/workspace/.vig-os`** — new `DEVKIT_DEV_PROFILE_PATH=` key, shipped
  empty, documented with the self-hosted rationale.
- **`resolve-toolchain`** — reads the key and emits a `dev-profile-path` output.
  Vets it once, on the cheap hosted producer job: a relative path, a path inside
  the runner's `_work`/`_temp` tree, or the filesystem root fails there, before
  any lane realises a dev-shell. Trailing slashes are trimmed.
- **`setup-devkit-toolchain`** — new optional `dev-profile-path` input, routed
  through `env:` (never inline `${{ }}` in `run:`). The step resolves it, or
  falls back to `$RUNNER_TEMP/devkit-dev-profile` when unset, and **all four**
  `nix develop` calls use the resolved path. What only the target host can
  answer — is the parent directory creatable, is it writable — is checked there
  and fails the step loudly. Neither layer falls back silently: a job-scoped
  gcroot is indistinguishable from the bug.
- **`ci.yml`** — the `lint`, `test` and `commit-checks` lanes pass the resolved
  path. Deliberately only those three: they are exactly the jobs
  `DEVKIT_CI_RUNNER` can move onto a consumer's runner, and the three the issue
  measured. Everything else in the scaffold stays on the hosted default, where
  `RUNNER_TEMP` is the correct place for the root.
- **`init-workspace.sh`** — the key is read before the template overwrite and
  written back, so an upgrade cannot silently re-root the dev-shell in
  `RUNNER_TEMP`.
- **`docs/MIGRATION.md`** — new "Keep the dev-shell gcroot across ephemeral
  self-hosted jobs" section plus the manifest-key table row, including the
  runner-host notes: slots on one host are expected to **share** the path
  (concurrent `nix develop --profile` realisations take the profile lock and
  converge), and it must be a local persistent directory, not a per-job tmpfs.

## Additional Notes

The wiring shape follows the recommendation in the issue comment rather than an
Actions variable. The comment's two implementation notes are both addressed: the
shared-path expectation is documented in `MIGRATION.md`, the `.vig-os` key
comment and the action's input table; and the fail-loudly constraint is split
between resolve time (a value no host could make persistent) and step time (what
only the target host can answer).

The `_work`/`_temp` guard catches the mistake the knob exists to prevent —
rooting inside the tree the runner clears — but it cannot prove an arbitrary
path is persistent, and does not claim to.
