# [PR 1938](https://github.com/vig-os/devkit/pull/1938) feat: add per-clone site configuration and initializer hook

## Description

Add per-clone site bindings and a site initializer hook following ADR §8–§9. The non-TTY fallback writes an unbound template that passes the same validation as initializer output.

## Changes Made

- Exclude relative and in-tree PATH entries and resolved executable targets; keep initializer selection outside repository control.
- Validate gitleaks rule shape separately from site bindings; support realistic `secretGroup`, userinfo regexes and allowlists. Coordinate this boundary with [S6](https://github.com/vig-os/devkit/issues/1932#issuecomment-6440119217).
- Restrict bound URI forms, detect writes outside staging, remove newly created empty site directories on failure, and return usage for missing module arguments.
- Pin `help` as the managed justfile default with a regression test.

- Add `check-site-config --print-path` and `site-init`, including schema validation, credential rejection, active-site lookup, PATH discovery, staging cleanup and `--force`.
- Add the managed `just site-init` recipe and ignore `.site/` and `.aws/`.
- Record the architect’s ADR §8/§9 clarification and Amendments entry: empty locations are valid unbound bindings, reported as notices; consumers must reject unbound locations with actionable errors.
