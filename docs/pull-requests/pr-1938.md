# [PR 1938](https://github.com/vig-os/devkit/pull/1938) feat: add per-clone site configuration and initializer hook

## Description

Add `check-site-config` and `site-init` for per-worktree site bindings. Both commands resolve the git toplevel from any subdirectory and refuse outside git. Initialization discovers trusted external tools or writes an unbound template, validates staged files, then publishes them.

## Changes Made

- Add the managed `just site-init` recipe while preserving `help` as the default; ignore `.site/` and `.aws/` in scaffolds.
- Validate schema v1, active-site lookup, credential restrictions and bound location forms. Reject whitespace/control characters, unsafe file URIs, invalid S3 bucket names and reserved site names; errors name fields without exposing values.
- Anchor discovery, staging and lookup to the resolved git worktree root, including linked worktrees. Exclude relative and in-tree PATH directories and resolved executable targets.
- Detect `.site/` changes recursively and refuse symlinks/special files. Clean staging and newly created empty directories after failure; enforce `--force` before publishing.
- Expose `validate_patterns(path: Path) -> None` for S6. Its self-contained pattern rule is recorded once in the ADR Amendments: case-insensitive keys without ambiguous variants, at least one usable id-plus-regex/path rule, no extend, missing files mean no check. Pattern values are never checked as site credentials or exposed in errors.
- Record the ADR §8/§9 clarification: empty locations are valid unbound bindings with notices; consumers must refuse unbound bindings with actionable errors.

## Additional Notes

Initializers are trusted external programs, not sandboxed processes. Recursive metadata checks detect changed entries but cannot prevent arbitrary writes or an initializer restoring metadata. This limit is documented in ADR §9. S6 coordination: https://github.com/vig-os/devkit/pull/1950#issuecomment-6485094966.
