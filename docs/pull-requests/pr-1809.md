# [PR 1809](https://github.com/vig-os/devkit/pull/1809) fix(init): warn when mirror mode has no release fold-back

## Description

`DEVKIT_SYNC_TARGET` mirror mode only folds back into the trunk through the release train (#1424), which is rendered into `release-core.yml`. With `release` in `DEVKIT_FEATURES_DISABLED`, that file is pruned. The fold render's `-f` guard then skipped it without any output, so the mirror was never merged back and the trunk's `docs/issues/` + `docs/pull-requests/` froze at the switch with no marker (hit in tessera#362).

The scaffold now prints a notice for this combination. It does not abort: a release-less consumer can choose this as a deliberate interim setup, which matches the #1284 / #1431 notice precedent.

The docs also claimed that "each sync run regenerates full state", which made the permanent divergence look self-healing. The sync is incremental (it uses a watermark), and only a `force-update` dispatch rebuilds from scratch. See the issue comment and #1757.

## Changes Made

- `assets/init-workspace.sh`: composition notice next to the #1284 sync-issues notice. It fires only when the release group is disabled, sync-issues is enabled and `DEVKIT_SYNC_TARGET` is set. The stale "regenerates full state" wording in the `render_sync_settings` comment is fixed.
- `assets/workspace/.vig-os`: the `DEVKIT_SYNC_TARGET` comment now describes the incremental sync and the release-train fold-back. The `DEVKIT_FEATURES_DISABLED` comment now says that disabling `release` removes that fold-back.
- `docs/MIGRATION.md`: "self-healing archive" is gone. There is a new paragraph on the release dependency in the mirror section, and the coupling is noted on the `release` feature-group entry.
- `tests/bats/init-workspace.bats`: one test checks that the notice fires. Another checks that it stays quiet when release is enabled, and when sync-issues is disabled too (there only the #1284 notice applies).
