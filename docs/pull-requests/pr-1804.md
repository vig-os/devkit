# [PR 1804](https://github.com/vig-os/devkit/pull/1804) fix: actionlint opt-out leaves two blank lines that fail the consumer's yamllint

## Description

`render_actionlint_optout` (`assets/init-workspace.sh`) deletes the
`# >>> devkit:actionlint` … `# <<< devkit:actionlint` range from a rendered
`.pre-commit-config.yaml` when `DEVKIT_FEATURES_DISABLED=actionlint`, but left
the blank lines flanking the block in place. The two now-adjacent blanks fail
the scaffold's own yamllint (`empty-lines: max: 1`) with
`too many blank lines (2 > 1)`.

## Type of Change

- [x] `fix` -- Bug fix

## Changes Made

- `render_actionlint_optout` now does the range-delete via `awk` instead of
  `sed`, deferring each blank line's print by one line so it can drop the one
  immediately before the opening sentinel instead of emitting it. Blank-line
  runs elsewhere in the file pass through unchanged -- this is scoped to the
  one seam the excision creates, not a file-wide collapse. Still a no-op when
  the sentinels are absent (the existing `grep` guard is unchanged) and
  idempotent. The temp-file-then-`cat` write preserves the consumer file's
  mode/inode, same as `splice_lines`.
- Checked every other sentinel-excision render (`grep '# >>> devkit:'`):
  `render_release_optout` (`.devcontainer/justfile.gh`) is the only other one,
  and it already drops its trailing blank line with a dedicated
  `sed -i '${/^$/d}'` pass -- it does not share this defect. No change needed
  there.
- **Preserved-config case**: a consumer who already hit the bug on a prior
  render is **not** repaired by a later upgrade. The excision is gated on the
  sentinels still being present (`grep -q '# >>> devkit:actionlint'`), and an
  already-excised file has none left, so there is nothing for a later run to
  act on. This is noted here rather than pinned by a test: a test asserting
  "not repaired" would pin the gap itself as a contract, turning red the day
  someone closes it. No fold machinery added for a cosmetic blank-line defect
  (unlike #1652's structural folds) -- if you already hit the bug, delete the
  one extra blank line by hand; there is nothing else to clean up.

    and re-running the opt-out) clears it
