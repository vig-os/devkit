# [PR 1690](https://github.com/vig-os/devkit/pull/1690) chore(ci): cut the BATS suite runtime

## Description

The BATS suite is ~54% of `Project Checks`, the only job on CI's critical path (6m14s of 11m28s, measured on run 36050981328), and 80% of that is `init-workspace.bats` making ~274 full `init-workspace.sh` renders. This PR pulls the three levers measured in #1687, in order of payoff:

- **WP1 — run BATS under `bats --jobs`.** `bats -j` shells out to GNU `parallel`, which was nowhere on PATH, so the `just test-bats` "parallel" branch was dead and CI ran the suite serially. `parallel` now rides with the bats wrapper in `nix/bats.nix` (bats is its only consumer; it lands on no consumer's PATH; incremental closure over the delivered toolchain is 0.77 MiB — perl and friends were already there). Both entry points, the recipe and the `test-project` composite action, run `bats -j "$(nproc)"`. Jobs are spread *within* files, the right axis when one file is 80% of the time.
- **WP2 — batch the two per-file fork loops in `init-workspace.sh`.** The `chmod u+w` scaffold sweep (production path) and the host-side placeholder-substitution fallback each forked once per file across a ~163-file tree, 65% of a scaffold's ~4.3k forks. Both are now one `xargs` batch. Rendered trees are byte- and permission-identical (`diff -r` + `find -printf '%m %y %p'`) for all four modes, all four old/new upgrade orderings, smoke mode, and nested/`.git/`/symlink/binary edge cases. Per scaffold: 680 ms → 267 ms (hyperfine, 20 runs).
- **WP3 — stop re-rendering trees an earlier test already built.** `_clone_shared <fixture> <ws>` copies a `setup_file`-rendered tree (`cp -a`, ~36 ms) instead of re-running the script; three seeded fixtures (`node-both`, `python-both`, `trunk-both`) join the four per-mode ones. Only pure-setup calls were converted (no `$output`/failure assertion on the render, empty target, stock env and flags); every `_upgrade`, `--prune-devcontainer`, `--smoke-test`, preview and consumer-seeded site keeps its real invocation. 343 → 250 script invocations per file run; 300 tests, identical `@test` list.

One real finding along the way: the suite was **not** fully parallel-safe. Four tests in `worktree.bats` drive real tmux sessions and `just worktree-clean` against the repo's live `<repo>-worktrees` directory, and raced under `-j 8`. That file now opts out of within-file parallelism via `BATS_NO_PARALLELIZE_WITHIN_FILE` (10 tests, no cost). Those tests `skip` under `CI=true`, so CI never saw it.

## Changes Made

- `nix/bats.nix` — `symlinkJoin` over `bats.withLibraries`, re-wrapping `bin/bats` with `--prefix PATH` to GNU `parallel`. `name` and `meta` are inherited so `devShellToolNames` (`meta.mainProgram`) and `test_flake_devshell.py::test_devshell_provides_bats` stay stable. `share/bats` (`BATS_LIB_PATH`) is unchanged.
- `.github/actions/test-project/action.yml` — `bats -j "$(nproc)" tests/bats/`.
- `justfile` — `test-bats` drops the dead per-file GNU-parallel branch for `bats -j "$(nproc)"`.
- `tests/bats/just.bats` — two RED-first pins: the recipe and the action use `bats -j`, and the `command -v parallel` branch is gone.
- `tests/bats/worktree.bats` — `setup_file` exports `BATS_NO_PARALLELIZE_WITHIN_FILE=true` (see above).
- `assets/init-workspace.sh` — `sweep_scaffold_writable` collects targets and issues one `xargs -0 -r chmod u+w --`; the manifest-less fallback is one `grep -rl --null --exclude-dir=.git … | xargs -0 -r sed -i … --`. The image-only manifest fast path is untouched. Accepted semantic differences: `grep -r` follows a symlinked `$WORKSPACE_DIR` itself (old `find` walked nothing there — strictly more correct); traversal order differs (edits are per-file independent); a failing `chmod` now aborts after the batch rather than at the first file.
- `tests/bats/init-workspace.bats` — `_render_shared` in `setup_file`, `_clone_shared` helper, three new fixtures, 94 call sites converted (61 `both`, 9 `direnv`, 2 `devcontainer`, 2 `bare`, 1 three-mode loop, 9 `node-both`, 4 `python-both`, 5 `trunk-both`). Converted sites keep the `run …; assert_success` shape, so a broken clone still fails the test; the fixture render's own exit status is checked once per file in `setup_file`.
- `CHANGELOG.md` (+ scaffold mirror via `sync-manifest`) — Changed entry.

**CI `Project Checks` before/after** (cross-cutting criterion):

| | BATS step | `Project Checks` job | whole run |
|---|---|---|---|
| before (run 36050981328) | 6m14s | 11m28s | 11m35s |
| after (run 36108278820, this PR) | **3m11s** (602/602, 4 jobs) | **9m59s** | 10m46s |

The BATS step halved (1.96x on 4 vCPU; the issue predicted 2.5-3x from 8-core measurements, and the runner's per-core throughput is lower than the local box). The job-level saving is smaller than the step-level one because the six nix/flake steps took 4m00s on this run against 2m40s on the baseline: the Tier 0 nix-fast-build gate had to build the changed dev shell (new bats derivation) instead of pulling it from Cachix. That is a one-off per derivation change and unrelated to the suite.

## Additional Notes

Not built locally: the full `devkitImage` tarball (its toolchain env was built and checked instead; the Image Tests job covers the rest).

Follow-ups, filed:

- #1693 — **Retire the image-only `.placeholder-manifest.txt` fast path.** It still forks one `sed -i` per manifest entry (~2.6 s) and is now slower than the batched fallback (~0.15 s); retiring it deletes the flake build step, its image test and the host/image code-path divergence.
- #1694 — **`worktree.bats` operates on the live repo's `<repo>-worktrees` directory** and runs `just worktree-clean` there. This is not hypothetical: a local full-suite run during this work force-removed three sibling worktrees (no tmux session, so "stopped") and deleted their branches — nothing was lost only because their commits had already been cherry-picked. It should drive a throwaway repo under `BATS_TEST_TMPDIR`, which would also let it rejoin within-file parallelism.
- #1695 — **Parallelize `setup_file`'s seven fixture renders** — they are a serial prologue on the `-j` critical path, which is what makes 2-test fixtures (Cargo, nix marker) not pay today.
- #1696 — **Prove `_upgrade` into an empty dir equals `_scaffold`** (or give it an `upgrade-both` fixture): the largest remaining redundant-render cluster (~13 tests).
- #1697 — `bats_require_minimum_version 1.5.0` in each `.bats` file to silence the `BW02` noise.

- #1692 — **Split `Project Checks` into parallel lanes.** Post-#1687 the job is still a serial chain of independent blocks (prek 42s, BATS 3m11s, pytest 1m18s, nix gates ~2m40s-4m) behind one 44s setup; lanes turn the sum into the max.
