# [PR 1870](https://github.com/vig-os/devkit/pull/1870) fix(ci): run scaffold drift through nix in direnv mode

## Description
In `DEVKIT_MODE=direnv`, `Scaffold Drift` did `docker login/pull/run`, so a strictly direnv-only repo still needed a container runtime. Now the job (direnv only) provisions nix via the shared toolchain preamble, fetches the pinned devkit flake source (`nix flake metadata`), replays the image's two bake steps (`{{IMAGE_TAG}}` stamp, VERSION file), runs `bash init-workspace.sh --force --no-prompts` against a scratch clone under `RUNNER_TEMP` (removed on exit; no container, no root-owned files) and diffs exactly as before. devcontainer/both/bare keep the container path unchanged. `rsync` is added to the dev-shell tools.

**Deviation from the brief:** `nix run …#install` cannot be used — `install.sh` itself `docker|podman run`s the image, so it is not container-free. The scaffold is run directly from the flake source instead.

**Parity (local, darwin, GNU tools):** scratch clone of gerchowl/claude-config @ dev (6d6ef67, devkit 1.18.0, direnv): exit 0 "No scaffold drift detected"; after committing a hand edit to SECURITY.md: exit 1 "Scaffold drift detected" with the diff; scratch dir removed both times.

**Docker/container audit of rendered workflows:** `container:` jobs use the resolved image (empty in direnv, so inert); resolve-toolchain's docker login/manifest probe only runs when an image is resolved (container modes); `setup-devkit-toolchain` only filters podman out of PATH. **Still docker in direnv mode:** `devkit-upgrade.yml` (`install.sh --docker`) — not changed here, needs its own issue.
