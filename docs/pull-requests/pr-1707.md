# [PR 1707](https://github.com/vig-os/devkit/pull/1707) fix(init): scope placeholder substitution to the paths devkit ships

## Description

`init-workspace.sh` had two placeholder-substitution paths: an image-only fast
path that sed'ed one file per entry of a manifest baked into the image (#718),
and a runtime fallback that batched `grep -rl | xargs sed -i` over the whole
workspace (#1687). This replaces both with one routine whose candidate set is
the files devkit ships, mapped into the workspace.

**The issue's premise needs a correction.** #1693 called the manifest path
"15-20x slower" on the strength of a ~117-entry list. The baked manifest has
**13 entries**, not 117, and on a clean tree the manifest path measured **31 ms**
against **16 ms** for the fallback — speed is noise at that size, and the
"retire it because it is slower" framing does not hold.

What does hold, and is the real reason to land this, is **scope**. The fallback
greps `$WORKSPACE_DIR`, which in the container is the consumer's mounted repo —
`.venv`, `node_modules` and all. Any file at a path devkit does not ship, holding
a literal `{{SHORT_NAME}}`, `{{ORG_NAME}}` or `{{GITHUB_REPOSITORY}}` token, was
rewritten in place on the first scaffold and again on **every upgrade**.
Reproduced with seeded files; two of the new BATS tests fail on `dev` for exactly
that reason. The manifest path never had that reach, so retiring it without
scoping the survivor would have made the consumer-facing behaviour strictly
worse. Scoping is also cheaper where it matters: on a 7.4k-file consumer tree the
walk drops from **405 ms to 38 ms**.

**What this does not change, stated plainly.** The new scope is the set of
*paths* devkit ships, not the set of files devkit *owns*. A consumer file living
at a shipped path that an upgrade preserves rather than overwrites — `README.md`,
`.typos.toml`, `.pre-commit-config.yaml`, `renovate.json`, a consumer `flake.nix`,
`.devcontainer/*` under `direnv`/`bare` — still has its tokens resolved. That is
the retired manifest path's reach exactly, and the reach `sweep_scaffold_writable`
still has for its `chmod`, so it is neither a regression nor a change; it was
simply never written down. `PRESERVE_FILES` is a copy-time concept and does not
carry over to substitution. The changelog entry and the routine's contract
comment both say so now.

## Changes Made

`assets/init-workspace.sh`

- New `emit_substitution_candidates <src_dir>`: walks `find -L "$src_dir"
  -mindepth 1 -type f`, skipping `.git/` and `.venv/`, maps each relative path to
  `$WORKSPACE_DIR/$rel` and emits it NUL-terminated when the destination is a
  regular file and not a symlink. It maps template paths to workspace paths the
  same way `sweep_scaffold_writable` does — a shared idiom, not an identical
  routine: the filters differ (that one takes `-e` of any type for `chmod`, this
  one regular files only, and it prunes where the other does not).
- The pass runs it for `$TEMPLATE_DIR`, plus `$SMOKE_TEST_DIR` under
  `--smoke-test` (the overlay lands outside the template tree — same guard
  `sweep_scaffold_writable` uses), and pipes the result through one batched
  `xargs -0 grep -lZ` and one batched `xargs -0 sed -i`.
- `.git` and `.venv` are pruned **by name at any depth**
  (`\( -name .git -o -name .venv \) -prune`), which is what the copy rsync's
  `--exclude='.git' --exclude='.venv'` mean — they are basename patterns — so the
  walk cannot reach a destination the copy never wrote. The case that matters in
  production is the venv the image bakes inside `/root/assets/workspace` (#735).
  Pruning is also cheaper than filtering: the directories are not descended.
- `emit_substitution_candidates` normalizes a trailing slash off its argument
  (`${1%/}`). Without it, `TEMPLATE_DIR=".../workspace/"` makes the prefix strip
  look for `.../workspace//`, which no `find` output starts with, so every
  relative path stays absolute, no destination resolves, and the pass substitutes
  **nothing** while exiting 0 — a scaffold that silently ships 13 files with live
  tokens.
- The #1687 selection-semantics comment survives as the routine's contract —
  regular files only, symlinked destinations skipped, `.git/` skipped, binaries
  matched (no `-I`), failures swallowed so neither `grep` exit 1 nor exit 2 trips
  `set -o pipefail`.
- Deleted: the `MANIFEST_FILE` variable, the `if [[ -f "$MANIFEST_FILE" ]]`
  branch, and both log lines (`Using build-time manifest (N files)`,
  `Warning: Manifest not found, searching at runtime (slower)`).
- `SCRIPT_DIR` stays — it locates `parse-github-remote-lib.sh`, `justfile.d/`,
  `gitignore.d/` and the smoke-test overlay — and its comment now says so
  instead of "for manifest location". Four other comments that claimed the
  manifest "already lists" a path (`seed_node_justfile_project`'s call site,
  `render_license`'s header, its inline rationale, its call site) are reworded to
  the template-shipped set.

`flake.nix`

- The build step that greped the template and wrote
  `/root/assets/.placeholder-manifest.txt` is removed. Nothing reads it.

`tests/`

- Four new behavioural BATS tests (`init-workspace.bats`), each RED before its
  fix:
  - two seed files at paths the template never ships — `docs/my-template.tmpl`
    and `.venv/lib/consumer-tokens.txt`, each carrying all three tokens — and
    assert they survive a first scaffold and an upgrade untouched while the
    managed files still resolve;
  - one scaffolds with a trailing slash on `TEMPLATE_DIR` and asserts
    `justfile.project` is substituted;
  - one builds a template copy carrying `.venv/lib/pyvenv.cfg` **and**
    `pkg/.venv/pyvenv.cfg`, seeds both paths in the workspace with tokens, and
    asserts neither is touched — the nested one is what the old path-prefix
    filter leaked.
- `test_image.py::test_placeholder_manifest_baked` becomes
  `test_placeholder_manifest_absent`: a negative pin, so neither the baked file
  nor the flake step creeps back.
- `scripts/sync_manifest.py`'s `MANIFEST` is a different mechanism
  (`test_manifest_files`, `verify_file_identity`) and is untouched.

```markdown
    Only paths devkit ships are reachable now. (Those three tokens are spelled

  - Reach is **unchanged** for the paths devkit does ship. A consumer file
    living at one of them that an upgrade preserves rather than overwrites —

    consumer `flake.nix`, `.devcontainer/*` under `direnv`/`bare` — still has

    and exactly as the `chmod u+w` sweep still reaches them. This is not a
    regression and not a change; it is the boundary being stated
  - The image no longer ships `/root/assets/.placeholder-manifest.txt` and the
    flake step that generated it is gone, together with the
    `Using build-time manifest (N files)` and
    `Warning: Manifest not found, searching at runtime (slower)` lines a
    scaffold used to print
  - Rendered output is byte- and permission-identical in all four delivery
    modes, under `--smoke-test`, and for a Node scaffold with
    `DEVKIT_LICENSE=proprietary`. A template file the consumer deleted, or one a
    mode prunes, is skipped silently
```

Two notes on that entry.

The #1687 bullet in the same `## Unreleased` section had its "the host-side
placeholder-substitution **fallback**" changed to "**pass**", so both entries stay
true in one release now that there is no second path for it to be the fallback of.

The three tokens are written with inner spaces because
`assets/workspace/.devcontainer/CHANGELOG.md` is template-shipped: the mirror is
copied into every scaffold and is therefore *in* the candidate set, so a literal
`{{SHORT_NAME}}` in a changelog entry renders as "a literal `testproj`" in the
consumer's copy. Verified: the scaffolded mirror carries no token from this entry.
